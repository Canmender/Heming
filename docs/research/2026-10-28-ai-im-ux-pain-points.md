## 0. 结论先行

按「发生频率 × 损失感 × 实现风险」排序，下一批痛点是：

| 优先级 | 痛点 | 用户感受 | 现状证据 |
|---|---|---|---|
| **P0** | 离开聊天页就「失联」：收不到新消息、通知不更新、未读不实时 | 「我在主页/设置里，别人发的消息我要过很久才知道」 | WS 只在 `ChatPage` 挂载时连接（`ChatPage.tsx` 的 `connectWs` effect）；切页即卸载；`NavRail` 的全局未读只在 `loadWorkspace` 刷新；通知中心依赖同一连接 |
| **P0** | 没有系统级消息通知；窗口不在前台时完全无感 | 「最小化/切到别的应用，等于离线」 | 桌面主进程只有 `voice-call:notify`（来电）会弹 `Notification`，消息没有任何系统通知；应用内通知也只在聊天页连接存在时产生 |
| **P1** | 会话多了找不到：没有持久会话列表 | 「只能靠雷达或记住名字搜索」 | 首页只取最近 6 条；聊天页只有「打开过的标签 + 52px 缩略列」；命令面板只搜会话名与技能名，不搜消息内容 |
| **P1** | 提醒不可控：没有按会话免打扰 | 「群太吵，只能忍着或退群」 | 通知中心与 OS 通知都没有静音维度；`notifications.ts` 只有 50 条上限与去重键 |
| **P1** | 历史消息找不到：无全局消息搜索/收藏/置顶 | 「记得说过，但翻不回去」 | 会话内搜索已有；跨会话消息搜索没有（命令面板不查消息）；无消息收藏/置顶 |
| **P2** | 在线状态仍缺失 | 「不知道对方在不在」 | d.38 只做输入态；presence 受 WS 生命周期限制，需先把连接上提 App 壳 |
| **P2** | 附件上传无进度、6MB 硬上限 | 大文件传得心里没底 | 只有「上传中…」状态；`uploadFile` 走 fetch，无百分比 |
| **P2** | AI 工作台能力缺口：多模型对比、提示词库、对话分支 | 「同样的题想比两家模型」 | 竞品调研 R3（多模型同题对比）仍是最有价值的功能缺口；无提示词库/分支 |
| **P3** | 桌面壳常驻：无托盘/任务栏角标 | 关窗即退出，靠自动更新与手动启动 | `main.js` 无 Tray；`window-all-closed` 直接退出 |

> 说明：P0/P1 是 IM 类产品的基础预期（会话列表、未读、免打扰、系统通知、搜索）。这不是「抄竞品」，
> 而是「缺了就会被当成不可靠」的门槛。设计经验部分不作为事实证据。

## 1. 为什么 P0 是「离开聊天页失联」

- 连接生命周期：`ChatPage` 的 WS effect 依赖 `[convId, appendMessage, loadReads]`；离开聊天页 → 组件卸载 → `handle.close()`。
- 后果链：
  1. `message_new` 不进 store → 未读不增长、`lastMessageAt` 不更新；
  2. 应用内通知不产生；
  3. 桌面系统通知无来源；
  4. 回到聊天页才靠 `loadWorkspace` / `loadMessages` 补齐，期间用户完全无感。
- 这不是「少一个功能」，而是**用户以为在线、实际收不到**的信任问题——与 d.37「不撒谎」同一条产品原则。

## 2. 同类产品的通行解（设计经验 + 本仓竞品调研）

- **常驻连接**：桌面客户端在应用进程存活期间保持一条消息通道；页面切换不影响接收。
- **分层提醒**：系统通知（窗口不在前台）→ 应用内通知中心 → 未读角标；三者共享同一份「新消息」事实。
- **免打扰**：按会话静音只抑制提醒，不丢消息、不清未读。
- **会话组织**：持久会话列表（最近活跃排序）+ 置顶 + 免打扰 + 搜索，是 IM 的骨架；本仓目前用「雷达 + 标签」替代，入口成本高。
- **桌面常驻**：托盘/任务栏角标与系统通知配套出现；本仓目前只在来电时用系统通知。

## 3. 本轮选择：d.39 全域消息感知

只做 P0 的两条 + 与之配套的免打扰（P1 的最便宜一项），不碰会话列表与全局搜索（下一轮）：

1. **后台消息通道**：非聊天页时由 App 壳持有 WS；收到消息只做「未读 + 最近活跃 + 提醒」，不解密正文。
2. **桌面系统通知**：窗口不在前台时弹系统通知；正文固定「你有一条新消息」，不显示消息内容；
   点击聚焦窗口并跳到对应会话。
3. **按会话免打扰**：会话信息卡可开关；免打扰只抑制应用内与系统提醒，未读照常计数。
4. 去重：同一条消息只计一次未读、只提醒一次（多连接/页面切换重叠时也不重复）。

明确不做：完整会话列表、全局消息搜索、presence、托盘常驻、附件进度（分别另立轮次）。

## 4. 验收与风险

- 验收：主页/设置页收到消息 → 未读角标实时 +1、通知中心出现、窗口不在前台时弹系统通知；
  点击系统通知回到对应会话；会话免打扰后不再提醒但未读仍增长。
- 风险：两条 WS 在页面切换瞬间重叠 → 用消息 id 去重；系统通知泄露内容 → 正文固定、不显示正文；
  E2E 消息不解密 → 通知只说「有新消息」。

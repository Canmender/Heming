# 缺口补全：功能、视觉与体感三张清单

- 调研时间：2026-10-21
- 基线版本：`d.22.1.6.0`（任务区首版）
- 交付版本：`d.23.1.6.0`
- 上游材料：`docs/research/2026-10-20-competitive-analysis-v2.md`、`docs/research/2026-10-21-feature-parity-and-optimization.md`、`docs/research/2026-10-21-task-area.md`
- 复用口径：**只借鉴产品交互与公开文档，未复制任何第三方代码**；本轮没有新增浅克隆。

---

## 0. 结论先行

1. **缺口不是"功能少"，而是"已有能力差最后一公里"。** 任务区能跑，但执行中看不到实时耗时、失败后要跳系统弹窗确认；HITL 能记规则，但规则会串到别的智能体；对话能看，但离开应用就带不走。本轮优先补这些"每天都会碰到"的断点，而不是再铺一条新功能线。
2. **规则必须跟着智能体走。** 同一个 `fs__write_file`，用户对"文档助手"允许写 `notes/`，不代表对"代码助手"也允许。规则增加可选 `agentId`，新规则只作用于当前智能体；旧规则没有 `agentId`，继续按全局规则生效，避免升级后历史规则突然失效。
3. **导出是信任功能，不是便利功能。** 导出的内容全部来自本机已解密的明文；解不开的信封**跳过而不是伪造占位**；附件只写元信息，不把文档解析正文再抄一遍。导出过程不联网、不上云，文件名也做 Windows 非法字符清洗。
4. **公式渲染要本地完成。** 用 remark-math + rehype-katex 在渲染层解析，KaTeX 字体随包分发，不请求外部 CDN；导出仍是原始 Markdown，`$...$` 不被渲染层改写，换工具打开也不丢语义。
5. **"活着"的感觉来自持续反馈。** 执行中每秒走动的耗时、三段式进度、步骤时间线、状态圆点与脉冲条，比再加一个总结字段更能让用户知道"它还在干活"。

## 1. 三张缺口清单

### 1.1 功能缺口

| 缺口 | 现状（d.22） | 本轮处理 |
|---|---|---|
| HITL 规则跨智能体串用 | 规则键只有 `{tool, resource}`，A 智能体的允许会放行 B 智能体 | 规则增加可选 `agentId/agentName`；新规则只匹配当前智能体；旧规则保持全局 |
| 会话无法带走 | 只能停留在应用内查看 | 会话标题栏增加导出菜单：Markdown / JSON，本机生成并下载 |
| 数学公式不可读 | `$...$` 原样显示 | remark-math + rehype-katex 渲染行内/块级公式，KaTeX 样式本地引入 |
| 任务删除依赖系统弹窗 | `window.confirm`，样式不可控 | 统一使用应用内 `ConfirmDialog`，文案与危险色一致 |

### 1.2 视觉缺口

| 缺口 | 现状（d.22） | 本轮处理 |
|---|---|---|
| 执行中无时间感 | 只在结束后显示总耗时 | 执行中每秒刷新已用时间，结束后冻结为最终值 |
| 状态只有文字徽标 | 列表与汇总靠文字判断进度 | 列表加状态圆点与执行中脉冲条；汇总加「创建 → 执行 → 收口」三段进度 |
| 步骤是平铺文本 | 看不出先后与单步耗时 | 改为竖向时间线：圆点 + 连接线 + 单步耗时 + 状态色 |
| 空状态只有一句话 | 新建任务前页面偏空 | 加细线图标容器与引导文案，仍不显示产品名 |

### 1.3 体感缺口

| 缺口 | 现状（d.22） | 本轮处理 |
|---|---|---|
| 长任务不知道是否卡住 | 只有「执行中」三个字 | 实时耗时 + 脉冲条 + 步骤时间线，停滞一眼可见 |
| 失败原因要翻步骤 | 汇总里混在长文本中 | 步骤分别标 `ok / error / denied`，拒绝原因保留 `user / rule / gate` |
| 删除误触 | 系统确认框点快了也会删 | 应用内对话框，默认焦点在「取消」，危险按钮单独着色 |
| 导出不知道导了什么 | 无反馈 | 完成后提示「已导出 N 条消息（仅本机明文）」；解不开的消息不计入 N |

## 2. 关键设计

### 2.1 HITL 规则作用域

```ts
interface HitlRule {
  tool: string;
  resource: string;
  effect: "allow" | "deny";
  at: string;
  agentId?: string;   // 缺省 = 升级前的全局规则
  agentName?: string; // 仅用于设置区展示，不参与匹配
}
```

匹配顺序保持三条不变式：

1. `deny` 永远优先于 `allow`；
2. `danger` 调用永不命中记住的 `allow`；
3. 闸门异常按 `deny`，且**不落规则**。

新增一条：规则带 `agentId` 时只匹配同一智能体；没有 `agentId` 的旧规则继续全局匹配。去重键从 `{tool, resource}` 变为 `{tool, resource, agentId}`，避免两个智能体的同资源规则互相覆盖。

设置区每条规则显示「全部智能体 / 指定智能体」，并注明新记住的规则只对当前智能体生效——用户能看懂"为什么换个智能体又开始问了"。

### 2.2 会话导出

| 项 | 口径 |
|---|---|
| 格式 | Markdown（人读）、JSON（`version: 1`，机读） |
| 消息范围 | 当前会话已加载的消息；`text / file / forward` 之外的类型跳过 |
| E2E | 只导出 `plainOf` 中已解密的明文；解不开的跳过，**不写"无法解密"占位冒充内容** |
| 撤回 | 保留一条「消息已撤回」占位，保留时间与发送者，不导出原文 |
| 附件 | 只写 id/名称/MIME/大小；不导出解析正文，不导出附件字节 |
| 时间 | 导出时刻由调用方传入，同一输入逐字相同 |
| 文件名 | `和鸣-<标题>-<YYYYMMDD-HHmm>.<md|json>`，非法字符替换为空格，标题截 60 字 |
| 网络 | 无。Blob + `URL.createObjectURL` + 临时 `<a download>`，随后 revoke |

Markdown 头部写明会话 ID、导出时间、消息数，并注明「仅包含本机可解密的明文消息」。JSON 结构与 Markdown 共用同一份输入，避免两种格式各算一套。

### 2.3 LaTeX

- `remark-math` 负责把 `$...$` / `$$...$$` 解析成 math 节点；
- `rehype-katex` 负责渲染；`katex/dist/katex.min.css` 在 `main.tsx` 全局引入；
- 块级公式在 `.markdown-body .katex-display` 上允许横向滚动，长公式不撑破气泡；
- 导出层不经过渲染，原始 `$` 语法完整保留。

不引入 MathJax：KaTeX 更轻、同步渲染、无外部请求；代价是少数冷门宏不支持，遇到时按原文显示，不阻断消息。

### 2.4 任务区视觉与体感

```
创建 ─────●───── 执行 ─────○───── 收口
        done          running
```

- **实时耗时**：`running` 时每秒更新 `now`，`endedAt` 一旦写入即冻结；定时器随组件卸载清理。
- **三段进度**：`done` 全亮、`running` 第二段脉冲、`failed/cancelled` 在收口段显示对应色，不把失败画成"未完成"。
- **步骤时间线**：每步一个圆点 + 竖向连接线，右侧显示工具名、状态、单步耗时；`denied` 用警示色，与 `error` 区分。
- **列表**：状态圆点 + 执行中 2px 脉冲条；选中态左侧边框与浅灰底，不使用高饱和色块。
- **删除**：应用内确认框，标题「删除任务」，说明"只删除本机记录，不影响会话消息"，主按钮为危险色。

## 3. 明确不做

| 做法 | 原因 |
|---|---|
| 导出 PDF / 分享链接 | PDF 需要额外渲染依赖；分享链接意味着把明文上传，直接违反数据边界 |
| 导出解密后的附件字节 | 用户本就有原文件；批量导出会放大泄露面 |
| 服务端渲染公式 | 消息是 E2E 信封，服务端本就不该看到明文 |
| 规则"全部智能体"一键切换 | 容易误把某次授权放大成全局放行；默认按智能体隔离更安全 |
| 任务自动重试 / 后台队列 | 与 HITL「每次写都要问」冲突，且会制造假状态 |
| 用模型生成导出摘要 | 二次幻觉，且导出应是原始记录的纯函数 |

## 5. 后续仍可做

1. **导出范围选择**：当前导出已加载消息；消息很长时可提供"仅导出选中片段"。
2. **任务模板**：把常用目标与智能体存成模板，减少重复输入。
3. **任务级 JSON 导出**：任务记录已结构化，补一个与报告同源的 JSON 导出即可对接外部审计。
4. **公式编辑器**：输入栏提供公式预览，避免用户写完才发现语法错误（需要先确定编辑体验）。
5. **规则导入/导出**：换设备时规则不跟随；若做，必须先解决"导入即放行"的确认流程。

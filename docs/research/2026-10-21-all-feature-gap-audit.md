# 全功能缺口审计：功能 / 视觉 / 体感（d.24 → d.25）

- 日期：2026-10-21
- 范围：`packages/web` 全部页面与公共组件、HITL 链路、任务区、会话导出、记忆/技能/接口/设置
- 方法：两条独立审计线并行——**功能线**按「用户能完成的任务」逐页走查，**视觉/体感线**按
  「加载 / 空 / 错误 / 破坏性操作 / 键盘与读屏」五类状态逐组件核对；只采纳能在本机闭环、
  不突破数据边界的项
- 结论：d.24 落地 10 项（§1），其余按价值与风险排序留作后续；**d.25 复核后落地其中 8 项**（§2），
  暂缓理由原样保留——它记录了「为什么当时不做」，仍然是判断同类需求的依据

## 1. 已落地（d.24）

| # | 缺口 | 落地内容 | 为什么值得做 |
|---|---|---|---|
| 1 | HITL 确认时看不到「将改什么」 | `lib/hitl/preview.ts`：对 edit 生成带上下文的行级 diff，对 write 展示内容行数，对 delete 只展示目标路径；`ToolApprovalModal` 增加「查看变更（+x −y）」折叠区 | 用户在企业微信/IDE 里习惯先看 diff 再批准；只给工具名与参数摘要，等于让用户盲签 |
| 2 | 待确认弹窗不知道来自哪个会话 | 弹窗顶部显示「请求来自会话「X」」，并提供「回到该会话」；`ChatPage` 从会话列表解析显示名 | 智能体在后台会话里请求授权时，用户当前可能正看另一个会话；没有归属就会误判上下文 |
| 3 | 切换会话后旧会话的确认请求还挂在屏幕上 | `useHitlStore.cancelForConversation`：切走会话时把该会话的待确认项与队列项按拒绝收口 | 用户已经离开那个会话，就不该再替它做决定；继续挂着会阻塞其他会话的确认（单槽队列） |
| 4 | 长会话里找不到历史消息 | 会话标题栏搜索按钮 + 搜索栏：大小写不敏感、一条消息只算一次命中、上下循环跳转、当前消息高亮并滚动到可视区 | 归档页只能按会话找，会话内定位仍靠肉眼；这是长对话最高频的「体感缺口」 |
| 5 | 空会话整片空白 | 空状态图标 + 「还没有消息 / 发送第一条消息，开始这段对话。」 | 空白页让新用户不知道下一步；空状态是最便宜的新手引导 |
| 6 | 任务只能复制 Markdown，外部工具难消费 | `buildTaskJson`（`format` + `version: 1` + 显式字段 + 去重来源），任务汇总区新增「复制 JSON」 | 任务记录已结构化，缺的只是稳定导出契约；审计/脚本/其他工具可直接读取 |
| 7 | 删除智能体仍弹系统 `window.confirm` | 改用应用内 `ConfirmDialog`（Esc / 焦点陷阱 / 遮罩 / 明确的不可恢复说明），确认前不发请求 | 系统框样式不可控、不可测、与全站弹窗行为不一致；破坏性操作需要统一的安全默认 |
| 8 | 导航轨当前页没有读屏标记 | 当前项补 `aria-current="page"` | 视觉上有反白，读屏用户却听不出「你在哪一页」 |
| 9 | 分割线 token 漂移（`#ebebeb` vs `#ececec`） | `DESIGN_TOKENS.lineSoft` 与 Tailwind `line-soft` 统一为 `#ececec` | 同一语义两种灰，换页面就能看出接缝；统一后视觉规范只有一处真源 |
| 10 | 设置页快捷键提示过期（写 Alt+1–6，实际 1–8） | 文案改为 Alt+1–8，补 Alt+7（归档）/ Alt+8（任务区）用例 | 提示与行为不一致会直接误导用户；这类「文档漂移」比缺功能更伤信任 |

附带：会话标签的归档/关闭按钮原本只在 hover 时显现，键盘 Tab 聚焦后仍不可见；
补 `focus:opacity-100`，键盘用户能看到当前焦点。

## 2. 暂缓项的 d.25 处置

| 缺口 | d.24 的暂缓理由 | d.25 处置 |

| 任务模板 | 交互未定：是「目标+智能体+固定提示词」还是可参数化槽位 | **已做**：定为「名称 + 目标文本，选中填回输入框仍可编辑」，不绑智能体、不做槽位——先解决「同一句话反复打」 |
| 消息多选导出 | 多选涉及选择态、批量操作栏、与搜索/回应的交互 | **已做**：选择态只挂在标题栏开关上，与搜索互不干扰；复用整会话导出的 `version: 1` 契约 |
| 各页破坏性操作统一应用内确认 | 需逐页确认「删的是什么、能否恢复、是否影响云端」 | **已做**：技能 / MCP 服务 / 记忆 / Wiki / HITL 规则 / 自我修改 / Registry 安装 / 更新卡片，逐页写文案而非机械套用 |
| 自建弹窗统一 Esc / 焦点陷阱 / `aria-modal` | 需先盘点弹窗并评估嵌套弹窗的焦点顺序 | **已做**：`useModalA11y` + 模块级 `openDialogs` 栈解决嵌套（只有栈顶吃 Esc，内层卸载交还外层）。★ 背景 `inert` / `aria-hidden` 与关闭后焦点归还**仍未做**：需要真实读屏验证，不凭猜 |
| 语音断线重连 | 需要真机与 TURN 环境验证，纯前端改动无法证明有效 | **部分做**：逐路 ICE restart（2 次预算、`disconnected` 先观察 3s）与新信令 `voice_call_reconnect` 已落地并有单测；★ **真机弱网与 TURN 仍未验证**，预算数字是工程判断而非测量结果 |
| 通知中心 | 涉及系统通知权限、免打扰、跨窗口聚合，属独立功能 | **已做（范围收窄）**：只做**应用内**通知（消息 + 任务收尾），不碰系统通知权限、不做免打扰；上限 50 条 / 64KB，只存本机 |
| 本地 npm/pypi 包安装 | 会打破「装完即用、零外部运行时」的承诺 | **已做，承诺改写**：仍然不内置运行时（+30MB 不换）。策略改为「先探测 → 缺什么直说 → 启动时翻译成 `node npx-cli.js`」，见 `docs/superpowers/specs/2026-10-21-local-package-runtime-policy.md` |
| 记忆重排 / 时效失效 | 需要真实使用数据评估；没有数据就调权重视为拍脑袋 | **已做，判据不变**：不引入学习式权重、不加数据模型字段；只补两条「不做就会出错」的确定性规则（同主题覆盖旧值、MMR 去重名额）。★ 个性化权重**依然不做** |

## 3. 安全与数据边界复核

d.24 的复核结论不变（没有新增「全部放行」档；切换会话按拒绝收口；变更预览只读本机调用参数、
不读目标文件内容；导出只存本机；删除确认不改权限判定）。d.25 新增的部分：

- **stdio 启动恒定 `shell:false`**：包名走字符白名单（shell 元字符一个都不在集合里——
  靠一个正则做到「根本没法构造」注入串，而不是靠转义函数没有漏洞）；Registry 的
  `packageArguments` / `environmentVariables` 一律丢弃；**必须有钉死的版本**（浮动版本 = 确认的不是跑的）
- **Registry 安装永远要确认**：「先探测再确认」只决定要不要问，不放松「必须问」；
  装完工具默认全部关闭，删除服务会回收其本机子进程
- 记忆重排是确定性打分（注入 `now`，两次结果逐字相同），不上传任何内容
- 通话重连**没有新增明文面**：SDP 信令本就与 invite/accept 同级走 WSS，媒体仍由 DTLS-SRTP 保护；
  未知 `callId` 一律 `forbidden`
- 通知中心 / 任务模板 / 多选导出只存本机 `localStorage`；导出不解密的文、附件只带元信息

## 4. 下一轮优先级建议

1. **弹窗背景 `inert` + 关闭后焦点归还**——骨架已有，缺的是关掉后焦点回到触发元素；
   需要接读屏实测，不能凭代码猜
2. **语音重连的真机验证**（弱网 / TURN）——状态机有单测，缺的是环境证据
3. **记忆召回效果的可观测**——先能归因「哪条被注入后模型用了 / 用了错的」，再谈调权重
4. **Registry 本地包的运行时补全清单**——`buildChildEnv` 补的是写死的常见目录，
   装在非常规路径仍可能探不到
5. **系统级通知 / 免打扰**——独立功能，按用户实际反馈排期（本轮刻意只做应用内）

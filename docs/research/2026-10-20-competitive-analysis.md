## 三、差距按优先级

### P0 — 用户最常做、我们为零的能力

1. **文档解析（PDF / Office / 图片）**
   竞品全部具备，我们完全没有。这是"让 AI 看这份文件"这个最高频场景的入口。
   当前右栏只能预览文件，不能把内容喂给模型。

2. **代码高亮**
   Markdown 是自研渲染，代码块无高亮、无复制按钮。
   对技术用户来说这是"一眼看出专业度"的地方，成本很低。

3. **多模型同时对话**
   Cherry Studio 靠这个功能立住"多模型客户端"的定位。
   我们一次只能一个模型回答，做不了横向对比。

### P1 — 生态与效率

4. **MCP 市场 / 一键安装**
   我们只有 3 个硬编码预置。LobeHub 有 10,000+ 插件库，
   mcp-gearbox 专门做"发现 + 一键装"。生态厚度是这个赛道的护城河。

5. **全局搜索**
   会话、消息、文件、技能都搜不了。会话一多就只能翻。

6. **定时任务 / 自动化**
   LobeHub 的 Schedule、Eigent 的 Automation 都在做"你不在线时智能体继续工作"。

7. **对话导出 / 分享**
   只有图表能导出。整段对话无法另存或分享。

### P2 — 扩展能力

8. **AI 语音（TTS / STT）** — 竞品在做语音输入与朗读；我们只有人-人通话。
9. **图像生成 / 视觉理解** — 竞品普遍具备。
10. **多智能体并行编排** — 我们是"用户与单个智能体对话 + 群聊"，
    没有 LobeHub Agent Groups / Eigent Workforce 那种"主智能体派活给子智能体并行干"。

## 四、我们的独特优势（要守住，别在追赶中丢掉）

这几项竞品普遍没有，是本项目的差异化所在：

1. **自我修改（`self_*` 13 个工具）**：智能体能改自己的记忆、技能、MCP 配置，
   带敏感信息护栏、单轮预算、变更留痕。竞品全是"用户配置智能体"，没有反过来的。
2. **去 AI 味检测**：基于 283 万字语料的 11 条统计规则，还能定位到具体句子。
   这是写作场景的硬需求，且已有可验证的检测器。
3. **Obsidian 文件态知识库**：知识是真实 markdown 文件，任何编辑器、任何 LLM
   都能直接读写，不被锁死在应用里。竞品的 RAG 是向量库，出了应用就用不了。
4. **真·零依赖**：Python 与 MCP 服务全打进安装包（377MB），用户装完即用。
   Cherry Studio 的"无需环境配置"指的是不用配 API，MCP 仍要系统装 uv/node。
5. **人-人语音通话**：竞品只有 AI 语音，没有用户之间通话。
6. **图表围栏规范**：` ```chart ` + 自研 SVG 渲染器 + 单文件 HTML 导出，
   不依赖 Mermaid 的语法限制。

## 五、建议的推进顺序

> **进度更新（2026-10-20）**
> - ✅ 代码高亮 + 复制按钮 — `d.16.1.4.0`（顺带补了整条 markdown 渲染管线）
> - ✅ 文档解析 PDF/Office — `d.17.1.4.0`（文本提取 + 进提示词，未做扫描件 OCR）
> - ⬜ 图片理解 / 全局搜索 / 多模型对比 / MCP 市场 / 定时任务

按「用户价值 ÷ 实现成本」排：

| 顺序 | 事项 | 理由 |
|---|---|---|
| 1 | 代码高亮 + 复制按钮 | 成本最低（引入 shiki/prism），观感提升立竿见影 |
| 2 | 文档解析（PDF/Office → 文本） | 补齐最高频场景缺口；纯前端可做（pdfjs + mammoth） |
| 3 | 图片理解（多模态消息） | 依赖 1、2 的附件管线，一起做更省 |
| 4 | 全局搜索 | 纯本地索引，不依赖外部服务 |
| 5 | 多模型同时对话 | 需要编排层改造，但可用现有 LLM 客户端复用 |
| 6 | MCP 市场 | 需要维护清单源，工程量最大，生态收益也最大 |
| 7 | 定时任务 | 依赖桌面常驻 + 后台调度，可与自动更新共用机制 |

**不建议现在做的**：图像生成、AI 语音、多智能体并行编排。
前两个是"别人有所以我也要"的补齐型功能，与和鸣"写作 + 记忆 + 自我改进"的定位关系不大；
第三个会大幅增加编排复杂度，而当前"一对一 + 群聊"已经覆盖主要使用方式。

## 六、结论

和鸣在**差异化能力上领先**（自我修改、去 AI 味、文件态知识库、零依赖），
但在**基础能力上有明显缺口**——尤其文档解析和代码高亮，这两项是所有竞品的标配，
缺失会让用户在第一分钟就感到"这个工具还不能干活"。

优化重心应该是**先补齐基础能力（P0），再谈生态厚度（P1）**，
而不是去追 P2 的多模态和并行编排。

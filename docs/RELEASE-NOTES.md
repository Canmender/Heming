# 和鸣 · 用户版发布说明

> 这份文件**面向用户**：只写「用户能感知到什么」，一句一条，不写实现细节、文件名、测试数量或缺陷根因。
> 工程记录（根因/修法/门禁数字）一律留在 [CHANGELOG.md](../CHANGELOG.md)，两边不要互相复制。
> 版本号与 CHANGELOG 对齐；没有写在这里的版本，应用内只显示一行标题，不展示工程细节。
> 维护方式：每次 bump 后，在 CHANGELOG 之外**顺手补一条**（一两条即可）；`node scripts/build-changelog.mjs` 会一并生成。

## d.133.3.54.0（2026-11-11）— 插件区只剩两个插件，安装包不带插件

- 插件统一为「信息」与「助理」：信息含采集/浏览/检索与首页卡；助理含幕僚、自动化、工作流，安装/启停/删除按整体。

## d.124.3.48.0（2026-11-10）— 插件可以在左侧导航有自己的页面了

- 装好带页面的插件后，左侧导航最下面（模块入口之后）会多一个这个插件自己的入口，点进去就是它的页面；停用或卸载后入口自动消失。
- 插件页面有两种：**声明式页面**的内容写在插件里，由和鸣按固定样式显示（说明文字、数字、表格、列表、跳转按钮），不执行代码、不联网，安装版和网页版都能看；官方界面插件也可以自带网页，那种只在安装版里显示。
- 页面里能直接看到这个插件提供了哪些技能、服务、命令，也能放跳转按钮，一键去插件区、设置或本插件详情。
- 一个插件最多一个页面，入口固定在导航最下面，不占数字快捷键；页面只能展示这个插件自己的内容，不会改动和鸣现有界面，也不新增任何权限。
- 更新插件后页面内容跟着更新；卸载后不会留下空白入口或残留窗口。

## d.123.3.48.0（2026-11-10）— 能力就三类：插件、技能、MCP

- 插件页只剩三个页签：**插件 / 技能 / MCP**。「工具」不再是单独页签，它跟着 MCP 服务一起看、一起授权。
- 插件全部来自我们自己的服务器仓库：点「从插件仓库安装」就能浏览、预览、安装；也可以手动粘贴清单，或安装官方带页面的插件（幕僚、信息中枢、自动化、工作流）。
- 桌面小组件改名「界面插件」，合并进插件页——它也是插件，只是带独立窗口。
- 技能 = 和鸣自带 + 社区（论坛）安装；MCP = 和鸣自带/预置 + 注册表社区安装。
- 装插件后的提示会说明入口在哪；导航顺序固定不受影响。

- 插件详情里的「诊断」仍会告诉你某个插件为什么没生效。

## d.122.3.47.0（2026-11-10）— 插件区更好看也更顺手；插件源码搬进 plugin-kit

- 插件页换了版式：顶部能力概览更清楚，安装面板可以把 plugin.json 直接拖进去，技能/工具/MCP/组件列表统一成卡片。

## d.120.3.47.0（2026-11-09）— 做插件变简单了：一条命令生成骨架，标准写在一处

- 「插件」现在有一份正式的标准：能声明什么、权限怎么生效、装/更新/停用/卸载各是什么语义，都整理在 `plugin-kit/`（标准、菜谱、常见问题、可抄的示例）。
- 写插件看 `plugin-kit/`：从零到发布、常见错误怎么修、提交前检查清单，还有四份能直接跑的示例。

- 修了几处「能写但不会生效」的字段：托盘菜单多了缩放项；窗口落位只支持右下时现在会明确提示，不再假装生效；详情的包内路径不再允许跳到包外。

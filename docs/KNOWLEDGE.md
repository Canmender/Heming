# 知识库（原生 vault）

> 面向：用和鸣管理自己文档/笔记的人。目标是把「你的 markdown 库」变成和鸣里的一等公民——
> 能浏览、能编辑、能双链、能被智能体读到，而且**和 Obsidian 共用同一份文件**。

## 1. 它是什么

和鸣的知识库是**直接读写你磁盘上真实 markdown 文件**的一个文档区（d.114）：

- 可以打开**任意目录**当作一个「库」（vault），多库并存、随时切换；
- 库里的文件就是纯 `.md`（外加 `.canvas`、图片附件），**不被和鸣重新编码**，
  所以你可以在 Obsidian / 任意编辑器 / git 里同时改它；
- 和鸣自带的 `~/Heming/wiki` 会自动登记为第一个库，老的「个人知识库」页面继续可用。

**数据边界**：库内容只在本机。不上传服务端、不进团队动向、不进消息附件。

## 2. 怎么用

1. 导航「知识库」→ 空态点「打开本地库」→ 选一个目录（或新建空目录）；
2. 左栏文件树浏览，点文件在中栏打开（多标签）；
3. 中栏三种模式：**源码**（CodeMirror 编辑）/ **分栏**（左写右预览）/ **阅读**；
   `Ctrl+S` 保存，标题栏有脏标记；
4. 右栏：当前页的**反链 / 出链 / 未解析链接 / 大纲 / 属性**（frontmatter）；
5. 左栏搜索框支持 Obsidian 风格子集：`tag:#项目`、`path:日报`、`file:周报`、`"短语"`、`-排除`；
6. 图谱：全库或「当前页 1–2 跳」的局部图，点节点跳转。

### 2.1 画布（`.canvas`）

Obsidian 的画布文件和笔记一样能在和鸣里打开：节点可拖动（20px 吸附）、双击文本节点改字、
工具栏新建文本节点、`Delete` 删除（连带删除与它相连的线）、滚轮缩放、拖空白平移、一键复位。
`read` 模式下只读但仍可平移缩放、点文件节点跳转。**改完和笔记一样按 `Ctrl+S` 保存**；
文件被外部改坏（JSON 非法）时只显示错误与原文预览，**绝不把坏内容写回去**。

### 2.2 日记与模板

- 知识库设置里配「日记文件夹 / 日期格式 / 日记模板」（默认 `daily/` + `YYYY-MM-DD`）；
  页头「今天」按钮：有就打开，没有就按模板创建（frontmatter 带 `date`）。
- 新建笔记时可从 `templates/*.md` 选模板，占位符 `{{title}} {{date}} {{time}} {{vault}}` 与 `{{date:YYYY-MM-DD}}` 会被替换；
  不认识的占位符**原样保留**（不会被悄悄吃掉）。

### 2.3 命令面板与快速切换

- `Ctrl/⌘+K` 命令面板：输入笔记名即可跳转（匹配文件名 > 别名 > 路径）；也能直接执行
  「新建笔记 / 打开今天的日记 / 新建画布 / 知识库设置」。
- 知识库页内 `Ctrl/⌘+O` 快速切换：输入过滤、↑↓ 选择、Enter 打开、Esc 关闭。

## 3. 双链语义（与 Obsidian 对齐）

| 写法 | 含义 |
|---|---|
| `[[页面]]` | 按文件名解析（不含 `.md`）；同名文件按「离当前文件最近」优先，歧义会在界面标黄 |
| `[[页面\|别名]]` | 显示别名，跳转目标不变 |
| `[[页面#标题]]` | 跳到页面里的某个标题锚点 |
| `![[图片.png]]` | 嵌入图片（md 嵌入限深 1，防环） |
| `#标签` / `#父/子` | 行内标签；frontmatter 的 `tags` 同样计入 |

代码块与行内代码里的 `[[...]]` **不算链接**——这是解析器最容易写错的一处，有用例钉住。

## 4. 与智能体记忆的绑定

- **笔记 → 记忆**：库里的笔记会作为「指针型语义条目」参与召回——记忆里只存
  `库 id + 路径 + 修改时间 + 内容指纹` 与一段摘要，**不复制正文**。
  智能体回答时若用到某篇笔记，会标注「来自知识库《路径》」。
- **记忆 → 笔记**：沉淀、用户明说「记住…」、复盘自评这三类长期记忆，会写回库里的
  `inbox/`（`inbox/memory-<键>-<日期>.md`，同键追加「## 更新」小节），
  这样记忆不再只存在于聊天记录的暗处，你在编辑器里就能看见、能改。
- **写入边界**：智能体**只能写库里的允许目录**（默认 `inbox/`），其它目录只读；
  每次写入仍走人工确认（HITL），拒绝即停。
- 开关：「记忆区 → 知识库参与记忆」。关闭只停注入，不删已建索引；上限默认 500 篇，
  超出按修改时间截断并在记忆区写明「已截断」。

## 5. 安全与限制

- 库根由主进程登记（`~/Heming/vaults.json`），渲染层只能传「库 id + 相对路径」；
  每次读写都在主进程重新夹一次路径并复核符号链接，越界直接拒绝；
- 只处理白名单扩展名：文本 `.md/.canvas/.json/.txt/.csv`（单文件 ≤2MB）、图片 `.png/.jpg/.jpeg/.gif/.webp/.svg`（≤8MB，只读）；
- `.obsidian/`、`.git/`、`node_modules/` 与隐藏目录默认不扫描、**永不写入**（那是 Obsidian 自己的配置）；
- 删除只删单个文件，不递归、不删目录；
- 浏览器（无文件桥）下是「临时模式」：功能可试，关掉页面即丢失。

## 6. 和 Obsidian 的关系

和鸣**不内置、不嵌入、不分发** Obsidian 应用本体（它是闭源商业软件，且和鸣不复制其代码）。
知识库是**按同一套文件约定自己实现**的：同一份目录、同一份 `.md`、同一套双链与标签语义，
所以两个客户端可以交替使用。做不到与 Obsidian 逐像素一致的地方会写在这里，而不是假装支持。

## 7. 排查

| 现象 | 原因与处理 |
|---|---|
| 打开库后文件树是空的 | 目录里没有受支持的扩展名，或全是隐藏目录；确认文件是 `.md` |
| 双链显示「未解析」 | 目标文件不存在或文件名不同（含空格/大小写）；点「创建该页」可直接补 |
| 链接标黄 | 同名文件多于一个，解析有歧义；改成带目录的写法 `[[dir/页面]]` |
| 保存提示「文件已被外部修改」 | 你在 Obsidian/编辑器里改过同一文件；重新打开该页再改，避免覆盖 |
| 记忆区「已截断」 | 笔记数超过上限（默认 500）；可在设置里调大或缩小纳入范围 |
| 智能体写不进去 | 目标不在允许目录（默认 `inbox/`），或用户拒绝了确认 |

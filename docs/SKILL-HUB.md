# 技能社区（Skill Hub）设计：接入国内技能平台「虾评」

> 目标：让用户在**技能区**直接搜索、看详情、下载安装来自国内 Agent 技能社区的技能，而不是自己去找帖子、复制 prompt。
> 首个接入源：**虾评**（`https://xiaping.coze.com`，国内 Agent 技能交易平台）。
> 本文是契约：字段形状以 `packages/shared/src/skillHub.ts` 为准，接口路径以本文为准。

## 0. 为什么这么做

- 和鸣已有「技能池 + 导入导出的 `SKILL.md`」能力（`lib/skills/markdown.ts`），缺的不是安装器，而是**发现**：
  用户不知道去哪找好技能、也不方便把网页/帖子里的技能变成本机技能。
- 国内社区已有现成平台（虾评提供列表/搜索/分类/详情/下载/安全报告 API），和鸣不需要自建社区。
- 接入形态必须守住产品红线：**技能是声明式文本指令，不是可执行代码**。社区内容再方便，也不能变成第二条代码执行路径。

## 1. 边界（先读）

1. **只导入文本**：下载包只取 `SKILL.md` 文本 + 文件清单（路径/大小）。**不执行**包里的脚本、不安装依赖、不落盘其它文件。
2. **Key 是用户的**：虾评下载正式版需要用户自己的 API Key（正式版消耗平台代币 2 虾米）。和鸣：
   - 不在服务端持久化 Key、不写日志；
   - 不代扣、不共享、不上报；
   - 无 Key 时只提供「浏览/详情/去注册」，不静默失败。
3. **账号创建要用户点**：一键注册会在虾评创建一个真实账号（用用户给的名字）。只允许用户明确点击后调用，并当场说明后果。
4. **第三方内容如实标注**：展示作者、版本、下载/收藏数、上游安全标记（有则显示，无则写「上游未提供」），**不假装是官方审核过的**。
5. **不自动分配**：导入的技能沿用现有语义（`source: "imported"`），默认不分配给任何智能体；用户自己去技能区分配。
6. **不绕过 HITL/沙箱**：技能只影响提示词；任何工具调用仍走原有 HITL 与权限上限。

## 2. 架构：为什么必须经过和鸣服务端

```
┌─────────────┐   同源 fetch    ┌──────────────────┐   HTTPS    ┌──────────────────┐
│  web 技能区  │ ──────────────▶ │ 和鸣 server 代理   │ ─────────▶ │ 虾评 API          │
│ (SkillHub*) │   /api/skill-hub │ (归一化/限流/解包) │  Bearer    │ xiaping.coze.com │
└─────────────┘                 └──────────────────┘            └──────────────────┘
```

必须代理的三个理由：

1. **CORS**：上游不返回 `Access-Control-Allow-Origin`，浏览器直连会被拦。
2. **归一化**：上游字段是平台命名（`current_version`/`owner_name`/`avg_stars`/`trigger[]`），web 只认 `shared/skillHub.ts` 的形状；换源/上游改名时不牵动 UI。
3. **解包与上限在服务端**：zip 读取、路径穿越拒绝、大小上限、只取 `SKILL.md` 都在服务端做，客户端拿到的永远是受限文本。

代理**不**做的事：不缓存用户 Key、不记录下载内容、不做账号体系、不代表虾评审核。

## 3. 接口契约

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/skill-hub` | 公开 | 是否启用、源信息、分类、上游可达性 |
| GET | `/api/skill-hub/skills?page&limit&search&category&sort` | 公开 | 列表/搜索；`limit` 夹在 1–30 |
| GET | `/api/skill-hub/skills/:id` | 公开 | 详情（含安全报告 Markdown） |
| GET | `/api/skill-hub/skills/:id/download` | `x-skill-hub-key` | 需用户 Key；返回解包后的 `SKILL.md` 与文件清单 |
| POST | `/api/skill-hub/register` | 公开（用户主动触发） | body `{ name }`；代用户在虾评创建账号，只返回 Key |

响应形状全部见 `packages/shared/src/skillHub.ts`（zod schema，客户端 safeParse）。

### 上游字段 → 归一键（节选）

| 上游 | 归一化 | 用途 |
|---|---|---|
| `id` | `id` | 安装绑定（`community.skillId`） |
| `name` / `description` | `name` / `description` | 卡片与详情 |
| `trigger[]` | `triggers[]` | 搜索 + 导入后技能的触发词 |
| `category[]` | `categories[]` | 分类筛选 |
| `tags[]` | `tags[]` | 展示与搜索 |
| `owner_name` | `ownerName` | 作者展示（安装确认必须显示） |
| `current_version` | `version` | 「已安装/有新版本」比较（字符串，不做 semver） |
| `downloads` / `star_count` / `avg_stars` | `downloads` / `stars` | 排序与展示 |
| `status`（official/trial） | `status` | 正式版/试用版标记 |
| `requires_api_key` | `requiresApiKey` | 安装前提示「需要自备某个 Key」 |
| `security_status`、`security_report` | `securityStatus`、`securityReport` | 如实展示上游检测结论（缺失不编） |
| `updated_at` | `updatedAt` | 排序 |

## 4. 安装流程（6 步，与 UI 一一对应）

1. 用户在「社区」搜到技能 → 打开详情（看描述/触发词/作者/版本/安全标记）。
2. 点「安装」：有 Key 则直接下载；无 Key 弹出「连接虾评」面板（粘贴 Key 或一键注册）。
3. 客户端请求 `/download`（带 `x-skill-hub-key`）→ 服务端向上游取 `download_url`、下载 zip、解包取 `SKILL.md`。
4. 客户端用 `parseImportText` 解析出技能（名称/触发词/标签/指令），展示**安装预览**：名称、触发词、指令字数、来源、作者、版本。
5. 用户确认 → 写入技能池（沿用导入路径），并把 `community` 元信息记在技能上（版本/作者/来源，用于「已安装/有新版本」）。
6. 提示「已安装，去技能区分配」——**不自动分配**、不弹二次引导。

安全校验（服务端强制，客户端不可绕过）：

| 检查 | 上限/规则 |
|---|---|
| zip 字节 | ≤ 5MB |
| 解包文件数 | ≤ 200 |
| 单文件 | ≤ 1MB（只解 `SKILL.md` 内容） |
| 路径 | 拒绝对路径、`..`、NUL、反斜杠规范化后的穿越 |
| `SKILL.md` | 包内任意深度、取**最浅**的一个；≤128KB；UTF-8 |
| 文件清单 | 只返回 path/size，不返回内容 |

## 5. Key 管理

- 存放：优先 `window.__heming_secrets`（Electron `safeStorage`）加密后写本机键 `heming.skillHub.key.v1`；浏览器端无桥时明文本地存储，UI 明确标注「当前环境无法加密」。
- 清除：设置项/社区面板提供「清除 Key」，只删本机键。
- 失败语义：上游 401 → 「Key 无效或已过期，请重新填写」；402/403 → 上游中文原因透传（可能是虾米不足/权限不够）；无 Key → 引导面板，不重试。

## 6. 信任与合规

- 社区是**公开第三方内容**：和鸣不是审核方；详情页展示作者、版本、下载/收藏、上游安全结论，并保留「查看上游页面」。
- 上游 `security_status` 缺失时不显示绿色标记，改写「上游未提供安全检测结果」。
- 技能导入后与手工技能同一套存储与导出；`community` 元信息会随技能导出（便于迁移），但**不**参与提示词。
- 隐私：和鸣只把「搜索词/分类/技能 id」发给社区 API；**不发送**用户记忆、会话、本机文件、团队数据。Key 只用于下载/注册请求。

## 7. 失败模式与降级

| 场景 | 行为 |
|---|---|
| 服务端 `HEMING_SKILL_HUB=off` | 技能区不显示「社区」Tab；直接访问接口返回 503「社区未启用」 |
| 上游不可达/超时（15s） | 列表 502 + 中文原因，UI 提供「重试」；已加载内容保留 |
| 上游改了字段 | 归一化层兜底默认值；缺 `id/name` 的条目整条丢弃并计数（不炸整页） |
| 用户点「一键注册」失败 | 显示上游错误原文 + 「去虾评手动注册」外链 |
| 下载后 SKILL.md 解析失败 | 不写技能池，报「这个技能不是和鸣可识别的 SKILL.md 格式（缺少 frontmatter/标题）」 |
| 技能重名 | 安装预览显示「将覆盖同名的社区技能」/「已有同名手工技能，将另存为 `名字（社区）`」——不静默覆盖 |

## 8. 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `HEMING_SKILL_HUB` | 开 | 设为 `off` 关闭整个社区功能（接口 503、UI 隐藏入口） |
| `HEMING_SKILL_HUB_BASE` | `https://xiaping.coze.com` | 上游 base URL；只允许 http(s)，测试用注入 fetch |

## 9. 接入第二个源（后续）

归一化层预留了「源」概念。新增一个国内社区需要：

1. `shared/skillHub.ts` 的 `SKILL_HUB_SOURCES` 加一项；
2. `server/skillHub.ts` 加一个 adapter（列表/详情/下载三个函数 + 字段映射）；
3. 服务端接口加 `?source=` 参数（默认首个源），web 端下拉切换。

不改 web UI 的数据形状——这是这次只做「一层归一化」而不是「按源写四套 UI」的原因。

## 10. 验收（d.109）

- 服务端：列表/详情/下载/注册四类接口 + zip 解包安全上限 + 无 Key 401 + 关闭开关，全部有单测。
- web：技能区「社区」Tab 搜索/分类/排序/详情/Key 引导/安装预览/已装徽标；无桌面桥、无 Key、上游失败三条降级路径都可用。
- 不变量：不引入代码执行路径；不持久化用户 Key；不自动分配技能；导入技能与手工技能同存储同导出。

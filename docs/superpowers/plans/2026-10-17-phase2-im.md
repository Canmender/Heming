# 和鸣二期 IM 批次实现计划（撤回 · 回复 · 转发 · 语音 · 表情回应 + 遗留收尾）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 IM 核心能力：消息撤回与回复引用（MVP 缺口）、消息转发、语音消息、表情回应；收尾三项 IM 遗留（他机流 watchdog、WS 重连补已读、群消息头像）；左侧导航图标列垂直居中。

**Architecture:** 协议扩展集中在 shared WS 事件与 Message/Payload schema；store 双实现（memory/sqlite）承载撤回标记与表情 toggle 持久化（sqlite 需幂等列迁移）；UI 全部落在 ChatPage 消息 hover 层与输入区浮层，复用既有 blob 附件链路（语音=audio 附件 + `<audio>` 气泡）与 uploadFile。全部串行执行（同文件交叠多）。

**Tech Stack:** 不新增依赖。Electron/Web 原生 MediaRecorder（语音）、既有 ws/zod/store 架构。Vitest。

## Global Constraints

- 不新增任何 npm 依赖；MediaRecorder/SpeechRecognition 一律**特性检测 + 不可用提示**，不自造降级实现。
- 图标一律细线 SVG（strokeWidth 1.5）；emoji 只作为**消息内容/表情回应数据**出现，UI chrome 不用 emoji 图标。
- 浅灰分割线（#e6e6e6/#ececec/#f1f1f1）；选中态 `bg-ink text-white`；无产品名 chrome；中文文案。
- 协议变更必须 shared schema + 服务端处理 + 客户端处理三处同步；server 收包经 WsClientEventSchema 校验，未知类型回 bad_event。
- store 改动必须 memory/sqlite 双实现同改 + `storeContract.test.ts` 双跑；sqlite 变更走 db.ts 幂等路径（新表 IF NOT EXISTS；**已有表加列用 PRAGMA table_info 检查后 ALTER**，防生产库炸）。
- 撤回与表情回应的**权限**：仅消息发送者可撤回；表情回应所有会话成员可加/删（服务端按 isMember 校验）。
- Message 新增 `recalledAt: string | null`（非 optional——双端同步后恒有该字段）；已撤回消息 payload 保留不改，客户端渲染层屏蔽。
- 转发**不携带 mentions**（防接收端触发智能体），只转发 text/file + 来源信息。
- 所有新交互配 vitest；`pnpm -r build && pnpm -r test` 全绿后提交。

function AudioBubble({ fileId }: { fileId: string }) {
  const [url, setUrl] = useState<string | null>(null);
  const [err, setErr] = useState("");
  useEffect(() => {
    let revoked: string | null = null;
    let alive = true;
    void fetchFileBlobUrl(fileId).then((u) => { if (!alive) { URL.revokeObjectURL(u); return; } revoked = u; setUrl(u); })

  }, [fileId]);

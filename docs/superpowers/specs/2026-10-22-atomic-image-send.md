# 图片 + 文字同发（原子发送）

日期：2026-10-22 · 版本：d.25.1.7.0 · 状态：已实现

## 1. 问题

视觉附件此前只从**历史消息**里取图（`ChatPage.fetchHistory` → `attachImageParts`）。
而上传入口（工具行「图片/文件」）是**当场独立发一条** `kind:"file"`、`text:""` 的消息：

- 用户先输入框写好「@和小鸣 这张图里有什么」，再点图片——附件那条消息发出去了，**草稿还留在输入框**，得再按一次发送；
- 这一次发送要 `loadMessages` 拉历史才能看到图，而刚上传那条要等服务端入库 + WS 回声 + 自解（`plainById`/`outbox`）才可用。回声没到 → 提示词里根本没有这张图，模型只能回「我看不到图片」；
- 附件单独发送（空草稿）时**完全不触发**智能体：@ 了也没反应。

净效果就是 HANDOFF §5 #2 记的那句：**本轮新上传的图片要等下一轮才进模型**。

## 2. 决策

**有草稿就同发**：附件入口不再另起一条空正文消息，而是把当前草稿、@ 选择、引用一并发进
**同一条 `kind:"file"` 消息**，并当场触发本轮生成。

不引入「待发送附件托盘」这类新 UI（多一块活动部件、要管暂存/清理/跨会话归属），
消息契约早就支持 `text + file` 共存（`MessagePayloadSchema`），前端气泡也本来就分段渲染正文与附件——
差的只是发送路径没把它们合起来。

同发的这一轮**不走历史**：附件直接拼进当前 user 行。理由是回声时机不可控，
靠历史等于把「模型能不能看到这张图」交给一次竞态。

## 3. 契约

### 3.1 消息面

```
draft 非空 + 选文件  →  { kind:"file", text: draft, file:{id,name,mime,size,key,text?}, mentions?, replyTo? }
draft 为空 + 选文件  →  行为不变：{ kind:"file", text:"", file:{...} }（不触发智能体）
```

- 走 `submitMessage` 同一条发送路径：无 subtle 拦、未绑定 LLM 拦、连接未就绪拦、MCP 懒预检，全部复用；
- 未绑定拦截提前到**上传之前**——否则白传一个占配额、又发不出去的孤儿文件；
- 同发成功即清草稿 / @ chip / 引用；解析截断与「模型不支持视觉」提示的口径与原来一致。

### 3.2 提示词面

`TriggerDeps.buildUserTurn?(text, profile)`（新增，可选）：触发端负责组装本轮 user 行。

```
无附件      → { role:"user", content: text }                        （与之前逐字等价）
图片        → { role:"user", content: text, contentParts:[text,image] }
文档        → { role:"user", content: text + "\n\n" + 附件块 }        （与历史行同一拼接口径）
两者都解不开 → 回落纯文本行，不阻断生成
```

编排层只做一件事：`messagesFor` 把这一行放在准备后的历史之后。
**解密、base64、能力判定全留在触发端**（`agentStream` 不认识 crypto 与网络，保持纯逻辑可测）。

去重：`fetchHistory` 跳过 `payload.file.id === 本轮附件 id` 的历史行。
回声先到时这张图只在当前轮出现一次；回声没到时它本来就不在历史里。同一次上传的 id 唯一，按 id 去重是确定性的。

## 4. 边界（不变的红线）

- **能力闸同源**：只有 `resolveCapability(profile).supportsVision` 为真才解密读图；非视觉模型一个字节都不去解，判定与丢弃同源。
- **单图 4MB / 历史 4 张上限不变**（`VISION_MAX_BYTES` / `VISION_MAX_IMAGES`）。
  本轮这张不计入「历史 4 张」——常量原意是历史侧封顶，最坏情况一次请求 5 张图，供应商上限远未到。
- 群里两个智能体可能一个能看图一个不能：按**各自绑定的模型**逐 mention 决定。
- 图片仍在本地解密后直连供应商，服务端只存密文；E2E 不降级（无 subtle 一律拦在上传前）。
- 重试（错误行「重试」）沿用 `streamMeta` 里记下的本轮附件，否则重试的那一轮会突然看不见原图。

## 5. 明确不做

- 待发送附件托盘（staged attachments）与多图同发：一次点选仍是一张图，输入框草稿仍是一条正文；
- 空草稿 + @ 时触发智能体（纯附件消息照旧只落消息、不生成）——需要「问图」请把话写进输入框；
- 非视觉模型的替代方案（OCR、图片转述）不动。

## 6. 测试

- `lib/agentStream.test.ts`：`buildUserTurn` 注入生效 / 抛错回落纯文本行且不阻断生成；
- `components/ChatPage.test.tsx`：同发出一条 `text+file` 消息、当前 user 行带 `contentParts`、
  历史里不重复该附件、草稿与 @ chip 清空；
- 原有用例守住不变面：纯附件消息（空草稿）仍发 `text:""`、非视觉模型不附片也不解密、超 6MB 不上传。

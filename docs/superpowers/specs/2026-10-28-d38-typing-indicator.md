# d.38 · 正在输入提示（人类会话）

- 日期：2026-10-28
- 相关版本：d.37.1.9.0（基线）、本 spec = d.38.1.9.0（特性位 +1）
- 上游依据：`docs/research/2026-10-22-deep-audit-followup-plan.md` P2 体感缺口（实时反馈）+ 本轮源码勘察
- 涉及包：`packages/shared`（两个 WS 事件）、`packages/server`（WS 转发与节流）、`packages/web`（发送节流与展示）
- 说明：只传「有人在输入」这一元数据，**不传输入内容**；不改 E2E、不改消息存储。

## 0. 问题

- 人类会话里，对方在不在、有没有正在回复，界面完全没有信号：`ChatPage` 只有发送后的消息与 agent 流式气泡。
- 群聊里更明显：连「有人正在回应」都不知道，容易重复追问或误以为消息没发出去。
- 智能体会话已有流式打字机（`AgentStreamBubble`），缺的是**人类**这一半。

## 1. 决策

### A. WS 元数据事件（不落库、不加密）

- 客户端事件：`{ type:"typing", conversationId }`（`WsClientEventSchema`）。
- 服务端事件：`{ type:"typing", conversationId, userId }`（`WsServerEventSchema`）。
- 服务端仅做成员校验 + 广播，**不存储**、不进离线队列语义（客户端只在已连接时发）。
- 不携带任何输入内容；服务端本来就掌握收发时间，这条元数据不新增内容暴露。
- 收到自己的 `userId` 一律忽略（广播按会话发给全体成员，含发送者自己的其他设备）。

### B. 节流与过期

- **发送端**：输入非空且已连接时，最多每 **2 秒**发一次 `typing`（`TYPING_SEND_INTERVAL_MS=2000`）。
  空输入不发；发送消息后不额外发「停止」，由接收端收口：**收到该发送者的消息时立即清除其输入态**；
  其余情况（停手、断线、事件丢失）由 3 秒 TTL 过期。
- **服务端**：每个连接每秒最多转发一次（`TYPING_MIN_INTERVAL_MS=1000`），防恶意/故障客户端刷屏。
  超出静默丢弃（不报错、不回包）。
- **接收端**：每个 `(conversationId, userId)` 记录最后事件时间；**3 秒**没有新事件即视为停止
  （`TYPING_TTL_MS=3000`）。切会话清空本会话的输入态。

### C. 展示

- 位置：输入框上方一行，占固定高度（避免出现/消失导致输入区跳动）。
- 文案（中文、无 emoji）：
  - 1 人：`鲍勃 正在输入…`
  - 2 人：`张三、李四 正在输入…`
  - 3 人以上：`张三 等 3 人正在输入…`
- 名字来源：direct 用 `peer.displayName`；group 用当前成员快照 `groupMembers.byId`（缺名字回退「有人」）。
- `role="status"`、`aria-live="polite"`：只在有输入提示时播报；不做每 3 秒重复播报（同一文案不变不重排）。
- 智能体不参与：agent 的输出已有流式气泡，再看「正在输入」是噪音。

## 2. 明确不做

- **真实在线状态（presence）暂缓**：WS 连接目前挂在 `ChatPage`，切到主页/工作区即断开；直接用它做在线状态会把「在看别的页面」显示成离线。要做得先把 WS 上提到 App 壳，牵动 E2E 解密 handler 与流式归属，另立规格。
- 不做「最后在线时间」「正在播放/正在录音」等扩展状态。
- 不做已在输入草稿的同步（草稿仍只在本机）。
- 不把 typing 写入消息库、不做跨设备已读之外的持久化。
- 不引第三方依赖。

## 3. 风险与处置

| 风险 | 处置 |
|---|---|
| 频繁输入造成帧风暴 | 客户端 2s 节流 + 服务端每连接 1s 兜底；超限静默丢弃 |
| 断线期间排队，恢复后补发过期 typing | 客户端只在 `connected` 时发送；`ws.send` 在未连接时本会入队——发送前判 `connected`，避免过期帧 |
| 群成员名字缺失（快照未落定） | 回退「有人」；不阻塞消息 |
| 过期定时器在后台标签页被节流 | 用 `Date.now()` 判过期而非依赖定时器次数；定时器只负责清理 UI |
| 多设备自己触发提示 | 接收端忽略 `userId === 自己` |
| 恶意客户端高频 typing | 服务端每连接 1 秒最多转发一次，且必须先通过成员校验 |

## 4. 测试计划

| 文件 | 覆盖 |
|---|---|
| `packages/server/src/ws.test.ts` | 成员发 typing → 同会话成员收到 `{type:"typing",userId}`；非成员收到 `error(forbidden)`；1 秒内第二条被静默丢弃；超过 1 秒窗口后恢复转发 |
| `packages/web/src/components/ChatPage.test.tsx` | 输入非空 → 发 `{type:"typing",conversationId}`；2 秒内连续输入只发一次（fake timers）；未连接时不发；智能体会话不发；收到他人 typing 显示 direct 名；自己/别的会话忽略；3 秒后消失；**该发送者的消息到达即清除其输入态（不等 TTL），其他发送者不受影响**；切会话清空、旧连接晚到不污染；群聊显示成员名与 2/3+ 句式；缺名回退「有人」 |
| shared schema | 类型编译由 server/web typecheck 兜 |

## 5. 验收

- 门禁：`pnpm --filter @heming/shared build && pnpm -r build && pnpm -r --workspace-concurrency=1 test` 全绿。
- 人工复核：两个窗口（或两账号）互发时，对方输入框上方出现「正在输入…」，停手 3 秒后消失；
  群聊显示名字；自己输入不出现自己的提示。
- 版本：`d.38.1.10.0`；CHANGELOG、HANDOFF、INDEX 同步。

## 1. 问题：上手门槛在哪

改之前，自建智能体与自定义技能的「第一分钟」有三类门槛（均为代码实证，不是主观感受）：

| 编号 | 门槛 | 证据（改前代码） |
|---|---|---|
| C1 | **空白表单恐惧**：打开「新建智能体」只有一个空表单，名称、简介、头像、系统提示词、绑定连接五组字段平铺，用户不知道从哪下手 | `AgentFormModal.tsx`（改前）字段平铺，无模板、无分段 |
| C2 | **进阶字段与新手字段同等显眼**：系统提示词（最多 8000 字）与模型绑定和名称并排，好像「必须填」 | 同上：提示词 textarea 紧跟在基础字段后，无折叠 |
| C3 | **建完看不到结果**：创建只 `onClose()`，用户还要自己在左栏找到新智能体、再点一次才能开始对话；技能更是「建了但没分配 → 对话里根本不生效」 | `AgentFormModal.submit` 只调 `onClose`；`SkillPool.assigned()` 对非内置技能默认不分配，而技能页当时**没有**「新建技能」入口，只能去记忆区/自我优化绕 |
| C4 | **术语与错误提示不落地**：「绑定连接」「简介」「未绑定」是系统视角；名称空错误只出现在弹窗底部，不指向具体字段 | 改前 `绑定连接` / `简介` / `未绑定` 文案；错误块位置 |

## 2. 简化了什么

### 2.1 自建智能体（`AgentFormModal.tsx` + `AssistantPage.tsx`）

1. **从模板开始（4 个预设）**：弹窗顶部一行四张卡，点一下把**空着的**名称 / 一句话描述 / 系统提示词填好。
   - 只填空字段：用户已经输入的内容一律不覆盖；
   - 再次点击同一模板、或换一个模板，都不会追加/重复提示词（`applyTemplate` 逐字段 `trim()` 判空后才写）；
   - `aria-pressed` 标记当前套用的模板，视觉与读屏同时可辨。
2. **表单分两段（渐进披露）**：
   - 「基础信息」：名称（必填）、头像（可选）、一句话描述（可选）；
   - 「进阶设置（可选）」：系统提示词、模型连接，**默认收起**；编辑已有智能体且进阶字段非空时默认展开（避免「已有配置看不见」）；
   - 折叠按钮带 `aria-expanded` / `aria-controls`，入口文案自带信息味（「系统提示词、模型连接；不填也能直接用」）。
3. **文案降门槛**：
   - 头像标「（可选）」，并说明「不传就用名称首字，之后也能换」；
   - 名称 placeholder 给示例（「例如：周报助手」）；描述改叫「一句话描述（可选）」并给示例；
   - 提示词 placeholder 给一段可直接改的示例，并写明「不填也能用：不写就按默认助手方式回答」；
   - 模型连接改名「模型连接（可选）」，说明「不绑定 = 用默认连接」，空选项文案改为「不绑定（用默认连接）」；
   - 名称校验错误**落在名称输入框下面**（`role="alert"` + `aria-invalid` + `aria-describedby`），不再只挂在弹窗底部。
4. **创建后直接开聊**：新增 `onCreated(created)` 回调；`AssistantPage` 收到后复用既有 `openAgent` + `openConversation`，右栏直接进入该智能体的对话——**不新增页面、不新增路由**。
5. **新建入口更直白**：
   - 名册表头「＋」改为「＋ 新建」（`aria-label="新建智能体"` 不变）；
   - 名册空态给两个直达动作：「新建智能体」（焦点落名称）/「从模板创建」（焦点落第一个模板，`startAt="templates"`）；
   - 右栏空态文案改成「从左边选一个智能体就能直接对话；没有合适的，点左栏右上角「新建」创建一个」。

### 2.2 自定义技能（`SkillsPage.tsx`）

1. **新增「新建技能」弹窗**（此前技能页没有新建入口，只能绕记忆区/自我优化）：
   - 3 个模板：写作润色 / 代码审查 / 会议纪要，只填空字段，不覆盖已输入；
   - 必填**只有名称与内容**；描述「一句话描述（可选）」；内容 textarea 给示例 placeholder（什么时候用 + 按什么步骤做）；
   - 名称/内容缺失时错误分别落在对应字段下方，不写库。
2. **创建即分配**：若技能页已选中智能体，新建后自动 `skills.assign(agentId, id)`——直接消除「建了却不会用于对话」的坑；未选中智能体时只入技能池并提示后续如何分配。
3. **空态直达**：技能池为空时给两个动作「新建技能」「导入 SKILL.md」；「已装技能」分组空态给「导入 SKILL.md」，「自定义技能」分组空态给「新建技能」（导入按钮会顺带切到技能池并展开导入框）。
4. **把「未分配不会用于对话」写清楚**：
   - 顶部：`已分配 N 个技能；只有已分配的技能才会用于「<智能体>」的对话`；
   - 技能池底部：`要用于对话，需要「启用」并「分配给对应智能体」`；
   - 「分配对象」标签改为「给哪个智能体用」。
5. **未破坏既有能力**：SKILL.md 导入/导出、沉淀、四分类分组、按智能体分配矩阵、删除二次确认、搜索、插件/系统来源徽标、`SkillsView` 嵌入视图全部沿用原实现（只抽出了共用的 `importPanel` 片段）。

## 3. 为什么这样做（对应门槛）

| 门槛 | 对应做法 | 依据 |
|---|---|---|
| C1 空白表单恐惧 | 4 个模板一键填空白字段 + 名称/内容为唯一必填 | 模板化起步：Notion 以模板/技能/智能体模板作为「从空白开始」的替代路径（[Notion Marketplace](https://www.notion.com/templates)） |
| C2 进阶字段喧宾夺主 | 「基础 / 进阶」两段，进阶默认收起，编辑已配置时自动展开 | 渐进披露：首屏只放高频、必要选项，进阶项按需展开，并让「如何展开」的入口显眼、带信息味（[NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)） |
| C3 建完看不到结果 | 创建成功 → 直接激活会话；新建技能自动分配给当前智能体 | 空态/完成态给出下一步动作，减少「建完还要自己找」的二次跳转 |
| C4 术语与错误提示 | 口语化标签（一句话描述 / 不绑定 = 用默认连接）、字段级错误、示例 placeholder | 表单标签用用户语言；错误就近展示，指明是哪个字段 |

> 外部资料只作设计参考，未引入任何新依赖；实现完全沿用仓库既有组件与 `ui-*` 语义类。

## 4. 交互与字段

### 4.1 自建智能体弹窗

```
┌─ 新建智能体 ──────────────────────────────┐
│ [头像] 新建智能体            提交中…      │
│ ┌ 从模板开始（可选） ───────────────────┐ │
│ │ [通用助手] [写作润色]                 │ │
│ │ [代码助手] [数据分析]                 │ │
│ │ 点一个预设…（或：已套用「X」：只填空字段）│ │
│ └───────────────────────────────────────┘ │
│ 基础信息                                  │
│ 名称（必填）   [例如：周报助手          ] │
│ 头像（可选）   [上传头像] 不传就用名称首字 │
│ 一句话描述（可选）[例如：帮我把邮件改短… ] │
│ [进阶设置（可选）] 系统提示词、模型连接…   │
│   （展开后）                              │
│   系统提示词（仅本机）[示例…不填也能用]    │
│   模型连接（可选） 不绑定 = 用默认连接     │
│   [<select> 不绑定（用默认连接） | 连接… ] │
│                       [取消] [创建]       │
└───────────────────────────────────────────┘
```

| 字段 | 必填 | 落库位置 | 说明 |
|---|---|---|---|
| 名称 | 是 | 云端 `POST/PUT /api/agents`（`name`） | ≤32 字；错误就近提示 |
| 头像 | 否 | 同上（`avatar`，dataURL 或 null） | 保留原校验：仅图片、约 ≤449KB |
| 一句话描述 | 否 | 同上（`description`） | ≤500 字 |
| 系统提示词 | 否 | 本机 `heming.agentPrompts`（`setPrompt`） | ≤8000 字；非空才落，编辑可清空 |
| 模型连接 | 否 | 本机 `heming.agentLlm`（`setBinding`） | 候选链 `route.<id>` 与单连接同旧版 |
| 创建回调 | — | 不落库 | `onCreated(created)` 仅供宿主页直接开聊 |

提交 payload 与旧版**逐字一致**：`{ name, description, avatar }`；更新同样只有这三个字段（测试断言 `toEqual`）。

### 4.2 新建技能弹窗

```
┌─ 新建技能 ────────────────────────────────┐
│ 新建技能  只需名称和内容，其余可空     [×] │
│ ┌ 从模板开始（可选） ───────────────────┐ │
│ │ [写作润色] [代码审查] [会议纪要]      │ │
│ └───────────────────────────────────────┘ │
│ 名称（必填）    [例如：周报润色        ]  │
│ 一句话描述（可选）[例如：把周报改短…   ]  │
│ 技能内容（必填）                          │
│  [写清「什么时候用 + 按什么步骤做」…   ]  │
│ 创建后会自动分配给「<当前智能体>」…       │
│                          [取消] [创建技能]│
└───────────────────────────────────────────┘
```

| 字段 | 必填 | 落库（`SkillPool.create`） | 说明 |
|---|---|---|---|
| 名称 | 是 | `name` | ≤32 字 |
| 一句话描述 | 否 | `description` | ≤200 字；路由会参考 |
| 技能内容 | 是 | `instructions` | ≤8000 字；注入正文 |
| 触发词 / 标签 | 否 | `triggers: []` / `tags: []` | 本轮不放进表单：名称+描述足够路由，减少字段（取舍见 §5） |
| 来源 / 版本 / 启用 | — | `source: "user"`、`version: "1.0.0"`、`enabled: true` | 与 `SkillPool.create` 既有默认一致 |
| 分配 | — | `heming.skillAssignments.v1`（`assign`） | 仅当前已选智能体自动分配；不新增存储键 |

## 5. 未做项（明确不做）

- **记忆区 / Wiki 的结构改版**：本轮只做任务 4 的 1、2（自建智能体、自定义技能）；记忆区、Wiki 保持现状，不改结构、不改交互。
- **自定义内容云端同步 / 市场 / 分享**：不做；自建智能体名册仍走既有 REST，技能与提示词/绑定仍只在本机。
- **任何 `localStorage` 键位迁移**：不新增键（仍是 `heming.agentPrompts`、`heming.agentLlm`、`heming.skills.v1`、`heming.skillAssignments.v1` 等既有键），不改存储结构，不做迁移。
- **技能表单加触发词/标签输入**：为避免字段膨胀，本轮不做；自定义技能靠名称/描述/内容路由。若后续有需求，可在同一弹窗追加「高级」折叠段（与智能体弹窗同模式）。
- **智能体模板的「保存为我的模板」/ 模板管理**：不做，模板是内置常量（`AGENT_TEMPLATES` / `SKILL_TEMPLATES`）。
- **个性设置**：归 `nav-shell` 在 `SettingsPage` 落，本工作流不碰该文件。
- **真机/肉眼验收**：本文档不宣称「已验证视觉效果」；验证以自动化测试与类型检查为准。

## 6. 数据边界与样式约束

- 不新增数据模型字段、不新增存储键、不改提交 payload 形状（测试 `提交 payload 与旧版一致` 断言）。
- 系统提示词、模型绑定、技能池仍只写本机；未触碰云端 API 契约。
- 样式只复用既有语义类：`ui-btn / ui-btn-sm / ui-btn-md / ui-btn-primary / ui-btn-ghost / ui-btn-danger / ui-input / ui-caption / ui-body-sm / ui-section-title / ui-empty* / ui-chip / ui-table`，以及这些文件里**已存在**的 Tailwind 工具类与灰度值（暗色主题在 `index.css` 已有对应覆盖）；未新增字体档位或新颜色。
- 无障碍：弹窗 `role="dialog" aria-modal="true"` + 既有 `useModalA11y`（Esc 关闭、Tab 循环、焦点归还）；折叠按钮 `aria-expanded/aria-controls`；模板按钮 `aria-pressed`；名称错误 `role="alert"` + `aria-invalid` + `aria-describedby`；「从模板创建」打开时焦点落到第一个模板，「新建智能体」落到名称。
- `open=false` 时所有 hooks 先执行再早返回（Hooks 规则）保持不变。

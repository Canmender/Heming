# 模态弹窗开着时全局快捷键不再穿透（d.29.1.8.0）

- 日期：2026-10-22
- 相关版本：d.26.1.7.0（弹窗屏蔽背景 + 焦点归还）、d.29.1.8.0（本 spec）
- 涉及文件：`packages/web/src/components/useModalA11y.ts`、`packages/web/src/App.tsx`

## 1. 问题

d.26 把「弹窗开着点不动背景」做掉了，`docs/HANDOFF.md` §6 当时留下一条明确没做的事：

> 弹窗打开时全局快捷键（`Alt+1–8`、`Ctrl+\`）仍生效——`inert` 不拦 JS 事件，与本特性正交、另议。

它不是理论问题。`inert` 只作用于点击与焦点，**不作用于 `keydown`**，而切页监听挂在 `window` 上：

1. 确认框开着按 `Alt+3` → `setPage("skills")` 照常执行，页面换掉，弹窗仍留在 DOM 里
   （它渲染在页面子树内，本仓无 portal），于是 `blocked` 引用计数、`openDialogs` 栈、
   Esc 归属、关闭后的焦点归还，全都作用在一个已经不是当前视图的子树上。
2. 同一个键按两次以上，用户看到的是「弹窗还在那儿，但背后的页面已经不是刚才那个」——
   比切不回上一页更难解释，因为它违反 d.26 已经建立的直觉：弹窗开着，画面是冻结的。
3. `Ctrl/⌘+K` 更糟：命令面板渲染在 App 根（`App.tsx:144`，`shellRef` 之外），
   它一开就把整个 shell 子树 `inert` 掉，**包括正开着的那个弹窗**，而弹窗自己不知道自己被冻住了，
   仍然留在 `openDialogs` 里。两个模态层在 DOM 上不嵌套，`topToken()` 的「最内层」判定
   退化成「后入栈的那个」，Esc 该关谁变成猜。

## 2. 决策

### 2.1 只拦「会换掉画面」的键，范围宁小不大

拦：`Alt+1–8`（切页）、`Ctrl/⌘+K`（开面板）。不拦：`Esc`/`Tab`（本来就该归弹窗）、
输入框内的键（沿用 d.26 之前的 `inText` 早退，连 `preventDefault` 都不做，避开输入法组合键）、
以及各页面自己的局部快捷键。

吞键时仍然 `preventDefault`：既然决定这一键此刻不做事，就不要把它再交给浏览器默认行为。
`inText` 那条分支保持原样直接 `return`——那是「这个键根本不是快捷键」，不是「快捷键被禁用」。

### 2.2 判据复用现成的模态栈，不另建一份状态

`useModalA11y` 已经维护 `openDialogs`（`topToken` 靠它判嵌套）。给条目补一个 `modal` 字段
（取 `blockBackground`），导出 `hasOpenModal()`：**面板仍挂载**且**屏蔽背景**才为真。
存活判定与 `topToken` 逐字一致，避免出现「Esc 认为没弹窗、快捷键认为有弹窗」的分裂。

为什么不新起一个 zustand 字段或 context：弹窗是各页面就地渲染的，谁开谁负责；
再引一份状态就多一份会漏同步的东西（关弹窗时忘了 set false 是这类状态最经典的 bug）。

### 2.3 非模态浮层不算，常驻但未打开的也不算

- `blockBackground:false`（`NotificationCenter.tsx:51`）不计入：抽屉本来就允许「点外面就关」，
  拦快捷键等于把它偷偷升级成模态，违背 d.26 定下的口径
- `active:false` 的常驻弹窗不入栈，自然不拦
- 语音通话浮层（`VoiceCallPanel.tsx:94` 的 `data-a11y-keep`）**没走这个 hook**，
  所以通话中 `Alt+N` 照常切页——这是刻意的：通话面板是常驻层，不是需要裁决的模态

### 2.4 App 侧只加一个门禁，不改监听结构

两处 `keydown` 各自在动作前问一次 `hasOpenModal()`，不引入「快捷键上下文」这类抽象：
本仓全局快捷键只有这两处，加一层反而更难读。

## 3. 隐私与边界

纯前端键盘行为，不新增存储、不新增网络请求，不落任何新数据。既有红线（记忆只在本机、
个人数据不出设备、E2E 不降级）与本轮无交集。

## 4. 测试

| 文件 | 覆盖 |
|---|---|
| `components/useModalA11y.test.tsx` | `hasOpenModal()`：模态开着为真、卸载回假、非模态浮层与 `active:false` 不算；嵌套时内层卸载仍为真（外层还开着） |
| `App.test.tsx` | 预览弹窗开着：`Alt+5` 不切页、`Ctrl+K` 不开面板、弹窗仍在；关掉后两者都恢复 |

`App.test.tsx` 的用例走真实链路（点文件行的「预览」→ `FilePreviewModal` 挂载 → 按快捷键），
不是直接调 `hasOpenModal()`，这样 hook 与 App 的接线断了也会红。

## 5. 已知边界

- **只拦 window 级监听**：各页面自己在文档上挂的监听若绕过 `useModalA11y`，本轮不管；
  现有全局键位只有 `App.tsx` 那两处。
- **不做 portal**：弹窗仍在页面子树内，这是 d.26 就定下的取舍（要动 10 个挂载点与 z-index 继承），
  本轮只是把键盘侧的漏洞补上，没有改变结构。
- **读屏软件仍未实测**（NVDA / VoiceOver），见 HANDOFF §5 待办 #2。

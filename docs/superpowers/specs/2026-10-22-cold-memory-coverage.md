# 冷记忆清单的覆盖面与计数一致性（d.29.1.7.0）

日期：2026-10-22
状态：已实现
相关：`docs/superpowers/specs/2026-10-22-memory-personalization-weights.md`（d.28 用量账本与冷清单）、`docs/HANDOFF.md` §5 #4/#7

## 1. 问题

d.28 上线后自检发现三件事，都属于「功能做出来了但没做到位」，不是新功能：

1. **冷清单只看了一个桶**。它取的是 `layers.globalSemantic`（全局公用桶），而召回读的是
   `store.semantic(agentId)` = **全局桶 + 该智能体私有**。于是自动沉淀、显式记录里落到私有条目的那些
   ——反复注入却从没被引用过的——**永远进不了这份清单**；情景记忆（`layers.episodic`）更是一条都没列，
   而它同样占语义 40%／情景 40% 里的第二份额度。这个清单存在的理由就是「帮人找出白占预算的记忆」，
   覆盖面缺一半等于没做。
2. **删除情景条目不清计数**。账本 `heming.memory.usage.v1` 按条目 id 累加，删语义条目时调了 `forgetUsage`，
   删情景条目时没调。后果不是「难看」而是**功能性**的：账满 400 条按「最后一次计入」淘汰最旧，
   孤儿 id 会占着容量、把还在被使用的有效计数挤掉，那些记忆下次召回就退回 ×1（权重无故消失，用户无从解释）。
3. 发布后另发现的三处非行为性技术债（未用单例、恒真过滤、共享空对象），见 §4。

## 2. 决策

### 2.1 清单的输入换成「召回集」，不是「某个桶」

```
coldRows = layers.semantic（全局 + 私有；未选智能体 = 所有桶）
         ∪ layers.episodic（同一口径）
         过滤 isColdUsage(usage[id])
         按 usage[id].injected 降序
```

- **判据一个字没改**：注入 ≥ `COLD_MIN_INJECTED`(6) 且疑似引用 0 次。
- **排序依据换成注入次数**：这份清单是给人逐条删的，「它挡了多少预算」是唯一有用的信息；
  原先按数组顺序（等于写入顺序）排，最占地方的一条可能排在最后。
- **仍不自动淘汰、不自动降权**：判据是词重合，偏保守（工具调用里用了但正文没复述不算），
  把漏判变成删数据是拿用户资产冒险。文案继续写明「系统不会因为『冷』自动降权或删除」。

### 2.2 每行必须说清「哪一层、谁的」

情景条目没有 `key`，只有 `summary` 和日期；多个智能体的条目在未选中智能体时会混在一起。
所以行内固定输出：层名（语义／情景）+ 归属智能体（仅「全部智能体」视角）+ 累计计数注脚。
标题行：语义条目用 `key`，情景条目用 `YYYY-MM-DD 的对话沉淀`。

### 2.3 删除不新造确认口径

冷清单的行内按钮只负责把条目塞进既有确认状态：语义 → `pendingSemantic`（「删除记忆」弹窗），
情景 → `pendingEpisodic`（「删除情景记忆」弹窗）。确认文案、`bump()` 重算、成功提示全部复用，
避免出现「同一个删除动作在两个入口上有两种确认强度」。

### 2.4 计数与条目同进同退

`pendingEpisodic` 的处理器补 `recorder.forgetUsage([id])`，与语义删除同口径。
不变式：**账本里的 id 集合 ⊇/≤ 实际存在的条目**（账本只多不少会占容量，少了则下次召回没依据）。

## 3. 隐私与边界

- 读的还是本机 localStorage 的用量账本，**没有任何数据出设备**，也没有新增任何模型调用。
- 账本不参与记忆导出（沿用 d.28 口径），清除召回记录时与日志一起清零。
- 「全部智能体」视角下列出所有桶的私有条目，与记忆页「数据库」标签原有的口径不同（那里刻意只显示公用桶）：
  这里的目的不是「看我的长期记忆」，而是「找出该删的」，所以必须包含私有条目。

## 4. 一并清理的三处技术债（不改行为）

| 位置 | 问题 | 处理 |
|---|---|---|
| `lib/memory/usage.ts` 末尾 | `usageLedger` 模块级单例无人调用，注释还写反（真正在用的是 `RecallRecorder` 构造参数里那份） | 删除导出 |
| `lib/memory/recall.ts` 两条排序 | 乘完分数后再 `.filter(score > 0)` 恒真（`base > 0` 已筛、乘子 ≥1） | 删除过滤 |
| `lib/memory/recall.ts` 早退 | 「未启用」与「异常」共用同一个空结果对象，调用方写一次即污染下一次 | 两条早退各回一份新表 |

## 6. 已知边界与后续

- 判冷仍然只看「注入次数」，不看它占了多少字符；一条被截断注入的记忆按一次计入。
- 情景条目按 `at` 排序的原有卡片视图不变，只有冷清单改成按注入次数排。
- 若将来要做自动淘汰，前置条件至少是：判据叠加「低置信 + 长期未更新」，且**默认只生成建议、由人确认**——
  与 HITL 一样不提供任何「全部允许」式的批量放行。

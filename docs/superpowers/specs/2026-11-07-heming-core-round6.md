# 本体第六轮：会话阅读位置恢复（d.83.2.42.0）

- 日期：2026-11-07
- 分支：`feat/d77-heming-core`
- 来源：第三轮「刷新恢复页面/Tab」之后剩下的最后一块——消息列表的阅读位置；也是审计 P1-1 的自然延伸
- 范围：`lib/chatScroll.ts` 新增；`ChatPage` 切会话/滚动/写盘接线；测试与真机验证

## 1. 语义：恢复「读到哪」，不恢复「滚动条数字」

| 上次状态 | 回来时 |
|---|---|
| 停在历史里（未贴底） | 回到那一屏（scrollTop 按会话恢复） |
| 贴着最新消息 | 继续从最新看起，不浮出「↓ 新消息」 |

判定用「距离底部 < 80px」与现有贴底跟随同一口径，避免出现「恢复后系统以为用户离底、其实就在底部」的矛盾。

## 2. 存储

| 键 | 存储 | 内容 |
|---|---|---|
| `heming.chatScroll.v1:<convId>` | sessionStorage | `{ top, atBottom, windowCount }` |

- 与页面/Tab 快照同一口径：**刷新保留、关窗清空**；
- 按会话 id 分键，切到别的会话不受影响；
- 只存位置数字，不存消息文本（用例断言存储里不出现消息正文）；
- 脏值/坏 JSON/非法字段一律回落 null（宁可回最新消息，不猜位置）；会话 id 只收安全字符，避免污染存储键。

## 3. 窗口化的配合

消息列表只渲染最近 `DEFAULT_WINDOW`（60）条，窗口只增不减。恢复深历史时：

1. 先把 `windowCount` 展开到「上次那一窗」；
2. 落位时若内容高度仍不够（`top > maxScroll + 24`）且还有更早消息，再放一窗，下一轮重试；
3. 已加载全部仍不够 → 停在能滚到的最深处（不为对齐数字无限加载历史）；
4. 首帧量不出高度（布局未完成 / jsdom）→ 挂一帧 rAF 重试，最多 30 帧。

写盘：滚动时采样、200ms 节流；`pagehide` / `beforeunload` / 组件卸载时补最后一次。

## 4. 验证

- 单测：`lib/chatScroll.test.ts` 4 例；`ChatPage.test.tsx` +2（带快照恢复 420px、贴底快照不回放旧位置）。
- 真机（1600×1000，0 error）：打开会话 → 滚动 → `sessionStorage` 出现该会话快照（本次本地库消息少，
  滚动量被真实高度夹到 0，写盘路径仍验证）→ 刷新后仍在原会话、无报错。
  像素级恢复由 jsdom 用例覆盖（jsdom 无布局，用例里显式给 scrollHeight/clientHeight）。

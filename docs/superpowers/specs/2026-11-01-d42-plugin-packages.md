# d.42 · 插件包：声明式能力包与插件区

- 日期：2026-11-01
- 相关版本：d.41.1.11.0（基线）、本 spec = d.42.1.11.0（特性位 +1）
- 涉及包：`packages/web`（纯前端，不改服务端、不改协议）
- 上游判断：d.41 让能力来源可归属（`ToolOrigin` 已含 `plugin` 占位），本轮把「插件」落成一个**可安装、可停用、可卸载的数据包**，不引入执行期运行时

## 0. 问题

- **能力包无法整体分发**：技能可以逐个粘贴 SKILL.md 导入，但没有「一组技能 + 元信息」的整体单位；用户装一套能力要重复操作多次，卸载也找不到边界。
- **来源不可归属**：技能池里只有 `source: "imported"`，无法回答「这几个技能属于哪个插件、一起停用 / 一起删除」。
- **平台化缺一块拼图**：d.41 的能力注册表已有 `plugin` 来源枚举，但没有真实插件实例；插件页是把枚举接上现实的下一步。

## 1. 决策

### A. 插件包格式：`plugin.json`（纯声明式）

```json
{
  "schemaVersion": 1,
  "id": "acme.finance",
  "name": "财务助手包",
  "version": "1.0.0",
  "description": "财报速读与现金流检查",
  "author": "Acme",
  "skills": [
    {
      "name": "财报速读",
      "description": "提取收入、利润与现金流的关键变化",
      "instructions": "你在阅读一份财报……",
      "triggers": ["财报", "年报"],
      "tags": ["财务"]
    }
  ]
}
```

| 字段 | 规则 |
|---|---|
| `schemaVersion` | 必须为 `1`（为将来格式演进留出口） |
| `id` | `^[a-z0-9][a-z0-9._-]{0,63}$`，全局唯一，更新时按 id 覆盖 |
| `name` / `version` | 1–64 / 1–32 字符；`version` 原样透传，不做 semver 强校验 |
| `description` / `author` | ≤200 / ≤64，缺省空串 |
| `skills` | 1–50 个；单个技能 `name` ≤32、`description` ≤200、`instructions` 1–8000、`triggers` ≤20×64、`tags` ≤20×32 |
| 技能重名 | 同一插件内拒绝（trim 后精确比较） |
| 未知字段 | 静默丢弃（不建档、不进存储） |

- 只接受 **JSON**；不读取 zip / 目录 / URL。文件选择与粘贴两条入口都只把文本交给同一个解析器。
- 解析失败给中文错误，并指出字段路径（如 `skills[0].instructions`）。

### B. 安装语义：技能物化进技能池

- 每个插件技能以 `SkillDefinition` 落进现有技能池：
  - `source: "imported"`（技能区「已装技能」分组）；
  - 新增 `pluginId` 字段标记归属，插件页据此计算归属与卸载范围。
- **更新**（同 `id` 再次安装）按 `pluginId + name` 匹配：
  - 已有同名技能原地更新描述/指令/触发词/标签/版本；
  - 新增技能创建，清单里消失的技能删除（连带绑定）；
  - 插件启用状态**保留用户选择**，不因更新被重置。
- **默认分配**：没有显式分配记录的智能体默认获得「内置技能 + 插件技能」；已有显式记录的智能体，安装时把新技能追加到其分配列表——插件装完即可用，不必逐台分配。
- **停用**：插件 `enabled=false` 时其全部技能置为未启用（保留数据与分配，重新启用即恢复）。
- **卸载**：删除插件的全部技能（含使用统计与智能体绑定），再删插件记录。不可恢复，需二次确认。

### C. 存储

- 单键 `heming.plugins.v1`：`{ version: 1, plugins: InstalledPlugin[] }`。
- 插件记录保存 `manifest`（原样规范化后的清单）+ `skillIds` + `enabled` + 时间戳。
- 上限 50 个插件；超限时报错而不静默丢弃。
- 读取容错：记录逐条校验，损坏条目丢弃；整体损坏视为空，不影响技能池与聊天主链路。

### D. 插件区与导航

- 新增「插件区」页（导航位置在技能区之后，`Alt+0`；老页编号不动）。
- 页面能力：
  - 列出已装插件：名称/版本/作者/描述/技能数/技能名标签、启用开关；
  - 安装/更新对话框：粘贴 `plugin.json` 或选择文件 → 实时解析预览 → 确认安装；
  - 卸载二次确认，明确「技能与分配一并删除」；
  - 空态、错误与成功提示。
- 数据只在本机 localStorage，不联网、不上传、不导出。

## 2. 明确不做

- **不执行第三方 JS**：插件只是数据，不含代码入口；可执行插件需要进程隔离、权限与签名，活动部件翻倍且顶到本机执行红线。
- **不声明 MCP 服务**：MCP 子进程的启动参数、凭据与信任模型独立于插件包，混在一起会把「装一个技能包」变成「拉一个进程」。
- **不做在线市场 / URL 安装 / 签名校验**：本轮只解决本地包的管理闭环。
- **不做插件级智能体分配**：分配仍以技能为单位（技能区已具备），避免两套归属。
- **不上提 `PluginManifest` 到 `shared`**：当前只有 web 消费；等桌面端/服务端需要读取时再谈跨包契约。

## 3. 风险与处置

| 风险 | 处置 |
|---|---|
| 插件指令进入系统提示词，等于引入外部文本 | 与现有「导入 SKILL.md」同一信任级别；插件页明示来源与内容，安装前可预览技能清单 |
| 更新时删除旧技能误伤用户手工改过的同名技能 | 只匹配带 `pluginId` 的技能；用户自建/导入的同名技能不受影响 |
| 卸载后分配表残留 id | 技能删除即从绑定清理；`assigned()` 读取时过滤未知 id |
| 存储损坏导致插件页崩溃 | 逐条容错解析 + 空回退；页面不因数据问题阻塞主链路 |
| 导航新增快捷键冲突 | `Alt+0` 独立编号，不动老页 1–9 |

## 4. 验收

1. 合法 `plugin.json` 可通过粘贴或文件安装；安装后技能出现在技能区「已装技能」，带插件归属。
2. 同 id 更新：技能不重复、被移除的技能确实删除、启用状态保留。
3. 停用插件后其技能不参与路由；重新启用恢复。
4. 卸载插件后其技能、绑定与分配全部消失，其他插件与手工技能不受影响。
5. 非法清单（坏 JSON、坏 id、空技能、重名、超长字段）给出中文错误且不落盘。
6. 全量门禁 `pnpm -r build && pnpm -r --workspace-concurrency=1 test` 全绿。

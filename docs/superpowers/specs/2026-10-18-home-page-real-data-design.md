# 主页硬编码项替换为真实数据 — 设计文档

- 日期：2026-10-18
- 范围：`packages/web/src/components/HomePage.tsx`
- 目标：把主页所有硬编码/占位替换为真实数据源，消除「写死 0」「M3 开放创建」「二期开放」等静态文案

---

## 1. 背景

主页（HomePage）自 M3.5 UI 完善后，部分区块保留占位文案或硬编码值，与实际数据脱节：
- 「我的智能体」统计卡写死 `0`
- 版本徽标写死 `v0.1.0`
- 智能体动态区写死「M3 创建智能体后，动态显示在这里」
- 团队用量排行 Tab 写死「二期开放」

实际数据源已就绪：
- 智能体名册：`chatStore.agentsRoster`（`loadAgentsRoster()` 拉取，全量含系统预设）
- 群内智能体：`chatStore.agents`（`loadAgents()` 按群 join 名册）
- LLM 连接：`llmStore.profiles`（本机配置）
- 文件用量：`fetchFileUsage()` → `{ used, quota }`
- 未读会话：`conversations` 的 `unreadCount` 字段
- Token 用量：`tokenUsageStore.records`（已实现，无需改动）

## 3. 设计决策记录

### 3.1 智能体统计卡与动态区的口径

**决策**：统计卡「我的智能体」= 名册全部（含系统预设「和小鸣」+ 用户自建）。

**理由**：
- 主页是总览，用户想看到所有可用智能体，而非仅自建的
- 系统预设「和小鸣」在群内会出现，属于「我的可用智能体」
- 名册接口 `GET /api/agents` 返回全量，无「仅自建」过滤参数
- 若只显示自建的，需要前端按 `owner_id === me` 过滤，但系统预设 `owner_id === null`，会漏掉

**实现**：
- 统计卡：`value={String(agentsRoster.length)}`，`sub` 改为「含系统预设」或「共 N 个」
- 动态区：取 `chatStore.agents`（群内已挂载的）前 3 个，显示头像+名+描述

### 3.2 版本号注入

**决策**：版本号在构建时注入，避免运行时读 `package.json`（file:// 桌面端无法 fetch）。

**理由**：
- 桌面端 `file://` 协议无法 `fetch` 本地 JSON
- Vite 支持 `import.meta.env.VITE_*` 环境变量内联
- `packages/web/package.json` 版本为 `0.0.1`，与主页显示的 `v0.1.0` 不一致；统一为 `0.0.1`

**实现**：
- `vite.config.ts` 加 `define: { __APP_VERSION__: JSON.stringify(pkg.version) }`
- 主页用 `const APP_VERSION = __APP_VERSION__`
- 徽标文案改为 `版本 v{APP_VERSION}`

### 3.3 团队用量排行 Tab

**决策**：保留 Tab，文案改为「二期开放（需服务端汇总）」。

**理由**：
- 这是已规划的功能（交接文档 §5 第 5 项），保留入口
- 服务端确实无汇总接口，无法接真实数据
- 用户点击后看到「二期开放」提示，知道功能规划中存在

### 3.4 智能体动态区空态

**决策**：名册为空时显示「暂无智能体，可在工作区创建」；有数据时显示前 3 个。

**理由**：
- 空态文案应引导用户去创建，而非「M3 创建后…」这种过去时
- `chatStore.agents` 是「群内已挂载的」，可能少于名册全量；若用户没建群但有自建智能体，这里会显示空
- 折中：动态区优先显示 `agents`（群内已挂载），空时回退显示 `agentsRoster`（名册全量）前 3 个

## 4. 不做的部分及原因

| 区块 | 原因 |
|---|---|
| 实时通道（系统状态） | 全局无 WS 状态，只有进会话才知道是否连接；写死"会话内连接"是准确的（主页确实不在会话内） |
| 本地工作目录 | 本地目录功能未做（`App.tsx` 的 `localPaths` 也写死 `[]`），写死"未绑定"是准确的 |
| 团队用量排行 | 服务端无汇总接口，二期功能，无法接真实数据 |
| 最新资讯 | 产品文案，非数据；内容由产品/运营决定，不由代码生成 |

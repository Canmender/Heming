## 1. 现象与目标

**现象（用户报告）**

1. 「导航栏可以隐藏和呼出」——d.67 及之前导航轨是 54px 常显图标轨，无法收起，宽内容页面在
   1280/1440 屏上会少掉 54px 可用宽度；用户明确要「自动隐藏 + 左缘悬停/快捷键呼出，可固定常显」。
2. 「再次优化布局、字体字样、UI 排列」——d.62/d.63 已把字号/控件档位语义化，但本轮仍需收口：
   字体栈没有显式声明（先前的 `body` 只有 `@apply bg-surface text-ink antialiased`，完全交给浏览器默认），
   页头纵向间距、卡片圆角/阴影在各页各写一份，主页在窄窗下的多列网格会把卡片压得过窄。

**目标**

- 导航轨提供 `pinned`（默认常显）/ `auto`（自动隐藏）两种模式，**默认仍是常显**，不让老用户升级后迷路。
- `auto` 下导航轨**不占布局宽度**，左缘热区 + 快捷键可呼出一个**浮层**，不挤压主内容；可随时 pin 回常显。
- 字体、字号行高、页头内边距、卡片外观、列表节奏做一轮统一，不推倒 d.62/d.63 的 `ui-*` 体系。
- 全部改动可键盘操作、暗色下可读、`prefers-reduced-motion` 下不动效。

**非目标（明确不做）**

- 不做 E2E 会话逻辑、HITL、数据出设备的任何改动；不改桌宠目录与桌宠窗口。
- 不改自建智能体/自定义技能表单（工作流 C 负责）；不改 `AgentFormModal` / `AssistantPage` / `SkillsPage`。
- 不新增 Tailwind breakpoint、不新增第三方依赖、不加载 web font、不改版本号/CHANGELOG。

## 2. 交互设计

### 2.1 两种模式

| 模式 | 默认 | 导航轨形态 | 占布局宽度 | 持久化 |
| --- | --- | --- | --- | --- |
| `pinned` | ✅ 默认 | 常驻 54px 图标轨（与 d.67 一致） | 是（`shrink-0`，54px） | `heming.nav.mode.v1 = "pinned"` |
| `auto` | — | 收起：左缘 8px 热区（不可见）；展开：浮层覆盖在内容上 | **否** | `heming.nav.mode.v1 = "auto"` |

模式切换入口三处、同一份 store 状态，不存在两份偏好：

1. 导航轨底部 **pin 按钮**：`aria-pressed` 表示当前是否常显；pinned 时 aria-label 为「自动隐藏导航栏」，
   auto 时为「固定导航栏」；悬停浮签给出「自动隐藏 / 固定常显」+ `Ctrl B`。
2. 设置区「外观 → 导航栏」卡（`data-settings-id="nav-mode"`）：两档 radio + 说明 + 「恢复默认」。
3. 全局快捷键 `Ctrl/⌘+B`（见 2.4）。

### 2.2 `auto` 的呼出/收回

| 行为 | 触发 | 结果 |
| --- | --- | --- |
| 展开 | 鼠标进入左缘 8px 热区 | 浮层滑出；**不移动焦点**（鼠标用户不应被抢焦点） |
| 展开 | 热区被 Tab 聚焦（`onFocus`） | 浮层展开，便于继续 Tab 进导航 |
| 展开 | 点击 / 回车 / 空格激活热区（它本身是 `button`） | 展开并把焦点送进**当前页按钮** |
| 收起 | 鼠标离开浮层/热区 **300ms** 后 | 自动收回（给手抖留容错） |
| 不收起 | 焦点仍在导航轨内 | 键盘用户不会被打断（延迟到点再查一次焦点） |
| 收起 | `Esc`（仅当 auto 且已展开） | 立即收回，焦点还给热区；**不走冒泡**，只收导航 |
| 不收起 | 有模态弹窗时的 `Esc` | 让位给弹窗（`hasOpenModal()` 判定），与 Alt+N / Ctrl+K 同纪律 |

### 2.3 默认值（与调研 §2.4 对齐）

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| 热区宽度（窗口内边缘） | **8px** | 窗口内边缘没有屏幕边缘的 Fitts 红利，取建议区间 8–12px 的下限，少挡内容 |
| 退出延迟 | **300ms** | 覆盖「手抖移出 1–2 帧」；桌面产品常见量级 |
| 动效时长 | **160ms**，`ease-out` | 与 150ms 级 hover 同档；再长会跟不上手 |
| 展开/收起动效属性 | **仅 `transform` + `opacity`** | 动 `width` 会逐帧 reflow、推挤内容；这是「自动隐藏必抖」的根因 |
| 浮层宽度 | 54px（与常驻轨道一致） | 不引入第二套栅格 |
| 热区与内容的空档 | **8px**（与热区同宽） | auto 下壳层内容行留一条 8px 左空档：助手页/团队页列表行是「整行按钮、左边缘就是可点区」，热区若直接压上去会吃掉最左侧点击。空档让热区只落在空白处，内容区相对 d.67 仍净增 46px |
| 降低动效 | `prefers-reduced-motion: reduce` → `transition: none` | 系统级无障碍偏好 |

> 与调研的一处**实现差异（有意）**：调研建议浮层用 `position: fixed`；本仓的桌面壳有自定义标题栏
> （`TitleBar` 是导航轨的兄弟节点），`fixed inset-y-0` 会盖住标题栏。因此浮层用 `absolute` 定位在
> 「壳层内容行」（`App.tsx` 里加了 `relative`）内：**同样脱离文档流、同样不挤压主内容**，
> 顶边天然落在标题栏下，不需要在组件里写死标题栏高度。观感与行为等价，且不会遮住窗口拖拽带。

### 2.4 快捷键 `Ctrl/⌘+B`

| 当前状态 | 按键后的行为 |
| --- | --- |
| `pinned` | 切到 `auto`：导航收起、主内容变宽（**并落盘**，与 VS Code 的 `Ctrl+B` 语义一致） |
| `auto`，浮层收起 | 呼出浮层（焦点送进当前页按钮） |
| `auto`，浮层展开 | 收回浮层（模式仍是 `auto`，「收起」不等于「放弃自动隐藏」） |

纪律（与既有全局快捷键一致）：

- 启动动画未完成（`!bootDone`）不响应；
- 有模态弹窗（`hasOpenModal()`）时**只吞键不动作**；
- 焦点在输入框/文本域/可编辑区时不响应（浏览器里 `Ctrl+B` 是加粗，不能抢）；
- `Alt` / `Shift` 组合不参与，避免与输入法、系统快捷键撞车。

想从 `auto` 回到「永远常显」，用导航轨底部 pin 按钮或设置区「导航栏」卡（快捷键只负责显隐）。

### 2.5 与既有守卫测试的关系

| 守卫 | 处置 |
| --- | --- |
| `NavRail.digit` / `App.SHORTCUT_PAGES` / `PALETTE_PAGES` 三处一致 | 未改动任何数字键位，`palette.test.ts` 原样通过 |
| `PageFallback` 的 `data-testid="page-fallback"` | 原样保留（未改 `App.tsx` 的懒加载占位） |

## 3. 状态与持久化

```ts
// lib/navPrefs.ts —— 纯函数层（可单测，不依赖 React/DOM）
type NavMode = "pinned" | "auto";
const NAV_MODE_KEY = "heming.nav.mode.v1";
const DEFAULT_NAV_MODE = "pinned";
NAV_HOTZONE_PX = 8; NAV_HIDE_DELAY_MS = 300; NAV_MOTION_MS = 160;
normalizeNavMode(raw) / parseNavMode(raw) / readStoredNavMode(storage)
persistNavMode(mode, storage) / otherNavMode(mode)
```

```ts
// store/ui.ts —— 状态
navMode: NavMode;   // 持久化；坏值/缺失 → "pinned"
navOpen: boolean;   // auto 浮层是否展开（临时态，不落盘）
setNavMode(mode)    // 切档并收起浮层 + 落盘
toggleNavMode()     // pin 按钮：pinned ↔ auto
openNav() / closeNav()   // 只在 auto 下生效；幂等
toggleNav()         // Ctrl/⌘+B 语义（见 2.4）
```

- 存储值只写 `"pinned"` / `"auto"` 两个字符串；读取兼容早期 `JSON.stringify` 写法（`"\"auto\""`）。
- 损坏值（乱码、大小写、数字、对象、空串）一律回落 `pinned`——默认态必须是最安全的那个。
- `localStorage` 不可用（隐私模式/配额）时只在本次会话生效，不抛错、不阻塞渲染。
- **不新增其它存储键**：`heming.navOrder.v1`（导航顺序）与 `heming.nav.mode.v1`（显隐模式）互不影响，
  旧用户升级后顺序与快捷键都不变。

## 4. 无障碍

| 项 | 实现 |
| --- | --- |
| 热区可聚焦 | 热区是原生 `<button type="button">`，`aria-label="展开导航"`、`aria-expanded`、`aria-controls` 指向浮层，Tab 可达，Enter/空格展开 |
| 收起时不进 Tab 序 | 浮层收起时挂 `inert` + `aria-hidden="true"`，Tab 不会落到看不见的按钮上 |
| 展开后焦点落点 | 焦点进入**当前页按钮**（`aria-current="page"`），键盘用户不用再找位置 |
| `Esc` | 只收导航，焦点回热区；有模态弹窗时让位给弹窗 |
| 非模态浮层 | 不给背景 `inert`：它是非模态浮层，Esc 只收导航；点击内容/切页不受影响 |
| pin 按钮 | `aria-pressed` 表达开关状态，`aria-label` 随状态变化（「自动隐藏导航栏」/「固定导航栏」），并带悬停浮签 |
| 设置卡 | 原生 `role="radiogroup"` + `role="radio"` + `aria-checked`，`←/↑/→/↓` 切换，`tabIndex` 只留当前项 |
| 对比度 | `--placeholder` light `#b8b8b8`→`#767676`（≈4.5:1）、dark `#6b7078`→`#8b9199`（≈5:1）；暗色下导航浮层用语义 token（`bg-[#fafafa]`→`var(--subtle)` 等由暗色兼容层接管） |
| 降低动效 | `motion-reduce:transition-none`（`prefers-reduced-motion: reduce` 时展开/收起瞬切） |

## 5. 布局与字体改动清单

### 5.1 字体（`index.css`）

- 新增 `--heming-font-sans`：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "HarmonyOS Sans SC", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`
  ——**拉丁在前、CJK 在后**（Windows 上 Segoe UI 管英文/数字，雅黑 UI 兜底汉字）。
- 新增 `--heming-font-mono`：`ui-monospace, "JetBrains Mono", "Cascadia Code", "Cascadia Mono",
  Consolas, "Sarasa Mono SC", "Noto Sans Mono CJK SC", "Courier New", monospace`
  （带中文等宽回退，日志/代码块里中英列能对齐）。
- `@theme { --font-sans: var(--heming-font-sans); --font-mono: var(--heming-font-mono); }`
  让 `font-sans` / `font-mono` 工具类也走同一套栈；`body` 显式 `font-family: var(--heming-font-sans)`；
  `code/kbd/pre/samp` 统一等宽栈。
- **不加载外部字体**：离线桌面端首屏加载 2–5MB 字体是负收益；系统字体无下载、无布局位移。

  `.ui-input::placeholder` 改引用 token（此前是硬编码 `text-[#b8b8b8]`）。

## 6. 未做项 / 待确认

1. **真机观感未验证**：本轮只跑单测与类型检查，没有在 Windows 桌面端实机看「悬停呼出 / 滑出动画 /
   窄窗主页换行」。不做「肉眼已验证」的宣称。
2. **进入延迟未实现**：调研建议窗口内边缘 150ms 进入延迟以过滤「路过」，本轮保持「进入即展开」
   （热区仅 8px，误触面小）；若实机反馈路过误触，再叠加 150ms 进入延迟。
3. **展开态宽度未做 200–240px 的两行中文标签**：仍沿用 54px 图标轨 + 悬停浮签（与 d.67 A 方案一致），
   避免引入第二套栅格与第二套导航内容。
4. **`auto` 下没有「记住上次是否展开」**：浮层每次启动都是收起态（模式本身持久化）。
5. **未做 pin 后忽略退出延迟的特殊分支**：pinned 模式根本不会挂退出定时器，语义上已满足「pin 后不自动收起」。
6. 命令面板没有新增「切换导航栏」动作：`Ctrl+B` 是全局快捷键，不进面板动作组，
   避免 `PALETTE_ACTIONS` 的「常用动作固定 4 个」守卫与语义被稀释；面板里通过「外观 → 导航栏」的设置检索直达。

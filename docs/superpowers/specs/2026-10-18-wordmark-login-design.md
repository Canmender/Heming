## 1. 概述

三件事：

1. **启动动画前置一段手写**：「Heming」以单线手写体逐笔写出（1.5s），接现有粒子聚拢 → 静默 → 声波扩散。总时长 3.0s → **4.5s**。
2. **登录页改左右分栏**：左侧居中登录卡片，右侧居中「Heming」手写字样。
3. **启动默认最大化窗口**：铺满屏幕，保留已实现的自定义标题栏与原生窗口控件。

## 2. 时间轴（总 4.5s）

```
0.0–1.5s   【手写】「Heming」逐笔写出        ← 新增（splash 渲染）
           · 音效3：轻柔上行音（笔尖起笔）
1.5–3.0s   【粒子聚拢】四周光点聚拢 → 墨色圆点 ← 现有，不动
           · 音效1：轻柔「聚集」音
3.0–3.2s   【静默】
3.2–4.5s   【声波扩散】中心波纹揭示主界面     ← 现有，不动
           · 音效2：轻柔「共鸣」音
```

**时序常量**（`packages/desktop/splash-config.js`）：

| 常量 | 现在 | 改为 | 含义 |
|---|---|---|---|
| `WRITE_MS` | — | `1500` | 手写段时长（新增） |
| `SPLASH_MS` | `1500` | `1500` | 粒子段时长（不变） |
| `GAP_MS` | `200` | `200` | 静默（不变） |
| `WAVE_MS` | `1300` | `1300` | 声波段（不变） |
| `BOOT_TOTAL_MS` | `3000` | **`4500`** | 四段之和 |
| splash 可见地板 | `1700` | **`3200`** | `WRITE_MS + SPLASH_MS + GAP_MS` |

`BootWave` 的兜底开播时限从 `5000` 提到 **`7000`**：它要覆盖的「挂载 → 主进程送信号」间隔上限就是 splash 可见地板（3200ms），7000 留了一倍余量；若信号永不到来，用户最坏白等 7s（主进程 bug 场景）。

## 3. 手写字样

### 3.1 字形风格

**单线手写（monoline script）**，笔画等宽、圆头圆角，斜度约 8°。选它的理由：

- **零字体依赖**：项目目前没有任何字体文件与字体配置；引入手写字体要处理授权、自托管与子集化，桌面端 splash.html 还要求自包含（内联 base64 会让文件膨胀）。
- **真「书写」**：只有逐笔描边（`stroke-dashoffset`）是真的在写；用字体只能做擦除式显现，观感差一档。
- **与既有语言一致**：项目视觉是细线墨色 SVG（strokeWidth 1.5），单线手写是同一套语言的自然延伸。

### 3.2 笔画与书写顺序

按真实书写顺序逐笔描出，笔尖不抬起的连续段合并为一条 path：

```
H  ← 左竖（自上而下）→ 右竖 → 横（左→右）
e  ← 起笔横 → 上弧 → 回环 → 收笔尾
m  ← 起笔上挑 → 三个拱
i  ← 竖 → 点（最后落，独立 path）
n  ← 竖 → 一个拱
g  ← 起笔 → 上弧 → 回环 → 下伸尾
```

每条 path 按其**实际长度**分配时长（`getTotalLength()`），使笔画推进速度均匀；字与字之间留 ~60ms 间隔，模拟抬手。

### 3.3 尺寸与落位

- `viewBox="0 0 400 150"`；基线 y=104，x-height 顶 y=64，上伸至 y=22，下伸至 y=132
- 手写段：居中，宽约 `min(420px, 46vw)`，墨色 `#1a1a1a`，`stroke-width 3`（视觉上按缩放自适应）
- 写完停留约 150ms 后整体淡出（200ms），交棒粒子段——**淡出而非硬切**，避免两个墨色画面相撞

### 3.4 登录页右侧字样

同一份字形数据，**静态**呈现（不重播手写动画——每次登录都演一遍会烦）：

- 居中于右侧栏，宽约 `min(320px, 28vw)`
- 颜色 `#1a1a1a`，不描边动画
- 与左侧卡片形成「左交互 / 右品牌」的构图

### 3.5 单一真源

字形 path 数据只定义一次，放 `packages/web/src/components/wordmark.ts`（`LoginPage` 与测试直接 import）。`splash.html` 要求自包含（无打包器、无 preload），必须内嵌一份。

**防漂移**：新增 desktop 测试，读取 `packages/web/src/components/wordmark.ts` 抽出 path 字符串，断言与 `splash.html` 内嵌的完全一致。项目已把「`WAVE_MS` 两边各写一份无断言」记为技术债，这里不再重复那个坑。

│      │   和鸣        │      │                            │
│      │  登录你的账号  │      │        H e m i n g         │
│      │  ┌────────┐  │      │      （手写体字样居中）      │

│      │  ├────────┤  │      │                            │

- 两栏**等宽**（`flex-1` 各半），分隔不画线（留白分隔，符合「分割线只在必要时用」）
- 窗口窄于 `900px` 时退化为单栏：隐藏右侧字样，卡片居中（避免出现两块都挤扁）
- 卡片内容不变（「和鸣」+ 副标题 + 用户名/密码/登录），仅位置变化
- 背景沿用 `#fafafa`；卡片保持 `border-line` + `shadow-card`
- 桌面端顶部已有自定义标题栏占位，分栏区占其余高度

## 5. 默认最大化

- 主窗口创建后调用 `win.maximize()`（**不是** `fullscreen: true`——真全屏会隐藏刚做好的自定义标题栏与原生窗口控件）
- **窗口状态持久化改用 `win.getNormalBounds()`**：最大化时 `getBounds()` 返回屏幕尺寸，直接存会把用户偏好的窗口尺寸覆盖掉；`getNormalBounds()` 取的是还原态的尺寸，最大化/还原往返才正确
- 用户把窗口还原并调整尺寸后，下次启动仍是最大化（按「打开默认全屏」的要求），但再还原回的是他调过的尺寸
- `window-state.test.js` 补：最大化状态下落盘用 normal bounds

| 时间点 | 音效 | Web Audio API 合成 |
|---|---|---|
| 手写开始（0ms） | 轻柔「起笔」音 | 正弦 220Hz → 440Hz 上滑，1.2s，增益 0.08（比另两个更轻，避免开场过响）；起笔处叠一个极短的低通噪声爆（8ms）模拟笔尖落纸 |

### 字形不是一次画对的，记下两次踩的坑

字形数据用「把 SVG path 采样成 ASCII」自检（本会话无法截图），第一版仍有两处**几何结构**错误，用户看预览页后指出：

| 缺陷 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **e 成了「8」** | 上下两个闭合环共享中横 | 右腰从顶到底连通 → 上环与下碗各自闭合 | 改为右下开口起笔（沿底向左 → 上左腰 → 过顶 → 右腰下行到中横高度 → 中横向左），右腰在中横与底部起笔之间留空 |
| **m/n 像栅栏** | 四根竖笔顶着四个小凸起 | 肩从 y=68 起弧、顶点 y=61，**肩高仅 7 单位而竖笔 36 单位** | 肩改为从 y=73 起弧、顶点 y=59（占字高约 1/3） |

顺带修：e 原比 x-height 高 10 单位（大小不一）→ 收齐到与 m/n 同高；整词原未在 viewBox 居中（左 15 右 62）→ 居中到 x 44–355 / y 23–127。m 与 n 各合并为**一笔写完**（手写本来一气呵成，逐笔描出也更像在写），笔画数 14 → 10。

**两个回归测试已用旧 path 验证过确实拦得住**（不能失败的测试没有价值）：

| 测试 | 旧（缺陷版） | 新 | 阈值 |
|---|---|---|---|
| e 右腰最大 y 间隔 | **1.5**（判失败） | 12.8 | > 5 |
| m/n 存在一段纵向跨度 ≥12 的曲线（肩弧） | **8.9**（判失败） | 14.0 | ≥ 12 |

两个判据都写成**形状无关**的（逐段解析，不看整体 bbox）——否则「竖笔拉长」会把浅肩缺陷掩盖掉。

### 计划外的第 4 件事：减弱动态的可见地板

地板从 1.7s 提到 3.2s 时漏了 `prefers-reduced-motion` 这条路径：这类用户不播任何动画，却仍要对着一块静止画面等满 3.2s（比原来的 1.7s 更糟，是本设计引入的回归）。

修法：偏好只有渲染进程查得到（`matchMedia`），故主进程在 splash 加载后异步查询并回填 `lifecycle.setReducedMotion()`；查到为 true 时立刻收尾（若常规定时器已排上则就地提前触发）。

## 12. 追加修复记录（2026-10-18，用户真机反馈「动画和登录卡片全挤在左侧」）

用户反馈：「开屏动画依旧存在问题，动画和登录卡片全部集中在左侧；正确流程是手写完整『heming』→ 接后续动画 → 左卡右字样。」查下来是**一个布局塌陷 + 一个开发模式专属卡死**，手写段本身没有问题。

### 12.1 「集中在左侧」＝登录页根节点宽度塌陷（主因）

| 项 | 内容 |
|---|---|
| 根因 | `LoginPage` 根 div 是 `App.tsx` 登录分支 `<div class="flex min-h-0 flex-1">`（**row** 方向 flex 容器）的 flex 子项，却没有 `w-full`/`flex-1`。flex 子项 `flex-basis:auto` 使其宽度按 max-content 收缩 |
| 实测（CDP，1440 视口） | `login @ 0..758`、左栏 `0..390`、字样 `414..734`、右侧 `758→1418` 全空 |
| 观感成因 | 宽屏分栏其实生效了（`min-[900px]:flex-row` 是视口断点），但两栏被挤在窗口左半的一条里 → 用户看到「卡片和字样全在左边」；开屏波纹以屏幕中心揭开、而内容只在左半边，于是连动画都像「在左侧」 |
| 修法 | 根节点 `+ w-full min-w-0`（`min-w-0` 抵消 flex 子项默认 `min-width:auto`，窄窗口不被内容反撑出横向滚动） |
| 修后实测 | 1440×900：卡片 `190..530`（中心 = 1440/4）、字样 `920..1240`（中心 = 3/4）、`scrollWidth=1440`；800×700：单栏、卡片居中 `230..570`、字样 `display:none`、`scrollWidth=800` |
| 回归守卫 | `LoginPage.test.tsx` 新增用例：根节点必须同时带 `w-full`/`min-w-0`/`min-[900px]:flex-row`/`flex-col`（jsdom 无布局，只能断言 class 语义，用例注释写清「删掉就退回塌陷」） |

顺带确认：`splash.html` 手写段**本来就是居中的**——CDP 逐帧实测 1440×900 下字样 bbox `499..919`（正中），10 笔在 ~1400ms 内写完整个「Heming」，1700ms 淡出交棒粒子段。此项**未改动**。

### 12.2 开发模式下白遮罩永不揭开（同批发现）

| 项 | 内容 |
|---|---|
| 现象 | `vite` dev 打开页面后整页白屏：`.boot-wave` 常驻、`--reveal` 从未写入（`unset`）、`#root > div` 仍带 `inert`；同一份代码 `vite build` + `preview` 正常 |
| 根因 | `main.tsx` 开着 `React.StrictMode`，dev 下 effect 会跑两遍：第一轮 `startAnimation()` 置 `startedRef=true` 并挂上 rAF + 收尾定时器 → cleanup 的 `stopTimers()` 全取消 → 第二轮 `startAnimation()` 命中 `if (startedRef.current \|\| finishedRef.current) return` 静默早退。没有任何东西再推进 `--reveal`，`finish()` 永不调用 |
| 修法 | cleanup 复位 `startedRef`（使第二轮能重播）与揭示进度，**不复位 `finishedRef`**（它是「`onDone` 只回调一次」的跨轮次事实）；波纹容器改用递增 `runId` 作 `key`，重播时重新挂载才让 CSS keyframes 从 0 重跑；起播音效加 `soundPlayedRef` 防双跑叠加变响 |
| 回归守卫 | `BootWave.test.tsx` 新增 2 例（`<StrictMode>` 下渲染）：① 双跑后仍能推进到 `100.00%` 且 `onDone` 恰好 1 次；② 减弱动态下首轮已 `finish` 时第二轮既不重复回调也不重新开播。**两例都用修复前的代码验过确实失败** |
| 影响面 | 仅开发/预览环境（生产构建不双跑 effect），但 dev 白屏会挡住所有本地联调 |

## 13. 手写段下沉到 web 层（2026-10-18，用户第二次反馈「应该有一个写字的动画」）

### 13.1 问题：写字只在 Electron 的 splash 里

手写段此前**只存在于 `splash.html`**（splash 窗口自播）。而 splash 窗口只有桌面壳会创建：

| 环境 | 有没有 splash 窗口 | 能不能看到写字 |
|---|---|---|
| 打包的桌面端 | 有 | 能（实测 10 笔在 ~1.2s 内写完） |
| `vite dev` / 浏览器 / 预览面板 | **没有** | **不能**——只剩 BootWave 的白遮罩 + 波纹 |

于是「在预览/浏览器里看」的人会觉得写字动画丢了。用户反馈的正是这个（此前一度以为是桌面端也丢了，实测打包程序仍在逐笔写字：`drawn` 从 0 → 5 → 8 → 10，`prefers-reduced-motion=false`）。

### 13.2 做法：web 层补一段同样的手写，但桌面端不重复播

- 新增 `packages/web/src/components/WordmarkWrite.tsx`：复用 `wordmarkGlyphs.ts` 的字形数据，逐笔 `stroke-dashoffset` 描出（速度按笔画长度均分、字母间 55ms 抬手，与 splash 同一套算法），写完停 150ms → 200ms 淡出 → 回调。
- `BootWave` 新增 `writeFirst?: boolean`：为 true 时先把手写段铺在白遮罩上播完，再开声波段。
- `App.tsx` 用 `HAS_NATIVE_SPLASH = typeof window.heming?.__onBootReady === "function"` 判定：
  - 桌面端（有 preload 信号通道）→ `writeFirst=false`，手写由 splash 负责，**不重复播**；
  - 浏览器/预览 → `writeFirst=true`，web 层自己写。
- 时序：写字 `WRITE_DRAW_MS 1250 + HOLD 150 + FADE 200`，之后接声波 `WAVE_MS 1300`，浏览器端总时长 ≈ 2.9s。
- 尊重 `prefers-reduced-motion`：直接跳过整段（与既有行为一致）。

### 13.3 验证

| 项 | 结果 |
|---|---|
| 单测 | `WordmarkWrite` 10 例（时长分配、抬手、进度曲线、逐笔描出、淡出与 onDone 只一次）+ `BootWave` 3 例（writeFirst 先写后波、减弱动态直通、桌面端不重复写） |
| 门禁 | web **49 文件 / 721 用例全绿**（原 708 + 13），`typecheck` 通过 |
| 浏览器实测（CDP 逐帧） | t=443ms 起写、t=1245ms 已 8 笔、t=1647ms 10 笔写完 → 声波 `--reveal` 0% → 92% → 卸载；登录页左卡右字样 |
| 桌面端实测 | splash 窗口仍逐笔写字；主窗口 `.wordmark-write` **不存在**（未重复播） |

### 13.4 已知取舍

- 同一套算法在 `splash.html` 与 `WordmarkWrite.tsx` 各有一份（前者要求自包含）。计时常量（`WRITE_DRAW_MS` / `WRITE_MS`）目前靠注释对齐，**没有跨包断言**，与 `WAVE_MS` 是同一类技术债。
- 浏览器端手写段结束到声波段之间没有「粒子聚拢」段（那是 splash 独有的），节奏比桌面端略短。

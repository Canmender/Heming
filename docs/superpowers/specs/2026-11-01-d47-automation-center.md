# d.47 · 信息中枢操作面与自动化中心

- 日期：2026-11-01
- 相关版本：d.46.1.11.0（基线）、本 spec = d.47.1.11.0（特性位 +1）
- 涉及包：`packages/web`（自动化数据层、调度器、执行器、自动化页、信息中枢页入口、导航）
- 前置：d.45 已把 InfoHub 源码并入 `packages/infohub` 并以 stdio 边车接入；d.46 已把归档做成工具、首页卡与全局检索

## 0. 问题

信息中枢已经有页面、工具、首页卡和检索，但**所有动作仍要人守着点**：同步、重扫日程都得当场操作。用户需要的是「把它当成和鸣里的一个功能部件」——页面能操作，动作能按计划自动发生，而不是又一个需要手动打开的外部程序。

## 1. 目标

1. 信息中枢页补上「定时」入口：当前同步选项、议程重扫都可以一键变成自动化任务。
2. 新增独立的「自动化」页：创建、启停、立即运行、编辑、删除本机自动化任务。
3. 自动化只做**本机 InfoHub 动作**，不和服务器、云端、外部推送发生关系。
4. 调度、执行、失败与跳过都在页面上可见，不静默。

## 2. 非目标

- 不做服务端调度：自动化任务只存本机，和鸣没有运行就不会发生。
- 不自动拉起 Python 边车：d.45/d.46 的红线不变，未连接时任务记「已跳过」。
- 不做任意脚本 / shell / 提示词任务：动作是白名单的。
- 不自动推送企业微信 / 邮件，不自动导出到 Obsidian（导出知识库必须由任务显式勾选，且桌面端会写配置目录）。
- 不做错过补跑：应用关闭期间错过的时刻不执行，页面明确说明。

## 3. 任务模型

```ts
type AutomationKind = "infohub.sync" | "infohub.agenda";

type AutomationSchedule =
  | { type: "daily"; time: "HH:MM"; weekdays: number[] } // 0=周日 … 6=周六
  | { type: "interval"; minutes: number };                // 5–1440

interface AutomationTask {
  id: string;
  name: string;
  kind: AutomationKind;
  enabled: boolean;
  schedule: AutomationSchedule;
  sync: { sources: ("qq" | "wechat")[]; full: boolean; archive: boolean };
  createdAt: number;
  updatedAt: number;
  nextRunAt: number;
  lastRunAt?: number;
  lastStatus?: "ok" | "error" | "skipped";
  lastDetail?: string;
  runCount: number;
}
```

- 存 `localStorage["heming.automations.v1"]`，最多 20 条，UTF-8 上限 256KB。
- 读取时逐条校验；损坏/不认识的条目丢弃，不让坏数据卡住页面。
- 不存任何密钥、路径或聊天内容；同步目标是本机归档目录（由信息中枢页保存）。
- `archive`（导出知识库）默认关闭；打开时编辑表单明确提示会写入 InfoHub 配置的 Obsidian 目录。

## 4. 调度语义

- `daily`：本地时区，严格晚于当前时刻的下一个匹配星期与时间。
- `interval`：从创建/编辑/上次结束时刻起算 `minutes` 分钟。
- 调度器挂在已登录的主界面，15 秒轮询一次；同一时刻只执行一条任务。
- **只在和鸣运行期间执行**。应用启动时，若任务的 `nextRunAt` 早于本次调度器启动时间，直接顺延到下一周期，不补跑、不记失败。
- 执行前校验：桌面桥存在 + InfoHub 已连接（`running` + `booted`）。二者任一不满足 → 记 `skipped`，详情说明原因，并顺延下一周期；不 spawn、不重试。
- 执行结果（成功/失败/跳过、简短详情、`runCount`）落盘；详情压成一行、最多 160 字。
- 手动「立即运行」走同一条执行器；同样要求已连接，并会顺延下次计划。

## 5. 动作白名单

| 动作 | 参数 | 副作用 |
| --- | --- | --- |
| `infohub.sync` | `sources`（qq/wechat）、`full`、`archive` | 写本机归档库；`archive=true` 时按配置导出知识库 |
| `infohub.agenda` | 固定 `days=14, overdue=30, rebuild=true` | 仅重扫本机归档的日程表，不联网 |

- `sync` 内部可能调用已配置的 LLM 做议程识别；InfoHub 的 `allow_remote` 仍是总闸（d.45 既有行为）。
- 不暴露 `push`、`daily notice`、`digest`、`wecom bot`：这些会发消息到外部，必须由人当场操作。

## 6. 页面与导航

### 6.1 自动化页

- 页面标题「自动化」，副标题说明「只在本机执行，和鸣运行期间到点触发；错过的时刻不补跑」。
- 顶部：任务数 / 启用数 / 下一个执行时间；浏览器端显示「仅桌面端执行」，桌面端未连接显示「信息中枢未连接」+ 跳转入口。
- 列表项：名称、动作、频率、下次/上次执行、最近结果；启停、立即运行、编辑、删除（删除需确认）。
- 编辑弹窗：名称、动作、同步选项、频率（每天定时 / 间隔）、星期、时间/分钟；保存前校验。
- 空态直接引导「新建自动化」。
- 新建时可从信息中枢页带入动作与同步选项（一次性意图，消费即清）。

### 6.2 信息中枢页

- 页头增加「定时」按钮：以当前同步来源/全量/导出选项新建同步任务。
- 同步面板的「开始同步」旁增加「保存为定时任务」。
- 日程页签的「重扫议程」旁增加「定时重扫」。
- 点击后切到自动化页并打开预填表单，不复制任务状态。

### 6.3 导航

- `Page` 增加 `"automations"`，默认顺序紧随 `"infohub"`。
- Alt+1–9/0 已排满，自动化不占数字快捷键，只从导航点开（与信息中枢同一口径）。

## 7. 红线

- 自动化数据不上云、不进消息库、不进服务器数据库。
- 不因自动化失败而阻塞聊天 / 任务主流程。
- 不允许任务携带任意命令、URL、可用凭据；动作与参数都是枚举/布尔。
- 未连接 InfoHub 时不自动启动子进程。
- 执行日志只落本机，且不记录聊天正文。

## 8. 测试

- 模型：时间解析、每日/间隔的下次时间、跨星期、校验、损坏条目淘汰。
- store：增删改启停、上限、落盘、并发保护、启动顺延、结果记录。
- 执行器：浏览器/未连接跳过；sync 参数与结果；agenda 重扫；错误归一。
- 调度器：到点执行一次、浏览器不消耗计划、错过不补跑。
- 页面：空态、创建、启停、立即运行、意图预填、删除确认。
- 导航与信息中枢入口：默认顺序、按钮投递意图。
- 门禁：`pnpm -r build && pnpm -r --workspace-concurrency=1 test`。

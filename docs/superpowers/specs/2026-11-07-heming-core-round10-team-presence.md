## 2. 在线口径：为什么在客户端补连接，而不是改服务端

服务端的「在线」= 当前进程里有已鉴权 WS 连接（`presence.ts`），这是清晰且可测试的语义。
矛盾来自**客户端只在会话页建连**——用户人在团队页/首页时，服务端当然认为他离线。

方案对比：

| 方案 | 结论 |
|---|---|
| 把「在线」改成「最近活跃 N 分钟内」 | 需要新的心跳/落库与清理，且把两个概念混成一个，团队页与名册都会失准 |
| 只在团队页建连 | 治不了首页/其它页；且多页各建一条更容易重复 |
| **App 壳登录后维持一条只用于在场的连接**（采用） | 语义不变（有连接=在线），覆盖所有页面；页面自己的连接照旧 |

实现：`lib/appPresence.ts` 的 `useAppPresence(enabled=true)`，仅当 `status==="authed"` 时 `connectWs`，
`onEvent` 忽略所有业务事件，卸载/登出 `close()`；断线重连沿用 `connectWs` 既有退避。
App 五套测试显式 mock 该 hook（避免测试真的连 WS）；hook 自带 3 例单测。

## 3. 关共享 ≠ 撤回

- 共享条说明加后缀：「关闭只停止上报，不撤回已上传的内容」。
- `turnOffShare(kind)`：关闭任务/日程/用量任一类时给 `role="status"` 一次性说明
  「已停止上报<类>；之前上传的内容仍留在团队里，可用『清除共享记录』撤回。」6 秒后消失。
- 动向空态分两种：`shareCount > 0` → 「你已经开启共享，但还没有可显示的摘要」；
  否则保留原「成员勾选后出现」的引导。
- 团队日程说明修正为实际行为（标题 + 到期档位，不含正文/证据/发送人）。

## 4. 成员详情与单用户说明

- 头行补：`近 7 天动向 N 条`（本页已加载的动向计数）+ `用量 X`（排行里的聚合；未共享/无记录分开说）。
- 只有 1 名成员时，共享条下说明账号来源（管理员在服务端创建），避免新用户以为团队功能坏了。
  明确不做「邀请」按钮：服务端公开注册默认关闭是既有边界，做了也发不出账号。

## 2. 本轮修复

### 2.1 登录页三条（P1，实测复现）

1. **错误文案透传服务端英文**：实测错密码后卡片显示 `invalid credentials`。
   → `store/auth.ts` 新增 `loginErrorMessage()`，按 401/429/408/5xx/网络失败翻译；页面只展示中文。
2. **错误残留**：失败后改密码，红字与 `aria-invalid` 都还在，读起来像在怪用户改得不对。
   → 输入框 onChange 调 store 新增的 `clearError()`；只在确实失败时复位（已登录态不受打扰）。
3. **没有账号来源说明**：登录页无注册入口、无提示。→ 补「账号由团队管理员开通。」，
   打开即聚焦用户名（`autoFocus`），密码框加 CapsLock 提示。

### 2.3 假状态换真数据（P1/P2）

- **首页「本地工作目录」永远「未绑定」**：读 `fileRootsStore.writeRoots()`，0→未绑定、≥1→已绑定 N 个，
  `window.focus` 时刷新（首页非常驻）。

  浏览器里显示真实版本，更新日志/关于两处一致。用例断言与 `__APP_VERSION__` 比较（bump 不失效）。

### 2.4 命令面板焦点环（P2，实测复现）

输入框贴面板顶边 + `overflow-hidden`，`GlobalFocusRing` 的未分层 `:focus-visible` 环被裁成一条黑线
（旧截图甚至没有焦点提示）。→ 输入框内联 `outline: none` 关掉自身环，焦点环画在面板容器上
（`onFocus`/`onBlur` 跟踪）；新增用例钉住「输入框无自身环 + 面板获得/失去 outline-ink」。

# 第二轮（d.68.2.28.0）：接上假网关，把对话真正跑通

## 6. 方法：本机假网关 + 真实 UI

前两轮只能测到「页面与空态」——**没有模型连接就永远走不到对话真实路径**。这一轮在本机起了一个
OpenAI 兼容的假网关（`.tmp/d69/mock-gw.mjs`，不入库，端口 8791），按 `model` 名分派行为：

| 模型名 | 行为 | 用来验证 |
|---|---|---|
| `mock-fast` | 6 字一段的快流 + usage | 流式渲染、消息落库、用量累计 |
| `mock-slow` | 30 段、每段 200ms | 「停止生成」按钮、`已中断，可继续生成` |
| `mock-chart` | 先回 `chart_render` 工具调用；收到 tool 结果后把围栏块原样贴回正文 | 工具调用链、图表卡片渲染 |
| `mock-429` | 429 + JSON 错误体 | 失败文案是否说人话 |
| `mock-think` / `mock-nousage` | 思考增量 / 不带 usage | 思考过程展示、未上报与 0 的区分（本轮未跑完） |

连接走真实 UI 建（设置 → 模型 → 新建连接 → Base URL 填 `http://127.0.0.1:8791/v1`），
绑定写 `heming.agentLlm`；凡是要换模型，都改 **`{profiles:[...]}` 形状**的 `heming.llmConfigs` 再刷新
（踩过一次：写成裸数组会被 `loadProfiles()` 读成空表，界面表现为「未绑定连接」——不是产品 bug）。

## 7. 第二轮发现与修复

1. **P1 · 429 把供应商 JSON 原文甩到气泡里**：`provider_error: HTTP 429 {"error":{...}}` 直接上屏。
   → 新增 `humanizeProviderError()`，按状态码翻译 + 原文放进气泡 `title`；桌宠对话复用同一条。
   同时修掉 `usePetChat` 里 `/^provider_error:\\s*/` 从没生效的转义写法。
2. **P2 · 「中断」与「Esc 停止生成」两个词**：按钮改「停止生成」，与提示、`Esc` 语义一致。
3. **P2 · 生成中途关闭后历史显示「无法解密（密钥缺失）」**：设备钥匙通常还在，缺的是链窗口钥匙；
   改为「本机解不开这条消息（可能来自其他设备，或生成时被中断）」，`title` 补原因。
4. **图表工具链已验证可用**：`chart_render`（图型 id 必须是 `F1`/`L1` 这类，不是 `bar`）返回围栏块后，
   消息里渲染出 `figure` + 图表 + 「导出 HTML / 打开」。第一版假网关传了 `type:"bar"`，
   工具如实回「未知图型 BAR」——**工具侧的诚实报错反而是对的**，不是缺陷。

## 8. 第二轮未覆盖 / 新候选

1. **HITL 确认弹窗没有真实触发**：浏览器端内置工具全是只读风险（chart/tone/wiki-read），
   要造写风险工具需要桌面端 `file_patch` 或自建 MCP 服务；下一轮优先补这一块（桌面端手测或本机 MCP）。
2. **失败气泡不落历史**：429 的失败行只存在于流式状态，刷新后聊天里只剩用户那条消息，
   看起来像「发出去没人理」。持久化错误记录需要定数据模型（存哪、什么时候清），本轮只修文案。
3. **历史消息里没有工具调用轨迹**：工具轨迹只在流式气泡里显示，回合结束后消失（任务区/回合日志另有记录）。
   要不要在消息里留一条可折叠的「用过哪些工具」，需要先定隐私与存储边界。
4. **假网关的「思考过程」「未上报用量」两条分支没跑完**，下一轮补。

# 第三轮（d.68.2.29.0）：把人工确认（HITL）真的点一遍

## 9. 方法：假 MCP 服务 + 真实确认弹窗

前几轮没能覆盖 HITL，因为浏览器端内置工具全是只读风险。这一轮起了一台假 MCP 服务
（`.tmp/d69/mcp-mock.mjs`，Streamable HTTP，端口 8792，`save_note` 无 annotations → 按名字兜底判 `write`），
用真实 UI 走完：`插件区 → MCP 服务 → 添加 MCP 服务 → 保存服务 → 连接 → 启用工具 save_note`；
假网关 `mock-mcp` 返回 `mocksrv__save_note` 工具调用；`guarded` 档位下弹出确认框。

## 10. 第三轮发现与修复

1. **P1 · 点了「允许」却得到「拒绝原因：未勾选」**：弹窗的安全设计是「写操作默认不勾、允许只放行勾选项」，
   但界面没有一句话说明要勾选。实测点「仅本次允许」而未勾选，工具不执行且模型收到拒绝文案——
   用户视角就是「我点了允许，它说我没允许」。
   → 在调用列表与按钮之间加提示行「先勾选要放行的调用，再点下方按钮；没勾的会按拒绝处理。」，
   **不改变勾选语义与默认动作**（安全边界不动）；新增 2 条用例。
2. **P2 · 工具名像代码**：`mocksrv__save_note` 原样展示 → 改为 `mocksrv · save_note`；用例断言不出现双下划线。
3. **P2 · MCP 连不上只显示 `Failed to fetch`**：浏览器跨域被拦时服务行只有英文报错。
   → `httpClient.ts` 把 fetch 的 `TypeError` 翻成「连不上这个 MCP 地址：请确认服务已启动、地址填写正确，且服务允许跨域访问（CORS）。」；
   新增 1 条用例（抓 `TypeError`、断言不含英文原文）。
4. **完整链路验证**：勾选 + 仅本次允许 → 假 MCP 的 `save_note` 真的被调用（返回「已保存便签（第 1 次调用）」）
   → 结果回灌模型 → 回复里出现该结果；0 console error。

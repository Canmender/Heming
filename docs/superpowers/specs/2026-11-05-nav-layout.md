# 导航重排与页面布局收口（d.72.2.33.0）

日期：2026-11-05
范围：`packages/web`（导航轨、设置区、信息中枢、命令面板页面目录）
版本：`d.72.2.33.0`

## 1. 背景：真实浏览器逐页截图发现的问题

用 headless Edge + CDP（脚本只在 `.tmp/d73/`，不入库）在 **1600×1000 / 1280×800 / 1024×768 / 900×700**
四档宽度逐页截图，并检查横向溢出、被裁切元素。结论：

| 页面 | 发现 | 判断 |
| --- | --- | --- |
| 导航轨 | 9 个图标等距平铺；智能体排在团队后；模块页夹在中间，无分组线索 | 要重排 + 分组 |
| 设置区 | 正文 `max-w-[720px]` 贴左，1600 宽屏右侧空半屏；标签/搜索横贯整页 | 要收口居中 |
| 信息中枢（浏览器） | 说明卡贴顶，`flex-1 items-center` 没生效 | 真空态居中 |
| 主页 / 团队 / 智能体 / 幕僚 / 自动化 / 插件区 / 记忆区 | 1024 / 900 下无横向溢出、无被裁元素 | 本轮不动 |

页面宽度档位本身（full / wide / readable / narrow）与页头（`PageShell`）在 d.62 已统一，
本轮不重做，只修「具体页面内明显不协调」的三处。

## 2. 导航分组重排

### 2.1 顺序

```
工作台：主页 → 智能体 → 团队
智能模块：幕僚 → 信息中枢 → 自动化
资料与能力：插件区 → 记忆区
系统：设置区
```

- 改 `store/ui.ts` 的 `DEFAULT_NAV_ORDER`；
- `lib/palette/pages.ts` 的命令面板页面目录同步该顺序（集合一致性由既有用例钉住）。

### 2.2 视觉分隔

新增 `lib/navGroups.ts`：

- `NavGroupId = work | modules | resources | system`；`NAV_GROUP_OF` 覆盖 9 个宿主页；
- `needsGroupDivider(prev, next)`：只在「有前后两项且分组不同」时为真。

Rail 渲染时对**过滤后的可见相邻项**调用它（模块停用会让相邻项跳变），因此：

- 3 个模块全停用时，只剩 工作台 → 资料 → 系统 两条线，不会出现空组；
- 每组第一条之前没有线，组间用 `w-6 h-px` 细线，组内仍 8px 间距。

图标轨宽 54px 放不下文字组标题，所以分组只用细线表达；组名在设置区「导航顺序」列表里逐行标注。

### 2.3 老用户迁移

本次重排之前没动过顺序的用户，`heming.navOrder.v1` 里是旧默认列表。处理：

- `LEGACY_DEFAULT_NAV_ORDER` 记录旧默认；`readStoredNavOrder` 读到与旧默认**完全一致**时返回新默认；
- 启动时 `persistMigratedNavOrder` 把归一后的顺序写回（避免每次启动重新迁移）；
- 只要用户动过顺序（哪怕只排了两项），归一后与旧默认不相等 → 原样保留，不覆盖。

快捷键不受影响：`Alt+1/2/5/6/8/0` 仍按页面固定绑定，顺序迁移不换键位。

## 3. 设置区内容列居中

- 标签栏、搜索框：`headerExtra` 内层加 `mx-auto w-full max-w-[760px]`；
- 正文：`w-full max-w-[720px]` → `mx-auto w-full max-w-[760px]`；
- 导航顺序列表新增分组标签（`ui-micro`）与一句「细线跟着组变化走」的说明。

宽屏（1600）正文列左右各留 ~327px，窄窗（<1200）仍用 16px 页面内边距。

## 4. 信息中枢空态居中

`PageShell` 默认 `scroll={true}` 时，children 位于滚动容器内；空态分支的
`flex min-h-0 flex-1 items-center justify-center` 因父级不是 flex 而撑不开高度，卡片贴顶。
改为 `scroll={false}` + `flex-1 overflow-y-auto`，让 460px 说明卡在页头以下垂直居中。

## 5. 测试与验证

单测：

- `lib/navGroups.test.ts`（3 例）：分组覆盖全页、默认顺序同组连续、跨组才画线；
- `NavRail.test.tsx`（新增 2 例）：默认顺序、3 条分隔线；停用幕僚 + 信息中枢后 2 条；
- `store/ui.test.ts`：默认顺序、`readStoredNavOrder` 补齐顺序、旧默认迁移 + 自定义保留；
- `SettingsPage.test.tsx`：上移后顺序、内容列 760 + `mx-auto`。

真实浏览器（`.tmp/d73/verify.mjs`）：

- 种入旧默认顺序 → 刷新后导航顺序为新版，DOM 内 3 条 `h-px` 分组线；
- 设置区内容列 `left=327, right=1087, width=760`（viewport 1600），导航顺序 9 行均带分组标签；
- 信息中枢说明卡中心 542，内容区中心约 543；
- 1024×768：无横向溢出，导航轨底部未越过视口；控制台 0 错误。

## 6. 明确不做 / 后续

1. **分组自定义**：分组是视觉分隔，不提供「改组 / 折叠组」。否则要同时解释「顺序 + 归属」两套规则，
   并给旧 `navOrder` 设计第二套迁移；当前只保留用户可调顺序。
2. **导航加文字标签**：54px 图标轨的既有取舍（d.67 A 方案），本轮不推翻。
3. **页面内容宽度大改**：各页档位已由 d.62 的 `PageShell` 统一，本轮只修三处不协调；
   若后续要继续，可评估：主页「Token 用量」空态的垂直空白、幕僚/自动化空态是否垂直居中、
   记忆区超宽卡片的行宽上限。
4. **横向平板/移动端布局**：本产品是桌面优先；本轮只验证到 900px 宽无溢出。

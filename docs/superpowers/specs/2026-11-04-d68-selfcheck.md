## 2. 发现与修复

### 2.1 导航 auto 模式：鼠标点完导航项后浮层永远不收回（P1，实测复现）

- **现象**：auto 模式下悬停左缘展开浮层 → 鼠标点「记忆区」→ 页面切换、鼠标移到内容区，
  等 1 秒后浮层仍开着（`aria-hidden=false`、`focusInside=true`）。
- **根因**：`scheduleHide` 只判断「焦点是否在导航内」。鼠标点击按钮后按钮保留 focus，
  于是这份**鼠标焦点**被当成键盘焦点，浮层被永久钉住——自动隐藏等于失效。
- **修法**：
  1. 区分键盘/鼠标交互：`onKeyDownCapture` 置 `keyboardFocusRef=true`、`onPointerDownCapture` 置 `false`；
     `scheduleHide` 只有在「焦点在导航内 **且**（键盘交互或 `:focus-visible`）」时才保留；
  2. auto 模式下**鼠标点击导航项后立即收起浮层**（键盘 Enter 激活则保留，焦点连续）；
  3. 收起前若焦点留在导航里则 `blur()`，避免焦点停在 inert 元素上。
- **验证**：浏览器实测同场景 → `aria-hidden=true`、`focusInside=false`；新增 3 条单测
  （鼠标焦点不钉住／键盘焦点保留／点击项立即收起）。

### 2.2 暗色下按钮/输入框是「白底近白字」（P0，实测复现）

- **现象**：暗色设置页里「恢复默认」「恢复默认外观」按钮、搜索框、自定义颜色输入框全是白底，
  文字几乎看不见；而亮色正常。
- **根因**：d.63 的组件基元把亮色写进了 `@layer components`
  （`.ui-btn-ghost { @apply bg-white }`、`.ui-input { @apply bg-white }`、`.ui-chip { @apply bg-[#fafafa] }`），
  而 d.67 的暗色兼容层**只按 JSX 里的类名覆盖**（`[data-theme="dark"] .bg-white`），
  匹配不到 `.ui-btn-ghost` 这种组件类；`text-ink` 是浅色变量 → 亮底 + 浅字。
  （与上一轮 `.ui-card` 是同一类问题，但影响面更大。）
- **修法**：`.ui-input` / `.ui-btn-ghost` / `.ui-chip` 背景改 `var(--surface)` / `var(--subtle)`；
  `.ui-input:disabled`、`.ui-btn-ghost:hover`、`.ui-list-row:hover`、`.ui-table tr:hover td` 同步走变量。
- **验证**：浏览器计算样式：ghost `bg=rgb(22,23,26)`、input `bg=rgb(22,23,26)`、placeholder `#8b9199`；
  暗色截图可读。新增源码守卫 `lib/themePrimitives.test.ts`（4 条基元 + 暗色 `.ui-card` 覆盖）。

### 2.3 暗色状态：近 30 日用量热力图是 30 个白方块（P1，实测复现）

- **根因**：`TokenHeatmap` 的 5 档颜色是组件内联 hex（`#f1f4f7…`），不参与主题变量，也不受类名兼容层影响。
- **修法**：`:root` / `[data-theme="dark"]` 各一套 `--heat-0…--heat-4`，组件改用 `var(--heat-N)`；
  今日格子描边从 `ring-[#1a1a1a]/20` 改为 `var(--line-strong)`。
- **验证**：暗色截图方块为深灰/蓝阶；守卫断言两套变量存在、组件不含亮色 hex。

### 2.4 暗色状态：开关轨道浅灰 + 滑块深色（观感倒置，审计发现）

- **根因**：4 处开关（ContextSettingsCard / MemoryPage / SkillsPage / plugins/shared）用
  `bg-[#d8d8d8]` + `bg-white`；暗色下 `bg-white` 被兼容层映射成深色底面，轨道却是浅灰。
- **修法**：新增 `--switch-off` / `--switch-knob`（亮/暗各一套）；滑块按状态取色
  （开启 = `--heming-on-accent`，关闭 = `--switch-knob`）。
- **验证**：暗色截图轨道深灰、滑块浅色；守卫断言四个组件不再使用 `#d8d8d8`。

### 2.5 暗色状态：大量 `hover:bg-[#f3f3f3]/[#f0f0f0]/[#f5f5f5]` 悬停闪白（审计发现）

- **根因**：d.67 兼容层只覆盖了 3 个 hover 类，而组件里实际有 7+ 种浅灰 hover。
- **修法**：按与静态底色相同的层级分组补齐 hover 映射（subtle/subtle-2/3/4、danger-soft、警告色），
  并补 `bg-[#ebebeb]/[#e9e9e9]/[#ececec]/[#e8e8e8]` 等静态中性色。
- **验证**：暗色逐页扫描（9 页 × 6 种控件）无「亮底亮字」；守卫断言常用 hover 映射存在。

### 2.6 桌宠右键菜单贴右边被窗口裁掉（P2，实测复现）

- **现象**：300×420 窗口里在 x=144 右键，菜单右边缘到 310px，超出窗口 10px，最右一条被裁。
- **根因**：`MENU_WIDTH=156` / `MENU_HEIGHT=248` 是旧估算，实际菜单宽 166（最小宽 + padding + border），
  暗色/浏览器下更宽；且没有挂载后按真实 rect 校正。
- **修法**：估算值改为 176/252；新增 `useLayoutEffect` 在绘制前按真实 `getBoundingClientRect()`
  再夹一次（只在右/下溢出且坐标真的变化时 `setMenu`）。
- **验证**：浏览器实测菜单 `right=296 < 300`；`PetWindow.menu.test` 原有用例保持绿。

### 2.7 桌宠浏览器降级：菜单一排死按钮 +「鼠标穿透（读取中）」（P2，实测复现）

- **现象**：浏览器直接打开 `pet.html`（无 Electron 桥），菜单显示放大/缩小/设置/隐藏/鼠标穿透（读取中）——
  全部点了没反应；「读取中」永远不结束。
- **根因**：菜单项只探测了 `resetPosition`，其余桥能力没探测；穿透项状态依赖 `bridge.state()`。
- **修法**：能力探测统一为 `{hasBridge, canScale, canResetPosition, canToggleClickThrough}`，
  按能力逐项渲染；无桥时只保留纯渲染层的「说点什么」。旧 preload 缺单项时同样不渲染死按钮。
- **验证**：浏览器实测菜单项 `["说点什么"]`；新增单测「无桥只保留说点什么、不出现读取中」。

### 2.8 插件区统计滞后：在「技能」Tab 新建技能后统计不涨（P2，实测复现）

- **现象**：技能池 7→8（新建成功、已分配），顶部统计卡仍显示 7。
- **根因**：`PluginsPage` 的统计来自 `describeCapabilities(...)`，只在宿主 `tick` 变化时重算；
  内嵌的 `SkillsView` 有自己的 tick，变更没有通知宿主。
- **修法**：`SkillsView` 新增可选 `onChanged`，其内部 `bump()` 同时通知宿主；插件区传 `onChanged={bump}`。
  独立页/旧用例不传，行为不变。
- **验证**：浏览器实测统计 8→9（delta 1）；新增 2 条用例（SkillsView onChanged、PluginsPage 统计 +1）。

### 2.9 顺带：导航浮签的快捷键键帽在暗色下对比度低（未单独截图复验）

- `Tip` 的 `<kbd>` 原用 `border-[#666] + text-[#ccc]`；暗色下浮签是浅色强调底，键帽几乎看不清。
  改为 `border-current` + `opacity-70`，跟随 `--heming-on-accent`。

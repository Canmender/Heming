# d.102 实时链路优化：筛选、统计与动效克制

- 日期：2026-11-08
- 版本：`d.102.2.42.0`（特性 +1）
- 承接 d.101 的「实时链路」节点视图。

## 1. 改了什么

用户反馈节点图直观，继续打磨可用性与信息密度：

1. **顶部统计**：请求总数 / 进行中 / 成功 / 失败，以及已结束请求的平均耗时与 token 合计；
2. **状态筛选**：全部 / 进行中 / 成功 / 失败 一键切换；有筛选时出现「清除筛选」；
3. **节点即筛选**：点击左侧客户端节点或右侧账号节点，只看经过它的请求；再点取消；
   节点上直接标出经过的请求数（「N 个请求 · 点击筛选」）；
4. **最后读取时间**：明确页面数据的时点（暂停时也能判断新旧）；
5. **动效克制**：尊重系统「减少动态效果」（`prefers-reduced-motion`）——
   开启时不播放沿线移动的圆点，只保留静态连线；
6. **筛选后的空状态**：区分「还没有请求」与「当前筛选下没有请求」，并给清除筛选的指引。

## 2. 代码

- `components/ModelTraceView.tsx`：新增 `filter` / `nodeFilter` / `reducedMotion` 状态；
  统计用 `useMemo` 从全量 graph 计算（节点筛选不改变统计，避免「筛完数字变了」的误解）；
- 图只渲染可见请求的连线；列表同步过滤；
- 纯函数与数据层（`lib/magpieTrace.ts`）未改，行为由原有用例覆盖。

## 3. 验证

- `ModelTraceView` 5 例：原有 4 例（节点/详情/空状态/错误）+ 新增筛选用例
  （切「进行中」只剩 live 连线，清除后恢复）；
- `magpieTrace` 11 例保持全绿；web typecheck 零错；全量门禁见提交记录。

## 4. 边界

- 统计口径是「当前快照内的请求」，不是历史累计（历史与费用在「用量」分区）；
- 节点筛选与状态筛选可叠加；「清除筛选」一次清掉两者；
- 关闭动效只影响装饰性圆点，不影响数据与交互。

# d.77 插件优化轮：列表可查找、安装可定位、权限上限真的生效

- 日期：2026-11-07
- 版本：`d.77.2.41.0`（特性 +1）
- 范围：只动插件子系统（`lib/plugins`、`lib/mcp` 的注入点、能力提供者、插件区 UI），不碰服务端协议与云端数据
- 分支：`feat/d77-heming-core`

## 0. 为什么做这一轮

前几轮把插件从「技能压缩包」做到了声明式能力包（技能 / MCP / 命令 / 工具束 / 权限 / 签名），
但存在两类问题：

1. **用户侧**：插件只能一条条往下翻——装到几十个后没有搜索、没有状态筛选；从「工具 / MCP」Tab
   装完插件还停在原 Tab，看起来像没装上；安装弹窗打开后焦点落在关闭按钮上。
2. **承诺侧**：`permissions.tools`（工具风险上限）只在**能力目录**里把超限工具标成「未注入」，
   而真正的注入路径 `buildToolBridge()` 只按「服务启用 + 工具开关」过滤——模型手上其实拿到了
   那个写工具。也就是说工具页那句「插件声明 read，未注入」是**假的**。

本轮把两边一起收口：能找得到、装完看得见、声明即约束。

## 1. 插件列表：搜索 + 状态筛选 + 安装定位

**搜索**（`PluginsPage` 顶部、仅插件 Tab）

- 新增 `aria-label="搜索插件"` 输入框，按 **名称 / id / 作者 / 描述 / 技能名 / 服务名 / 命令标题**
  命中（小写、多词 AND，与技能区搜索同口径）。只搜插件名不够——用户记得的常是「那个带天气服务的包」。
- 实时命中数：`匹配 N / 共 M 个`；清空后回到「共 M 个插件」。

**状态筛选**

- 「全部 / 已启用 / 已停用」三档 `aria-pressed` 按钮；「部分停用」仍归入已启用（主开关才是总闸）。

**空态分两种**

- 一个插件都没装 ⇒ 原来的「还没有安装插件」+ 安装 CTA；
- 有插件但筛没了 ⇒ 新增「没有匹配的插件」+「清除筛选」。

**安装后定位**

- `install()` 成功后切回插件 Tab，并用命令面板同一套高亮机制滚动定位新卡（2 秒 ring 高亮）。
  从工具 / 技能 / MCP Tab 安装也不会「看起来没生效」。

**详情里的零贡献类别**

- 本包未声明的类别（服务 0 / 命令 0 / 工具束 0）开关**禁用**并写明「本包未声明」；
  可点却点不出效果的开关比灰掉更容易被当成故障。

**其它小收口**

- 安装弹窗打开即落焦到清单输入框（主操作是粘贴/选文件）。
- 统计卡不再显示「1 + 0」这种读不出构成的写法：总数 + `系统 1 · 已装 N`。
- Tab 栏右侧说明只在「插件 / 模块」两个 Tab 出现，不再挂在「工具 / MCP」上。

纯函数落在 `components/plugins/viewModel.ts`：`pluginMatchesQuery` / `filterPlugins`，
页面只做展示，测试直接断言口径。

## 2. 权限「声明即约束」：上限落到注入点（缺陷修复）

**问题**

- `riskAllowed()`（`lib/plugins/permissions.ts`）全仓库只有测试引用；
- `catalog.ts` 只把超限工具推进 `blocked` 供 UI 展示；
- 真正的注入点 `buildToolBridge()`（`lib/mcp/runtime.ts`）只看 `enabledTools()`
  （服务启用 + 工具开关）。

于是「声明 read 的插件不能把写工具交给模型」这条承诺没有执行点：
工具页说「未注入」，模型上下文里却有它。HITL 仍会逐次确认（红线没破），但这是**声明失效**。

**修法**

- 新增 `lib/plugins/toolCeiling.ts`：`makePluginToolFilter(plugins)` 返回逐工具判定。
  - 归属按 `pluginIdFromServerId()` 反解，非插件服务不受上限约束；
  - 风险与 HITL 同口径（`riskOfName`，`danger` 归 write）；
  - 插件记录缺失时按 `none` 处理——「找不到声明」不能变成放行，与目录口径一致。
- `buildToolBridge(registry, { toolAllowed })` 新增可选过滤参数（缺省不过滤，零行为变化）。
- `mcpProvider.build()` 传入插件过滤器，**目录与执行从此同源**。

## 3. 清单/地址校验的两处不一致

1. **大写协议名导致确定性的半安装**：`manifest` 用 `new URL()` 校验，`HTTPS://…` 合法；
   但 `McpRegistry.add()` 用区分大小写的 `/^https?:\/\//`，于是在**技能已物化之后**抛错、
   插件记录未写——留下「技能在池里、插件列表没有」的半安装。改为大小写不敏感。
2. **默认端口写法永远匹配不上**：清单允许 `api.acme.com:443`，但两侧比对前
   `hostOfUrl()` 会把 443 规范化掉，于是判定「未声明主机」，提示要补的正是作者刚写的值；
   `localhost:80` 更直接被判成格式非法。新增 `normalizeNetworkHost()`（小写 + 去 80/443 默认端口），
   解析期与运行时报告共用；展示仍按声明原文。

## 5. 明确未做（留给后续轮次，附实测证据）

以下按审阅时确认的严重度排列，本轮**只记录不修**，避免把一次优化轮变成数据结构改造：

1. **已装记录读取被整套重新校验，规则一变就整条丢弃**：`store.ts` 的 `coerce` 失败 → `null`，
   而清单校验要求命令 `target.page` 属于当前 `PALETTE_PAGES`。`10634fb`（d.67）删掉
   `skills/interfaces/workspace/tasks` 四个 page id 后，d.64–d.67 期间装过的此类插件在升级后
   整条记录被静默抹掉，但其技能仍按 `pluginId` 默认分配、MCP 服务仍启用并会被自动连接。
   **应改成「保留骨架 + 标记降级」或按 `plugin:<id>:` 前缀回收孤儿。**
2. **安装不是事务**：先写技能、再登记服务，任一步失败无回滚（本轮只堵住了大小写这一条确定路径）；
   `save()` 吞掉 `setItem` 失败（配额/无痕）仍返回成功，内存与磁盘会分叉。
3. **卸载/停用只信记录里的 `skillIds/serverIds`**，字段缺失或被容错成空就漏删：
   应按 `plugin:` 前缀与 `pluginId` 回扫技能池/注册表取并集。
4. **更新会覆盖用户在技能区单独设置的技能开关**（`store.ts` 注释写「保留用户选择」与实际不符）。
5. 插件市场/URL 安装、插件级智能体分配、stdio 本地命令类配置仍按既有红线**不做**。

## 6. 红线未变

- 插件仍只声明、不执行代码；不含命令/环境变量/请求头/密钥；安装不联网、不自动连接、不自动授权。
- 风险上限只收紧不放宽；HITL 判定链、拒绝优先、危险操作不记忆等规则一字未动。
- 数据仍只落本机 `localStorage`，不上云、不导出、换设备不跟随。

# 和鸣智能体运行时 · 上下文与工具预算说明

- 文档版本：2026-11-15 / d.147.4.94.11
- 面向读者：接入智能体运行时的前端与评测同学
- 关键词：context window、token budget、rollout、HITL、tool result folding

## 1. 一次对话是怎么跑的

用户在输入框里 @ 一个智能体后，客户端起一条流（stream）。流里的每个回合大致分三步：

1. 组装请求：system 提示词 + 历史消息 + 本轮要回灌的工具结果；
2. 请求模型：模型返回 text 或 tool_calls；
3. 执行工具：只读工具并行、写与危险工具串行，结果回灌下一回合。

模型看不到「本地文件系统」本身，只能看到工具返回的文本。因此**工具结果的长度直接决定上下文压力**。

## 2. 三个预算数字（必须记住）

| 预算项 | 数值 | 作用点 | 超出后的行为 |
|---|---|---|---|
| 历史预算 | 6000 tokens，保留最近 8 轮，预留 900 | 拼装请求前的历史裁剪 | 更早的轮次被折叠成摘要 |
| 工具结果回灌预算 | 3000 tokens，最近 3 条不折叠 | 每轮重发请求前 | 旧工具结果替换为占位摘要（不删除） |
| 单条工具输出截断 | 8000 字符，保留头 2/3 + 尾 1/3 | 工具结果进入上下文前 | 中段被省略，并标注已截断 |

三个数字的分工不同：历史预算管「旧对话」，回灌预算管「工具证据」，单条截断管「一次别塞太多」。
调优时禁止只改其中一个而不看另外两个，否则会出现「省了 token 但模型丢了证据」的静默回归。

## 3. 工具轮与收敛

- 工具轮上限 12（`MAX_TOOL_ROUNDS`），这是防死循环的兜底，不是鼓励模型多轮；
- 单轮工具 token 上限 12000（`MAX_TURN_TOOL_TOKENS`）；
- 收敛应靠「信息够了就收口」，而不是靠耗尽轮次；
- 脚本必须自然收尾：最后一个回合直接给 `text`，不要等脚本耗尽。

## 4. 上下文压缩（compaction）

长会话不是无限增长的。最近 8 轮之前的内容会被压缩成第二条 system 消息：

- 压缩摘要只保留事实与决定，不保留寒暄；
- 被折叠的原始消息不会立刻消失，评测里仍可通过 rollout 回放；
- 压缩后的答对率是专项指标（题集 `context` 标签），不降才算达标。

一个常见误区：把「压缩」理解成「删除」。实际实现是**替换占位**，原文仍在回放里，
只是不再进入后续请求，因此模型必须能在摘要里找到继续任务所需的最小事实。

## 5. HITL（human in the loop）与安全边界

工具调用不是都自动执行的：

- 读操作自动通过；
- 根内写按「首次确认一次」的口径处理；
- 根外写、删除、危险扩展名、改 package.json 的 scripts 属于硬排除清单，永不自动放行。

HITL 的兜底方向永远是「不执行」：确认流程异常时按拒绝处理，而不是放行。
安全用例在评测里是一票否决项，任一失败整轮判红。

## 6. 观测与回放

- rollout 记录 5 类事件：turn_start、tool_call、tool_result、assistant_final、turn_end；
- turn_end 带 usage（input / output / cacheRead）与工具耗时；
- tokenUsage 账本带 streamId，可把一次流的所有回合串起来；
- 回放视图支持单回合导出，评测报告只放摘要，不入库。

## 7. 评测题集与确定性

确定性评测使用假网关：不联网、脚本固定、时延固定，同一提交两次跑分必须逐用例一致。
题集只使用工作区内 fixture 与假 MCP 响应，禁止依赖真实模型、网络或用户目录。

判定口径写死在脚本里：

- 全部 grader 通过才算该用例 pass；
- 安全用例任一失败 = 整轮红；
- 分数下降超过 2%、每通过用例 token 涨超过 10%、p95 时延涨超过 15% 都判红。

## 8. 常见故障速查

1. 工具结果丢了中段证据 → 先看单条截断（8000 字符）与回灌折叠（3000 tokens）。
2. 长会话后半段答非所问 → 看压缩摘要是否漏掉关键事实。
3. 补丁反复失败 → 让模型先 file_read 再按读到的原文重写锚点，不要凭记忆写。
4. 根外写被拒 → 这是预期行为，给模型的信息是「改成根内相对路径」，不是换写法绕。
5. 评测结果抖动 → 先确认假网关脚本是否被改动，再怀疑模型。

## 9. 术语表

| 术语 | 含义 |
|---|---|
| stream | 一次智能体调用的完整流，含多个回合 |
| turn / 回合 | 一次模型请求 + 可能的工具执行 |
| rollout | 运行时事实日志，评测与回放的共同来源 |
| HITL | 需要人确认才能执行的高风险操作 |
| fixture | 评测用例的初始工作区，整份复制到临时目录 |

# InfoHub 采集桥（和鸣插件）

把本机 InfoHub（QQ/微信归档）的能力接进和鸣：
智能体可以查看**采集状态**、发起**增量采集**、**检索归档**、读会话与日程。
数据只在本机 `127.0.0.1` 回路里走，插件本身不含代码、不带密钥。

> 本插件是**声明式**的：`plugin.json` 只声明一个「本机 MCP 服务」和一组技能/命令/工具束。
> 真正干活的采集桥是 InfoHub 项目里的 `infohub mcp` 命令（见下），和鸣安装插件时不会运行它。

## 它贡献什么

| 能力 | 内容 |
|---|---|
| MCP 服务 | `InfoHub 采集桥` → `http://127.0.0.1:8776/mcp`（只接受本机回环） |
| 技能 | 「本机归档采集与查询」：什么时候用哪个工具、写操作先确认、引用标注来源、不可用时如实说 |
| 工具束 | 「本机归档工具」：把下面 5 个工具归到本插件名下（工具页可看已匹配几个） |
| 命令 | 「查看采集状态」「采集本机消息」「检索本机归档」「查看归档日程」→ 信息中枢页；「采集桥连接与授权」→ 本插件详情 |
| 权限 | 网络：`127.0.0.1:8776`；工具风险上限：`write`（采集会写本机归档） |
| 检索 | 插件列表里可用「QQ」「微信」「聊天记录」「日程」「待办」「同步」等词搜到本插件 |

MCP 服务提供的 5 个工具：

| 工具 | 读写 | 用途 |
|---|---|---|
| `infohub_status` | 只读 | 归档规模（会话数 / 消息数）+ 每个来源最近一次采集的时间与结果 |
| `infohub_sync` | **写** | 增量采集，`sources` 可传 `qq` / `wechat`；缺省用 InfoHub 里已启用的来源 |
| `infohub_archive_search` | 只读 | 全文检索归档，返回片段、会话名、发送者与时间 |
| `infohub_archive_read` | 只读 | 按会话读最近消息；会话名有歧义会返回候选 |
| `infohub_archive_agenda` | 只读 | 从消息里识别出的日程与待办（逾期 / 今天 / 本周） |

## 安装与使用

1. **先启动采集桥**（在 InfoHub 项目里，只需一次）：
   ```bat
   .venv\Scripts\python.exe -m infohub mcp
   ```
   看到 `MCP 服务已启动：http://127.0.0.1:8776/mcp` 就是好了；保持这个窗口开着。
2. **装插件**：插件区 →「手动粘贴清单」→ 选择本目录的 `plugin.json`（或直接粘贴内容）。
3. **连接服务**：插件区 → MCP 服务 → 找到「InfoHub 采集桥」→ 连接 → 逐个启用要用的工具
   （默认全部关闭，这是既有规则；`infohub_sync` 是写工具，每次调用都会走人工确认）。
4. **用**：直接对智能体说，或从命令面板（Ctrl K）搜「采集」「归档」：
   - 「最近采过消息吗，QQ 和微信各多少条」→ 只读 `infohub_status`
   - 「把上周的 QQ 消息同步一下」→ 复述范围、确认后调 `infohub_sync`
   - 「搜一下『免检单』是什么时候说的」→ `infohub_archive_search`，命中后可用 read 看上下文
   - 「最近有什么要办的事」→ `infohub_archive_agenda`
   也可以从信息中枢页手动采集 / 检索 / 看日程。

## 连接与排错

| 现象 | 处理 |
|---|---|
| 插件区 → MCP 服务里连接失败 | 采集桥没启动或已退出：重新运行 `infohub mcp`，确认窗口保持打开 |
| 端口 8776 被占用 | 采集桥拒绝复用端口（Windows 下会启动失败）：关掉占用的进程，或给 `infohub mcp` 换端口——但换端口后 `plugin.json` 的 `network` 与 `url` 也要一起改，否则装不上 / 连不上 |
| 工具在列表里但智能体说没工具 | 工具默认关闭：到插件区 → MCP 服务 →「InfoHub 采集桥」逐个启用；重建对话后生效 |
| 浏览器版和鸣连不上 | 采集桥只监听本机回环，并从浏览器跨源访问需要 CORS 放行（采集桥已放行）；若仍失败，改用桌面端 |
| 智能体答「采集桥没连上」 | 这是如实回答，不是报错：先启动服务并连接，再重问 |

## 边界

- 采集只读本机聊天数据库并写 InfoHub 自己的归档库；不注入、不 Hook、不发送消息。
- 归档内容不上传、不进和鸣会话记录；智能体引用时会标注「来自本机归档」。
- 采集桥只监听 `127.0.0.1`，不对外网开放；插件不携带密钥、安装时不联网。
- 本插件的写操作只有 `infohub_sync`；重扫日程、导出等仍在信息中枢页手动操作。
- 和鸣的「信息中枢」内置模块（桌面端 stdio 边车）仍然可用；两者互不依赖，
  插件这条路的优势是浏览器里也能用、并且把采集能力显式交给智能体（仍走人工确认）。

node scripts/plugin-lint.mjs plugin-kit/plugins/infohub-collector/plugin.json

## 卸载

插件区 → 插件 → 卸载。**不会**删除 InfoHub 的归档或配置（它们不在和鸣存储里）；
采集桥进程需要你自己关掉（Ctrl+C）。

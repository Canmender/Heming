# 插件开发助手

插件 id：`heming.plugin-dev`；类型：声明式插件（`schemaVersion: 5`）。

在和鸣里写插件的随身手册：三条技能、五条命令、一个速查页面。本目录同时是一份**可抄的 v5 参考实现**——
技能、命令、声明式页面、最小权限四类写法都在里面。

## 装了什么

| 贡献点 | 内容 | 怎么用 |
|---|---|---|
| 技能 ×3 | `编写和鸣插件` / `排查插件安装失败` / `设计插件页面` | 对智能体说「帮我写一个插件」「插件装完没生效」「给插件加个页面」，或从命令面板打开 |
| 命令 ×5 | 写新插件、插件排查、设计页面、打开插件区、本插件详情 | `Ctrl/⌘+K` 搜索「插件」 |
| 页面 ×1 | 左侧导航末位的「插件开发助手」 | 插件选型、校验命令、提交前检查一页速查；**静态展示**，不联网、不执行代码 |

页面用宿主受控块渲染（markdown / stats / table / list / actions / contributions），安装版与浏览器版都能看。
没有写 `permissions`——这个插件不联网、不读写文件、不订阅事件，也不需要模型网关。

## 数据放哪

不产生任何数据：没有本机存储键、没有缓存目录、没有设置项。卸载即干净移除，不留孤儿记录。

## 怎么安装

和鸣桌面端 → 插件区 → 安装 → 选文件或粘贴本目录的 `plugin.json` → 先看预览（权限、贡献、兼容性）→ 点安装。
装完左侧导航末位多一个入口；停用插件后入口随插件一起撤下。

## 怎么卸载

插件区 → 本插件卡 → 卸载。它会连同三条技能、五条命令与页面一并移除；本插件没有需要保留的用户数据。

## 为什么是这些内容

编写插件最容易踩的坑集中在四处：**形态选错**（把第三方需求设计成 bundle）、**权限多要**（MCP host 没写进
`network` 或者无脑写 `tools: "write"`）、**页面越界**（想在静态页里拉数据/改宿主界面）、**装完不生效只会猜**
（顺序应是总开关 → 贡献级开关 → 兼容性 → 签名 → 工具上限 → 孤儿记录）。三条技能分别对应这四类问题，
页面则是把校验命令与检查清单放在手边。

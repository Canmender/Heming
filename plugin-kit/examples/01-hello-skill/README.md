# 示例 01 · 最小技能包（v5 声明式）

**教会你**：一个插件最少要写什么；`instructions` 怎么写才稳定。

```bash
node scripts/plugin-lint.mjs plugin-kit/examples/01-hello-skill
```

## 抄的时候改这几处

| 字段 | 说明 |
|---|---|
| `id` | 换成你的（反向域名或 `作者.能力`），**发布后不能改** |
| `name` / `description` | 用户看到的名称与一句话说明 |
| `engines.heming` | 换成你真正需要的最低宿主版本（如 `d.117`） |
| `contributions.skills[0]` | 技能名（插件内唯一）、`instructions`、`triggers`、`tags` |

## `instructions` 的四段结构

1. **什么时候用**：一句话场景。
2. **步骤**：编号，一步一个动作。
3. **输出形状**：段数/字数/字段。
4. **边界**：不编造、不越权、缺数据就说缺什么。

反例是「请生成一份专业、全面、详细的周报」——没有步骤和边界，输出每次都不一样。

## 装进应用后

1. 插件区 → 安装 → 选这个 `plugin.json` → 看预览（差异/权限/兼容性）→ 安装。
2. 技能进入技能池；若你的智能体有显式分配记录，去技能区把它分配给该智能体。
3. 对智能体说「写周报」即可命中触发词。

> 没有 MCP 服务时不写 `permissions` 就对了——别为了「看起来完整」声明一堆用不到的权限。

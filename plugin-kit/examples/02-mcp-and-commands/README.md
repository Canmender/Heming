# 示例 02 · 技能 + MCP + 命令 + 工具束（v5 声明式）

**教会你**：接一个 MCP 服务时权限怎么写、为什么装完还要用户手动连接、命令与工具束各自做什么。

```bash
node scripts/plugin-lint.mjs plugin-kit/examples/02-mcp-and-commands
```

## 关键点

| 部分 | 注意 |
|---|---|
| `permissions.network` | **每个服务的 host 都必须在这里**（本示例 `127.0.0.1:3999`，本机回环允许 http）。写漏了直接装不上 |
| `mcpServers[].url` | 只 https；http 仅限 `localhost` / `127.0.0.1` / `[::1]` |
| `permissions.tools` | 风险上限：`read` 时写工具**不会注入给模型**；`write` 也仍逐次人工确认 |
| `commands[].target.kind: "skill"` | `name` 必须是本插件 skills 里的名字 |
| `toolPacks` | 只声明「这些工具属于我」，**不开关工具、不授权** |

## 装进应用后的完整链路（也是你要写进 README 的）

1. 安装（预览里会列出「网络访问：127.0.0.1:3999」）。
2. 接口区 → 找到「演示服务」→ 连接（插件安装**不会自动连接**）。
3. 工具目录里逐个启用 `demo_summary`（工具**默认关闭**）。
4. 对智能体说「用报告工具箱汇总本周数据」→ 命中技能 → 调用工具。

## 本地起一个演示服务

任意实现 `POST /mcp` 的 MCP 服务即可；仓库没有内置它。调试时可以把 `url` 换成你本机的服务地址（记得同步改 `network`）。
若没有服务，只校验清单也完全够用——`plugin-lint` 不联网。

## 其它

- `meta` 只影响市场展示，不影响安装；图标建议 https URL。
- 工具名跨束不能重复；一个包最多 10 个服务、10 个工具束。

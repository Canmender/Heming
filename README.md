# 和鸣

原生电脑端智能体应用平台（云端团队名册）：一个内置智能体、会话式工作 + 独立协作页 + 真实团队动向。

> **当前版本**：`d.348.4.128.12`　查看最新：`node scripts/version.mjs`（或 `pnpm version:show`）
> **版本号规则**：5 段 `d.特性.破坏性.修订.构建`，**每次修改/修复都要 bump** —— 见 [docs/VERSION-MANAGEMENT.md](docs/VERSION-MANAGEMENT.md)
> 改动记录见 [CHANGELOG.md](CHANGELOG.md)。

> 接手开发先读 **[docs/HANDOFF.md](docs/HANDOFF.md)**（现状 / 架构红线 / 工作方式约定 / 下一步候选）。

## 能力

- **极简外壳** — 顶栏（手写标志 + 命令面板 Ctrl+K + 快捷键帮助 + 通知中心）+ 常驻侧栏（顶部是页面导航：插件 / 团队 / 模型 / 知识库与已装插件页；其下是「工作区」面板——会话按本机文件夹分组、组头可折叠、可新建工作区；左下角是设置与账户）+ 内容区，
  不设左侧图标导航轨、栏也不再收起；打开应用默认进「会话」页，切页走侧栏、命令面板或 `Alt+1/2/5/6/8/0` 键位
- **智能体对话** — 模型能力统一由本机 **magpie 网关**提供（原生组件）：设置区只填网关地址与网关 Key（默认 `127.0.0.1:3425` / `magpie-heming`），
模型目录来自网关 `/v1/models`，用户已有的 Agent 登录/订阅/API Key 都由 magpie 管理、多个账号可轮换供 token；**只有唯一内置智能体「和鸣」**（不可创建/修改/删除），与它开多段独立会话（Claude Code 式：左侧常驻会话侧栏、每段各自保存历史），支持流式回复、思考过程与工具轨迹可视化，会话页顶部有「编排条」（标题 + 团队/模式/工具调用/后台任务）+「对话 / 轨迹 / 上下文」页签（切页签不丢草稿）；支持视觉的模型可读图片（**历史里的图与本轮刚上传的图都能看**：输入框有正文时选图即为「图片 + 文字同发」一条消息，按智能体所绑模型判定，图片本地解密后直连本机网关卡）；绑定的模型缺能力时**发送前就明说会丢什么**（不支持工具 / 不支持图片），判定与实际丢弃同源。**人类私聊/群聊与语音通话已从本版移除**，对话入口只剩这一个内置智能体
- **工具与 MCP** — HTTP / stdio 两种传输、自动连接、工具级开关；**Windows 桌面控制与网页抓取是随应用内置的系统能力**（接口页只读展示、不可删除，只读工具默认启用、其余逐个授权），私有 MCP 服务仍自行添加 / 改 / 删；模型可在会话中调用外部工具，结果回灌后继续回答；stdio 仅桌面端，启动恒定 `shell:false`，删除服务会回收其本机子进程；工具目录超过 20 个时自动切**按需检索**——只暴露一部分 schema，其余由模型按关键词检索后加入可调用列表（检索是内部只读动作，不弹确认）
- **MCP Registry 发现** — 接口区可搜索官方 Registry 并一键安装（搜索防抖、6h 本地缓存、离线降级）；安装前始终弹确认卡（来源/评级/请求头），装完工具默认全部关闭；本地 npm/pypi 包需本机已有 Node.js（uv / uvx 随桌面端内置在 `runtime/bin`，Node 仍不内置；装之前先探测并标出「缺运行时 / 需桌面版」），且必须钉死版本、包名走字符白名单、启动恒定 `shell:false`；删除服务会回收其本机子进程
- **人工确认（HITL）** — 工具执行前先问用户；风险分 `read/write/danger` 三级，档位 `strict/guarded/trusted`，没有“全部放行”档；可按工具与资源记住允许/拒绝（**规则只对内置智能体生效**，拒绝优先，危险操作不记忆，最多 200 条、可一键清空）；被拒调用不执行但仍回灌 tool 消息，且区分「用户拒绝 / 命中规则 / 闸门异常」；确认前可查看将写入的变更（编辑显示行级 diff、写文件显示行数、删除只显示路径，不读取文件内容）；弹窗标明请求来自哪个会话，离开会话时其待确认项按拒绝收口
- **任务区** — 面向长任务的三栏视图（Alt+8）：左侧任务列表（搜索/状态筛选/清除已结束），中间复用智能体会话继续对话，右侧确定性汇总（目标、结果、步骤、来源、拒绝原因）与**只读过程日志**（开始→工具调用→结果→答案→终态，被拒单独标出，运行中每 2 秒刷新）；新建任务自动把目标投递给该智能体，**任务模板**可把常用目标一键填回输入框（仍可编辑，最多 12 个、只存本机）；执行中实时耗时、三段进度与步骤时间线；报告由记录生成并可一键复制 Markdown 或 JSON（`version: 1`）；记录只存本机 `localStorage`，不上云
- **消息公式** — 消息支持 LaTeX 行内与块级公式（KaTeX 本地渲染，不请求外部 CDN）；会话导出（含多选导出）已在本版移除
- **记忆与技能池** — 三层记忆（工作/情景/语义）按需注入系统提示词；召回走**同主题时效覆盖 + MMR 去重名额**（同一主题只带最新一条，近似重复不会占满 1200 字注入预算；确定性打分、无学习式权重）；**召回全程可观测**——本机留最近 40 次生成的召回档案（短期/长期/个人知识库三个开关自 d.147 起固定全开、全部后台运行，记忆页已删除，没有开关界面）；技能池支持新建/导入导出（`SKILL.md`）/按查询路由/分配给内置智能体（**启用即边界**：未启用的自定义技能不会进入提示词）；记忆与技能数据只落本机 `localStorage`，不上云、不进消息，召回日志也不随记忆导出带走
- **插件包** — 插件区（Alt+0）可安装、更新、启停与卸载系统能力包，支持按名称 / id / 作者 / 技能 / 服务搜索与「全部 / 已启用 / 已停用」筛选，装完自动定位并高亮新卡；`plugin.json`（现行 v5；v3 及更早旧包仍可装，界面插件用 v4 bundle）可声明技能、远程 MCP 服务（https，或本机 http）、命令、工具束与模型接入预设，并显式声明权限（网络主机 / 工具风险上限 / 文件根）：主机白名单必须覆盖每个服务（默认端口两侧统一规范化），**风险上限在执行期生效**——超过上限的工具不会交给模型，而不只是页面上标「未注入」；不执行随包代码、不携带密钥、安装时不联网、不自动连接/授权；同 id 再装即更新（技能按名称、服务按 key 增/改/删，保留请求头、工具启用状态与插件启停状态），更新前先看只读差异（新增/变更/不变/移除，冲突或数量超限时禁止确认），插件详情只读展示每个技能与服务的启用状态和地址（未声明的贡献类别灰置开关并注明）；停用同步关闭服务，卸载连同技能、绑定、服务与工具清单一并删除，同名手工技能与转正服务不受影响；插件、技能与服务配置都只落本机 `localStorage`，不上云、不导出；**插件包不随安装包分发**：仓库自带的真实插件源码在 `plugin-kit/plugins/`（InfoHub 采集桥 / 工作流引擎 / 桌宠），由 `scripts/publish-plugin.mjs` 发布到云端插件目录（服务端 `GET /api/plugins`），用户在「安装插件 → 从云端浏览」里下载、**校验 sha256** 后安装；v4 清单新增 `contributions.llmPresets`（只填协议/地址/模型，不含 Key），插件停用后对应预设消失、已保存连接不受影响；**写插件看 `plugin-kit/`**（标准 / 菜谱 / FAQ / 真实插件源码 `plugins/` / 四份示例 / 脚手架；`pnpm plugin:new` 起步）
- **内置能力模块（可插拔）** — 插件区 → 「模块」Tab 把**幕僚 / 信息中枢 / 自动化 / 模型路由**四个内置页当成能力模块管理：可查看版本、贡献（页面入口 / 首页卡 / 后台循环 / 模型工具前缀）、依赖与本机数据键，用开关启用或停用。停用只下线入口、页面、首页卡、后台挂载与相关工具注入（信息中枢已连接的本机进程会释放），**不删除任何本机数据**，重新启用即恢复；自动化依赖信息中枢，依赖未启用时开关保留但实际不生效；模型路由停用时选路退回声明顺序、候选链与失败切换照常。「模型路由」页是 magpie（MIT）选路语义的移植收口：七档策略（声明序 / 智能 / 用得最少 / 节奏 / 权重 / 速度 / 轮流）、失败切换、冷却、逐候选用量与脱敏都只在本机算，不读供应商配额/不读价格、不做请求翻译；测速样本只在内存、重启清零。默认全部启用，行为与改造前一致；模块状态只存本机 `heming.modules.v1`，不上云、不导出。第三方能力仍走「插件」Tab（技能 / 远程 MCP / 命令），第三方页面贡献明确不做。侧栏「模型」页把模型能力做成和鸣自己的界面：模型、来源、运行三块（账号并入来源；用量/备份/同步/库/高级收进运行）；加来源只需登录订阅或粘贴一个 Key，随应用启动、无需开关服务，「实时链路」还能看见请求从客户端到账号的走向；登录/口令等交互走真终端，浏览器版只读。
- **信息中枢** — 把本机 QQ/微信归档接进和鸣：桌面端主进程用 stdio 拉起 InfoHub Python 边车（不开端口、不走网络），浏览会话、只读消息、全文检索（命中高亮并可回到会话）与议程都在本机完成；归档以 SQLite `mode=ro` 打开，同步/导出必须由用户显式勾选来源后触发；`config.json` 不进仓库，配置摘要只显示开关与「是否配置过」，不展示密钥；浏览器环境直接提示仅桌面端可用。**归档也是智能体能力**：桌面端已连接时注入 `infohub_search` / `infohub_read_conversation` / `infohub_agenda`（只读）与 `infohub_agenda_rebuild`（重扫日程，走人工确认），首页显示本机归档卡，Ctrl+K 可同时检索归档；未连接不注入工具、不自动拉起进程，`sync` 始终只由用户在信息中枢页显式触发
- **自动化** — 「自动化」页（内置能力模块，入口由插件页装出）可为本机归档建定时任务：每天定时（本地时区 + 星期）或按间隔（5–1440 分钟）执行 `infohub.sync`（QQ/微信来源、全量重扫、导出知识库）或 `infohub.agenda`（重扫日程）；任务只存本机 `localStorage`（最多 20 条），不上云、不导出、不执行任意脚本；只在和鸣运行且信息中枢已连接时触发，未连接记为跳过并顺延，**绝不自动拉起 Python 边车**；关闭期间错过的时刻不补跑。信息中枢页的「定时 / 保存为定时任务 / 定时重扫」会把当前选项直接带进新建表单。**执行内核**（d.66）：动作是声明式注册项（加动作只加元数据 + 执行函数）、运行记录独立键（最多 40 条 / 192KB 双淘汰，含触发来源与耗时，删任务即级联删记录）、失败进通知中心并可跳回定位——仍**不自动重试、不补跑**，任务与记录都只在本机
- **自我优化与知识库** — `self_*` 工具可改自己的记忆/技能/MCP（带敏感内容护栏、单轮上限与留痕），每次改动都有反向快照、可在技能区逐条回滚；LLM Wiki 文件态知识库（桌面端写真实 Markdown，Obsidian 可直接打开），问答可通过只读工具检索并附确定性来源脚注；网页抓取内置（Scrapling）
- **上下文预算** — 设置区可对智能体触发的历史做 token 预算：超出部分压缩为早期对话摘要（可选 LLM 摘要或零成本确定性摘要），供应商报上下文超限时自动收紧预算重试；只在本机执行
- **团队系统与主页** — 全站一个团队，所有注册用户即成员：团队页（侧栏第 2 项，Alt+2）显示名册、在线状态、最近活跃与动向流；在线来自服务端 WS 连接，最近活跃落库，名册 20 秒刷新。动向只含**摘要**——成员自己的任务标题/状态、日程标题/到期档位，**不包括对话正文、提示词、工具参数、智能体轨迹或附件**；任务 / 日程两类共享默认全关，逐类开启后才采集，设置只存本机，可一键清除已上传记录。智能体不是团队成员，名册与动向都不出现智能体条目。主页有团队动向卡（最近 3 条）与成员/在线/会话/今日动向四张统计卡；Ctrl+K 改为「搜索成员与技能」，选成员直接跳团队并定位。应用内通知中心保留任务、审批与幕僚三类，不再有消息通知。
- **会话页** — 全产品只有一个内置智能体，页面就是「会话」，界面按 ChatGPT / Claude 官方极简风做：左侧常驻「工作区」侧栏（顶部是页面导航，其下会话按本机文件夹分组、组头可折叠、可新建工作区；「新对话」主按钮、搜索、改名、删除照旧；所有页面共用，栏底依次是设置与账户入口），顶部只显示当前会话名（不再重复产品名），右上角「会话进度」按钮可呼出 Codex 式右侧栏（本轮进度 / 动态流程图 / 任务步骤 / 工具调用，切页或换会话自动收起，左缘可拖拽调宽 240–560 并记住宽度）；消息列与输入区最宽 960 自适应（`max-w-[min(100%,960px)]`）、助手回答全宽无气泡、用户消息右对齐圆角、输入框收成一个大圆角容器（左侧工具图标、右侧圆形发送）。会话彼此独立保存，状态条的「模型设置」跳到模型页统一绑定。保留消息列表、流式气泡、E2E 封发、附件、文档解析、图表、HITL、记忆/技能/工具、任务草稿与会话内搜索（导出与多选导出已移除）。**自建智能体（名册/新建/编辑/删除）已整体移除**——对齐 Codex / Claude Code 的会话模式；多智能体协作不再混在会话页，见下一项。
- **协作页** — Alt+5（侧栏无入口）：参与者固定「和鸣」（不可取消）+ 本机智能体（从本机 magpie 检测到的 Claude Code / Codex 等，至少两位才能开始）；三种模式（顺序 / 主管 / 辩论）、轮数 1–3、开始/停止、逐回合卡片与「清空」，上一次运行可恢复（`heming.collab.last.v1`）。发言统一走本机 magpie 网关——「和鸣」用它当前绑定的模型档案，本机智能体按模型名匹配本机档案；**本机 CLI 不会被执行 prompt**（只能以它的模型身份发言），浏览器环境没有桌面桥时页面会说明。
- **键盘与可访问性** — 弹窗统一契约：Esc 只关栈顶那层、Tab 在面板内循环、打开即落焦、**打开期间屏蔽背景**（`inert`，无 portal 故按兄弟逐个屏蔽 + 引用计数支持嵌套；非模态浮层可退出）、关闭后焦点归还触发元素（仅在焦点确实无处可去时还，不抢关闭方主动安排的焦点）
- **端到端加密** — 智能体消息与附件端到端加密（前向保密棘轮，服务端只见信封）；本地明文缓存；明文存量自迁移；桌面端安全上下文白名单
- **共享文件（文件库）** — 云端共享库文件投递、内嵌预览（文本/Markdown/图片）、每用户存储配额（`HEMING_FILE_QUOTA_MB`，默认 200MB）；会话页不再常驻「共享文件」面板（窄窗抽屉一并退场），文件库 API 与存储保留，团队交付物仍走共享库
- **桌宠** — 桌面 Live2D 化身：独立透明置顶窗（`pet.html` 独立入口，不背主应用 bundle）、默认鼠标穿透并按模型包围盒动态关闭、视线跟随/点击动作/说话口型；点角色直接对话（复用 `streamChat` 直连本机 LLM，**不写会话、不进消息列表**）；位置与缩放缓存在本机，托盘常驻可显隐/切穿透；未连接 magpie 网关时如实提示并直达设置
- **桌面端** — 嵌入 web 产物经 `app://heming` 本地加载、自动更新、内置运行时、启动动画与自定义标题栏；通话窗口与语音桥已随 IM 一并移除。**内置 magpie 模型网关**（d.92）：安装包随带 `magpie-cli`，主进程负责启动/探活/退出回收，并在本机回环上开一个带 CORS 的反代给渲染层用——用户装完即有可用的模型目录，无需自己跑 magpie；本机已有 magpie 在跑时直接接入（不另起、不抢端口、不会关掉它）

- **本机文件读写（d.153）** — 内置智能体第一次真的能落盘：`file_read` / `file_patch` / `file_write` / `file_edit` / `file_glob` / `file_grep` 六个工具，写盘只在可写根内（web 侧收敛 + 桌面主进程再夹一次，软链、越界、二进制、2MB 逐项拒），父目录按需创建，写盘原子（tmp + fsync + rename）。**根从哪来**：会话工作区自动成为写根；未分组会话用默认工作区「文档 / 和鸣」（主进程建目录、经 IPC 同步下发）；手动添加的根优先，可逐条改读写模式

- **改了什么，工具行里就能看（d.239.4.116.12）**：工具调用展开后先给「这次改动：新增 N 行 / 删除 M 行」与逐行增删（`file_write` / `file_edit` / `file_patch`），失败的调用不画；改动对照弹窗新增「只看改动」，长文件里不用在上下文里翻找。

- **上网有了边界（d.238.4.116.12）**：设置 → 网络访问 里可以把「能读哪些域名」限定成一份列表（默认仍是「开放」），列表外的网页会被拒绝，`/status` 会如实写出当前边界；内网与本机地址始终读不到。

- **无头 CLI：能边跑边说，也能从管道接指令（d.237.4.116.12）**：`heming exec --output-format stream-json` 的 stdout 每行一条事件（开始 / 第几轮 / 正在调哪个工具 / 结果 / 重试 / 收尾），CI 能实时看到、别的程序能边看边决策；prompt 写 `-` 就从 stdin 读（`git diff | heming exec -`，上限 1 MB 并会指路 `--cwd`）；`exec --json` 新增 `stopReason`，把「做完了」和「撞轮次上限停了」分开。
- **会话内搜索快捷键与工具轨迹（d.236.4.116.12）**：`Ctrl+F` / `Cmd+F` 唤起并聚焦、`Esc` 关闭；搜索范围扩到工具轨迹（每条消息最近 8 次调用的名称/参数/结果，单条截断 4000 字），「那次 grep 搜到了什么」也搜得到。
- **新加的桌面通道有真机检查了（d.235.4.116.12）**：「看改动」「定位」依赖的两条桌面通道进了自动冒烟（真 Electron 里走一遍，冒烟 56 项），并且「定位一个已删掉的文件」不再被说成「环境打不开文件管理器」。

- 信息中枢（可选）：浏览/检索用桌面端内置 Python 即可；采集/转写需要 InfoHub 自己的 Python ≥ 3.11 虚拟环境，并在页面里选它的解释器

## 启动

```bash
pnpm install
pnpm -r build

# 终端 A：云端服务端（http://127.0.0.1:8787）
pnpm --filter @heming/server dev

# 终端 B：前端（Vite，代理 /api 到 8787）
pnpm --filter @heming/web dev

# 终端 C（可选）：桌面壳（本地 dev：加载 Vite 开发服务器，由其代理 /api）
HEMING_DEV_URL=http://localhost:5173 pnpm --filter @heming/desktop dev
```

> 桌面壳（`packages/desktop`）默认加载**包内嵌入的 web 产物**（自定义协议 `app://heming`），API 与 WS 仍走云端；也可用 `HEMING_DEV_URL`（本地 Vite）或 `HEMING_WEB_URL`（自定义生产地址）覆盖。嵌入产物由 `pnpm -w run dist:desktop` 预构建，`pnpm --filter @heming/desktop start` 即以嵌入产物启动。
>
> **不能用 `file://` 加载**：它不是安全上下文，`crypto.subtle` 不可用会让 E2E 加密失效；`app://` 注册为 privileged + secure，实测 `isSecureContext=true`。
>
> 改了 web 代码要**两处分别发布**：云端（浏览器访问）与桌面端（重打安装包）。只发一处会出现“浏览器是新的、已装客户端是旧的”。


## 打包 Windows 安装包

```bash
# 国内网络需先设置 electron-builder 二进制镜像（NSIS / winCodeSign 下载）
export ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
```

## 测试

```bash
pnpm test        # 等价于 pnpm -r build && pnpm -r test
pnpm typecheck   # 等价于 pnpm -r build && pnpm -r typecheck
```

说明：根目录 `pnpm test` / `pnpm typecheck` 会先自动 `pnpm -r build`（`shared` 的类型产物被其他包经 workspace 引用，fresh clone 直接跑测试会因缺 `dist` 失败），再执行各包的 test/typecheck。
服务端测试（`packages/server`）由 `scripts/test-each.mjs` 驱动：**每个测试文件一个独立 vitest 进程**，只对 worker 原生崩溃（Windows 上 `0xC0000409` 一类）做有界重试（最多 3 次），断言失败一次就算失败；每次重跑都会打印出来。这样退出码可信，不需要人工单跑重试。

### 智能体评测（确定性）

```bash
pnpm eval:agent                                   # 跑全部 18 条用例（离线：脚本化模型 + 真实编排层）
pnpm eval:agent -- --filter edit                  # 只跑 id 含 edit 的用例
pnpm eval:agent -- --compare evals/baselines/latest.json   # 与冻结基线比（分数/token/p95 三项红线）
pnpm eval:agent -- --repeat 3 --json evals/reports/freeze.json  # 稳定性：3 次分数极差 ≤3 个百分点
```

- 用例 `evals/cases/*.yaml` + 夹具 `evals/fixtures/`，契约见 [evals/README.md](evals/README.md)；基线 `evals/baselines/latest.json` 只许人工复核后更新（运行器没有 `--update-baseline`）。
- 判定：分数降 >2%、每通过用例 token 涨 >10%、p95 涨 >15%（且 >100ms 噪声门限）即红；安全用例（tags 含 `security`）任一失败一票否决。报告写 `evals/reports/`（不入库）。
- 夜间真实模型任务需要 `HEMING_EVAL_API_KEY`（`--real`），缺 key 时 GitHub Actions 的 nightly job 显示 skipped 而不是绿。

## 结构

- `packages/shared` — 协议类型与 Zod schema（前后端唯一事实来源）
- `packages/server` — Express 5 + WebSocket + SQLite 持久化存储
- `packages/web` — React 18 + Tailwind（顶栏 + 会话侧栏 + 内容区）；智能体运行时（LLM/记忆/技能/MCP/HITL）全部在此
- `packages/desktop` — Electron 壳（嵌入产物、自动更新、stdio MCP 桥、文件桥；通话窗口已移除）

## 数据

服务端数据（账号、好友关系、智能体会话与消息、团队动向摘要）持久化在 SQLite：

- 库文件路径由 `HEMING_DB_PATH` 指定，缺省 `./data/heming.db`（相对进程工作目录）。用的是 Node 24 内置 `node:sqlite`，没有原生依赖。
- 云端裸机部署（见 `docs/deploy.md`）注入 `HEMING_DB_PATH=/var/lib/heming/heming.db`，该目录是 api 进程唯一的写入点；systemd 重启、重发版、回滚都不动它，备份/恢复针对该目录（`docs/deploy.md` §6）。
- 本地开发默认落 `./data/heming.db`，已在 `.gitignore` 排除（`data/`），不进版本库、不进部署包。

> 智能体的**三层记忆、技能池、上下文预算、HITL 策略、自我修改留痕**不在此库中：它们只存触发设备本机的 `localStorage`；magpie 网关 Key、插件密钥与 MCP 配置也只在本机。Wiki 知识库在桌面端写真实 Markdown 文件。上述数据不上云、不进消息、不进部署包；换设备或清浏览器数据会丢失（记忆/技能支持导出导入）。

# 信息采集中枢（和鸣插件 · d.98）

把本机 QQ / 微信归档的**采集与查询**交给和鸣的智能体。

插件本身是纯声明的（`plugin.json` 只声明权限、一个本机 MCP 服务、一个技能和三条命令），
真正干活的是和鸣桌面端托管的**采集桥**：它只监听 `127.0.0.1:8776`，把 7 个 `infohub_*`
工具交给智能体；归档、检索与日程都留在本机，写操作仍逐次走人工确认。
安装并启用插件后，和鸣桌面端会**自动开始采集**（每 30 分钟增量一次，可在信息中枢页关闭或手动触发）。

> 本插件**不随和鸣安装包分发**：仓库里维护这份包，由 `scripts/publish-plugin.mjs`
> 摆进云端插件目录，用户从插件区自行安装（版本 1.1.0，应用侧对应 d.98）。

## 它贡献什么

| 能力 | 内容 |
|---|---|
| MCP 服务 | `infohub` →「信息采集中枢（本机采集桥）」→ `http://127.0.0.1:8776/mcp`（只接受本机回环） |
| 技能 | 「本机信息采集与归档查询」：告诉智能体 7 个工具各干什么、什么时候用、写操作先确认、端点没起来就如实说 |
| 命令 | 「查看采集状态」「采集本机消息」「查看本机日程」→ 都跳到信息中枢页 |
| 权限 | 网络：仅 `127.0.0.1:8776`；工具风险上限：`write`（采集与补扫日程会写本机归档）；文件：无 |
| 不携带 | 代码、命令、环境变量、请求头、密钥、脚本——全都没有，安装不联网、不执行任何东西 |

风险上限设成 `write` 是为了让 `infohub_sync` / `infohub_agenda_rebuild` 能被注入；
这不放宽确认流程，写工具每次调用仍按名字判风险、逐次确认。

## 三步用起来

1. **装插件**：插件区 → 安装插件 →「从云端浏览」，找到「信息采集中枢」→ 载入清单 →
   确认弹窗里展示的权限与贡献 → 安装（同 `id` 再装一次就是更新）。
   装完技能进技能池、服务进接口区；**采集也会自动开始**（见下一条）。
2. **自动采集（默认开，可在信息中枢页关掉）**：安装并启用插件后，和鸣桌面端会自动开始采集
   ——装完先跑一次，此后**每 30 分钟增量采集一次**；采集桥（本机 MCP 端点）由和鸣托管。
   - **关掉自动采集**：信息中枢页 →「采集桥」区块 →「自动采集」→「关闭自动采集」。
     关掉后不再按点自动采，插件停用或卸载也会停。
   - **立刻手动采一次**：同一处点「立即采集一次」；自动采集关着也能用，
     采集桥没启动/没连接时页面会自动处理并给出中文原因。
   - **浏览器版限制**：浏览器端**不会自动采集，也不会拉起进程**；采集桥必须由和鸣桌面端
     或你自己启动的外部进程提供，页面只显示「检测到 / 未检测到本机采集桥」并支持重新检测。
3. **启用工具**：状态变成「运行中 · 127.0.0.1:8776」之后，到接口区把 `infohub` 服务的工具
   逐个启用（默认全关，这是既有规则）。

## 7 个工具

| 工具 | 读写 | 用途 |
|---|---|---|
| `infohub_status` | 只读 | 先看状态：会话数、消息数、各来源最近一次采集时间与结果 |
| `infohub_sync` | **写** | 增量或全量采集（`sources` 可选 qq/wechat，`full` 全量）；**调用前必须复述来源与范围，用户确认后才执行** |
| `infohub_archive_search` | 只读 | 归档全文检索（`query` 必填，`limit` 1–50），返回会话/时间/发信人/片段 |
| `infohub_archive_read` | 只读 | 按 `conversationId` 读最近消息（`limit` 1–100），时间正序 |
| `infohub_archive_agenda` | 只读 | 从消息里识别出的日程（`days` 1–60、`overdue` 1–365） |
| `infohub_conversations` | 只读 | 先列会话再读消息（`source`/`keyword`/`limit` 1–200），拿 id 再读 |
| `infohub_agenda_rebuild` | **写** | 采集后补扫日程（`days` 1–90）；采集本身不重扫，**调用前先说明要重扫几天并确认** |

两个写操作的口径一致：**先复述清楚要做什么（来源、增量还是全量、重扫多少天），等用户明确同意再调**；
被拒绝就停下如实说明，不换个说法重试。工具不可用（服务未连接 / 端点没起来）时，
智能体应当直接说「采集桥没有运行，请在和鸣桌面端信息中枢页启动采集桥」，而不是编造归档内容。

## 边界

- **只走本机回环**：服务地址固定 `http://127.0.0.1:8776/mcp`，权限里也只声明 `127.0.0.1:8776`；
  不监听外网、不对外提供端口。
- **自动采集由和鸣托管**：安装并启用插件后自动开始采集（装完先跑一次、此后每 30 分钟增量一次），
  可在信息中枢页关闭；插件停用/卸载即停止。自动采集只发生在**桌面端**，浏览器版不会自动采集，
  也不会拉起任何进程。采集桥进程同样由和鸣桌面端托管（或你自行启动的外部进程），页面不会悄悄起进程。
- **不携带可执行内容与密钥**：清单里没有代码、命令、环境变量、请求头或任何密钥；
  安装插件时不联网、不执行。
- **归档不出本机**：采集桥只读写本机归档库；智能体引用时会标注「来自本机归档」，
  归档内容不会上传到云端，也不应被建议导出到外部服务。
- **归档不是当前会话**：智能体不应把归档里的消息当成用户此刻说的话；两者来源不同。
- **浏览器版限制**：浏览器能安装与调用工具，但不能拉起进程；需要和鸣桌面端或外部进程提供端点，
  且公网 https 页面访问本机回环受浏览器策略影响，本轮不做承诺。
- 与内置的「信息中枢」模块（桌面端 stdio 边车）互不依赖：插件这条路让浏览器也能用，
  并把采集能力显式交给智能体（仍走确认）。

## 卸载

插件区 → 插件 → 卸载即可：技能、服务登记与命令会被级联收回，**自动采集也会随插件停用/卸载停止**。

**不会删除归档**：本机 QQ/微信归档库与采集桥配置都不在和鸣的插件存储里，卸载插件不影响它们。
如果采集桥是和鸣拉起的，退出和鸣或用「采集桥 → 停止」关闭；是你自己起的窗口就 Ctrl+C。
